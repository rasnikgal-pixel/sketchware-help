Проект 7. Финальный большой проект

Финальный проект — объединяем всё, что изучили. Делаем полноценное приложение: с авторизацией через Firebase, базой данных, рекламой и подготовкой к публикации в Google Play.

Это самый сложный проект гайда. Он покажет, как собрать из отдельных частей работающее приложение, которое не стыдно выложить в магазин.

Что будем делать

Создадим приложение-заметки с синхронизацией в облаке. Пользователь:

  • Регистрируется по email.
  • Входит в аккаунт.
  • Создаёт заметки.
  • Видит их на любом устройстве.
  • Смотрит рекламу в паузах.
  • Получает push-уведомления.

Постановка задачи

Название: CloudNotes. Пакет: com.rasnikgal.cloudnotes.

Функции:

  • Экран входа / регистрации.
  • Главный экран со списком заметок.
  • Экран создания заметки.
  • Синхронизация через Firebase.
  • Баннер AdMob внизу.
  • Push-уведомления при новой заметке.
  • Тёмная тема по системе.

Использование всех виджетов

В проекте используются практически все категории виджетов:

  • Layouts: Linear(V), Linear(H), Scroll(V), RelativeLayout.
  • AndroidX: CardView, TextInputLayout, SwipeRefreshLayout.
  • Widgets: TextView, EditText, Button, MaterialButton, ImageView, CircleImageView, CheckBox, Switch.
  • Списки: RecyclerView для заметок.
  • Библиотеки: LottieAnimation на экране загрузки.
  • Дата и время: DatePicker для даты заметки.

Использование всех компонентов

В проекте подключаются ключевые компоненты:

  • Intent — переходы между экранами.
  • SharedPreferences — сохранение темы и последнего пользователя.
  • Dialog — подтверждение удаления.
  • ProgressDialog — ожидание при загрузке.
  • RequestNetwork — если нужен внешний API.
  • Notification — push-уведомления.
  • Calendar — даты создания заметок.
  • Timer — автосохранение.
  • Vibrator — тактильная обратная связь.
  • Camera — прикрепить фото к заметке.

Firebase

Авторизация:

  • Включаем Email/Password в Firebase Console.
  • Регистрация через createUserWithEmailAndPassword.
  • Вход через signInWithEmailAndPassword.
  • Выход через signOut.

База данных:

  • Realtime Database для заметок.
  • Структура: /users/{uid}/notes/{noteId} — каждая заметка в отдельном узле.
  • Правила безопасности: только владелец может читать и писать в свою папку.

Хранилище:

  • Firebase Storage для фото к заметкам.
  • Путь: /users/{uid}/notes/{noteId}.jpg.

Push-уведомления:

  • Cloud Message для уведомлений.
  • Токен устройства сохраняется в базе.
  • Отправка через Firebase Console или свой сервер.

⚠️ Важно: правила безопасности Firebase — критичны. Без них база открыта всем. Настрой:

{
  "rules": {
    "users": {
      "$uid": {
        ".read": "$uid === auth.uid",
        ".write": "$uid === auth.uid"
      }
    }
  }
}

Реклама

Форматы:

  • AdView — баннер внизу главного экрана.
  • InterstitialAd — реклама после удаления заметки.
  • RewardedVideoAd — за просмотр даётся премиум-функция на час.

Настройка:

  • Регистрация в AdMob.
  • Создание приложения и блоков объявлений.
  • Получение AdUnitId для каждого формата.
  • TestMode = true на этапе разработки.
  • TestMode = false перед публикацией.

⚠️ Важно: не тапай по своей рекламе. Даже для проверки. Это приводит к бану аккаунта AdMob.

⚠️ Важно: не показывай слишком много рекламы. Один баннер внизу + Interstitial раз в 3–5 действий. Иначе пользователи удалят приложение.

Публикация

Подготовка:

  • Иконка — 512×512 PNG.
  • Скриншоты — минимум 2, максимум 8.
  • Описание — до 80 символов кратко + до 4000 подробно.
  • Политика конфиденциальности — обязательна, если есть авторизация или аналитика.
  • Категория — выбери подходящую.
  • Контент-рейтинг — пройди опрос.

Сборка:

  • Экспорт APK или AAB (предпочтительно).
  • Подпись приложения — сертификат.
  • Ключ подписи — сохрани, он понадобится для обновлений.
  • Код версии — увеличивай с каждой публикацией.

Публикация в Google Play:

  • Регистрация в Google Play Console — 25$ единоразово.
  • Создание приложения.
  • Заполнение всех разделов.
  • Загрузка AAB.
  • Прохождение проверки — от нескольких часов до нескольких дней.
  • Публикация.

⚠️ Важно: Google Play проверяет приложения. Нарушения: спам, вредоносный код, нарушение авторских прав, недостаточная функциональность.

⚠️ Важно: не загружай приложение, которое уже есть в магазине под другим именем. Забанит.

⚠️ Важно: сохрани ключ подписи в надёжном месте. Без него не сможешь обновлять приложение.

💡 Совет: сначала опубликуй в внутреннем тестировании — на 20 человек. Так найдёшь баги до публичного релиза.

💡 Совет: собирай отзывы первых пользователей. Исправляй проблемы перед широкой публикацией.

💡 Совет: не гонись за функционалом на старте. Простое приложение, но работающее — лучше, чем сложное и глючное.

💡 Совет: обновляй приложение регулярно. Google Play любит активных разработчиков.

💡 Совет: читай правила Google Play перед публикацией. За нарушения — бан аккаунта без возврата денег.

❌ Частая ошибка: публиковать сырое приложение. Google Play отклонит или пользователи оставят негативные отзывы.

❌ Частая ошибка: забыть про политику конфиденциальности. Без неё не опубликуют.

❌ Частая ошибка: использовать чужой контент — картинки, музыку. Авторские права.

❌ Частая ошибка: не увеличивать код версии при обновлении. Google Play отклонит.

❌ Частая ошибка: не сохранить ключ подписи. Обновить приложение не получится.

❌ Частая ошибка: тапать по своей рекламе. Бан AdMob.
