CheckBox — галочка

CheckBox — флажок (галочка). Виджет, который может находиться в одном из двух состояний: включён (галочка стоит) или выключен (галочки нет). Пользователь тапает по нему и переключает состояние.

Иконка в палитре — квадрат с галочкой внутри.

Как работает

  • Имеет два состояния: Checked = true (галка стоит) или false (галка снята).
  • Тап по чекбоксу переключает состояние.
  • Независим от других чекбоксов: можно отметить один, два или все сразу.
  • При изменении состояния срабатывает событие onCheckedChanged — там можно описать логику.
  • В отличие от RadioButton, который работает только в группе, CheckBox работает сам по себе.

Когда использовать

  • Согласия — «Принимаю условия», «Согласен с обработкой данных».
  • Множественный выбор — отметить несколько интересов, категорий, фильтров.
  • Настройки — включение/отключение функций.
  • Списки задач — «Сделано», «Куплено».
  • Опции заказа — «Добавить соус», «Оформить как подарок».

Настройки

Настройка Что делает Значения
Text Подпись рядом с флажком. Любая строка.
Checked Начальное состояние (включён / выключен). Переключатель: вкл / выкл.
TextColor Цвет текста подписи. HEX или выбор из палитры.
TextSize Размер текста. Число в sp.
ButtonTint Цвет самого флажка (в современных версиях Android). HEX или выбор из палитры.
Gravity Положение текста относительно флажка. left, right, center.
Enabled Активен ли чекбокс. Переключатель: вкл / выкл.
Padding / Margin Внутренние и внешние отступы. Число в dp для каждой стороны.
Width / Height Ширина и высота. wrap_content или match_parent.

Как перетащить CheckBox на макет

CheckBox, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V), Linear(H) или RelativeLayout.
  3. Раскрой категорию Widgets в палитре слева.
  4. Зажми CheckBox и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — чекбокс появится в разметке.
  6. Тапни по нему и задай Текст — например, «Согласен с условиями».
  7. Присвой осмысленный ID — он нужен, чтобы читать состояние.
  8. Открой вкладку «События» — добавь событие onCheckedChanged для этого чекбокса, если нужна логика при переключении.
⚠️ Важно: обычный тап по CheckBox в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: без ID чекбокс не появится в списке событий вкладки «События». Его состояние нельзя будет прочитать в логике.
⚠️ Важно: если чекбоксов несколько и они не связаны логически — каждый работает сам по себе. Если нужно выбрать только один — используй RadioGroup и RadioButton.
💡 Совет: для чтения состояния в логике используй блок isChecked — он возвращает true или false. На основе этого можно включать и отключать другие элементы.
💡 Совет: для обязательного согласия (например, «Согласен с условиями») проверяй состояние в onClick кнопки «Продолжить». Если false — покажи предупреждение и не продолжай.
💡 Совет: не делай чекбоксы слишком мелкими. Стандартный размер флажка в Android — 48dp по тапу. Подпись делай читаемой — 14–16sp.
❌ Частая ошибка: использовать CheckBox для взаимоисключающего выбора («Мужской / Женский»). Для этого — RadioGroup с RadioButton.
❌ Частая ошибка: забывать про ID и потом не иметь возможности прочитать состояние в логике.

Резюме

  • CheckBox — флажок с двумя состояниями: включён / выключен.
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • Независим от других чекбоксов: можно отметить несколько сразу.
  • Ключевые свойства: Текст, Checked, Размер текста, Цвет текста.
  • Для чтения состояния в логике обязательно задавай ID и используй isChecked.
  • Для взаимоисключающего выбора используй RadioGroup + RadioButton, а не чекбоксы.
  • Для события при переключении используется onCheckedChanged.

Частые ошибки новичков

  • Тапают по CheckBox в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Не задают ID. Нельзя прочитать состояние — чекбокс не появится в событиях.
  • Используют CheckBox для выбора одного из нескольких. Нужен RadioGroup.
  • Не проверяют состояние в логике. Пользователь ставит галку, а приложение её игнорирует.
  • Ставят Checked = вкл по умолчанию без необходимости. Лучше оставить выкл — пользователь сам ставит галку.
  • Делают подписи слишком длинными. «Я согласен с условиями использования и обработкой персональных данных» — тяжело читать. Лучше короткая подпись со ссылкой.
  • Забывают про событие onCheckedChanged. Логика при переключении не срабатывает.
