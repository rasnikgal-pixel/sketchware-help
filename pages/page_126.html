SharedPreferences — хранилище настроек

SharedPreferences — компонент для хранения небольших данных между запусками приложения. Настройки, флаги, последние значения, простые пользовательские данные — всё это сохраняется в SharedPreferences.

Иконка в диалоге добавления — дискета или карточка с полосками.

Как работает

  • Сохраняет данные на устройстве в виде пар «ключ — значение».
  • Данные переживают закрытие приложения — остаются при следующем запуске.
  • Поддерживает простые типы: строки, числа, флаги (true/false).
  • Данные приватны — доступны только твоему приложению.
  • Хранение происходит в файле на устройстве — но пользователь его не видит.

Когда использовать

  • Настройки приложения — тёмная тема, звук, уведомления.
  • Флаги — «пользователь уже видел приветствие», «показать обучение».
  • Последние значения — последний введённый город, ник, счёт.
  • Счётчики — количество запусков, прогресс в игре.
  • Простые данные профиля — имя, email, аватар (в base64).

Для больших объёмов данных (списки, объекты) лучше использовать базу данных или Firebase DB.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова в логике. Например, prefs.
  • Имя файла — имя файла на устройстве. Обычно совпадает с именем приложения.

Основные блоки в логике

  • putString — сохранить строку.
  • putInt — сохранить целое число.
  • putBoolean — сохранить флаг.
  • getString — прочитать строку.
  • getInt — прочитать число.
  • getBoolean — прочитать флаг.
  • remove — удалить одно значение.
  • clear — удалить все данные.

Как использовать

  • Подключи компонент SharedPreferences на вкладке «Компонент».
  • Задай ему имя — например, myPrefs.
  • Для сохранения: используй блок putString (или другой) с ключом и значением.
  • Для чтения: используй блок getString (или другой) с тем же ключом.
  • Первый блок — putString с ключом user_name и значением из EditText.
  • Второй блок — getString с ключом user_name при следующем запуске.

Пример: сохранение имени

Задача: сохранить имя пользователя и восстановить его при следующем запуске.

  • Компонент: SharedPreferences с именем prefs.
  • Виджеты: EditText (id nameInput), Button (id saveBtn).
  • Логика:
    • в onCreate — setText для nameInput со значением из prefs.getString("name", "");
    • в onClick кнопки — prefs.putString("name", nameInput.getText()).

⚠️ Важно: ключи должны совпадать при записи и чтении. Ключ user_name ≠ ключ userName. Данные не найдутся.

⚠️ Важно: тип данных тоже важен. Нельзя сохранить putString, а прочитать getInt. Sketchware может упасть или вернуть значение по умолчанию.

⚠️ Важно: всегда задавай значение по умолчанию при чтении. Если ключа нет (первый запуск) — вернётся значение по умолчанию. Иначе — ошибка или пустота.

⚠️ Важно: не храни в SharedPreferences пароли в открытом виде. Данные лежат в открытом файле — любой с root-доступом может их прочитать. Используй хеширование.

💡 Совет: для простых настроек (тема, звук) используй putBoolean — сохраняй true/false. Читай в onCreate и сразу применяй.

💡 Совет: давай ключам понятные имена: user_name, last_city, theme_dark. Тогда в коде сразу ясно, что где хранится.

💡 Совет: для сброса всех данных используй clear. Полезно для кнопки «Сбросить настройки» в приложении.

💡 Совет: не храни в SharedPreferences большие строки (например, JSON на мегабайт). Это замедляет работу. Для больших данных — база или файлы.

❌ Частая ошибка: несовпадение ключей. Save с одним ключом, read с другим — данные не находятся.

❌ Частая ошибка: несовпадение типов. Save putString, read getInt — ошибка при запуске.

❌ Частая ошибка: хранить пароли в открытом виде. Любой, у кого есть доступ к файлам, увидит пароль.

❌ Частая ошибка: забыть про значение по умолчанию. При первом запуске приложение падает или показывает пустые поля.
