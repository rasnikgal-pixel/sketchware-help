SearchView — поле поиска

SearchView — готовое поле поиска с иконкой лупы. Совмещает в себе EditText и кнопку очистки, и обычно встраивается в тулбар или размещается в разметке отдельным виджетом.

Иконка в палитре — лупа внутри прямоугольника.

Как работает

  • Отображает поле поиска с иконкой лупы слева.
  • При тапе — открывается клавиатура, можно вводить запрос.
  • По мере ввода можно реагировать в реальном времени (событие onQueryTextChange).
  • При нажатии кнопки «Поиск» на клавиатуре — срабатывает событие onQueryTextSubmit.
  • Кнопка «×» справа очищает поле.
  • Может раскрываться по тапу на иконку (если в тулбаре) или быть всегда видимым (если в разметке).

Когда использовать

  • Поиск по списку — фильтрация ListView или RecyclerView.
  • Поиск на сервере — отправка запроса к API.
  • Поиск в базе данных — по названию или тексту.
  • Фильтр в каталоге — поиск товара по имени.
  • Глобальный поиск в приложении — по всем экранам.

Основные свойства

  • QueryHint — подсказка внутри поля (например, «Поиск товаров…»).
  • Iconified — свернутый режим: показывать только иконку лупы, пока пользователь не тапнет.
  • IconifiedByDefault — раскрывать ли поле сразу при запуске.
  • SubmitButtonEnabled — показывать ли кнопку поиска отдельно.
  • Query — текущий введённый запрос.
  • TextColor / TextSize — цвет и размер текста.
  • Background — фон виджета.
  • Width / Height — match_parent или wrap_content.

Как добавить

  • Выбери контейнер, куда хочешь положить поиск.
  • Тап по SearchView в палитре — виджет добавится внутрь.
  • Задай QueryHint — «Поиск…» или более конкретно.
  • Присвой id — для работы в логике.
  • Открой вкладку «События» и добавь:
    • onQueryTextSubmit — реакция на нажатие «Поиск»;
    • onQueryTextChange — реакция на изменение текста в реальном времени.
  • Внутри событий опиши логику: что фильтровать, куда отправить запрос, что показать.

⚠️ Важно: SearchView сам не ищет. Он только даёт поле ввода и сообщает логике, какой текст введён. Что делать с этим текстом — полностью на тебе.

⚠️ Важно: событие onQueryTextChange срабатывает на каждый введённый символ. Если в нём идёт запрос к серверу, это создаст нагрузку при быстром вводе. Для серверного поиска лучше использовать onQueryTextSubmit.

💡 Совет: для локальной фильтрации (по списку в приложении) используй onQueryTextChange — так пользователь видит результаты сразу по мере ввода.

💡 Совет: для поиска на сервере используй onQueryTextSubmit — иначе каждый введённый символ полетит на сервер.

💡 Совет: задавай понятный QueryHint — «Поиск товаров», «Поиск в чатах». Универсальное «Поиск…» не помогает пользователю понять, что можно искать.

💡 Совет: если поле поиска всегда нужно раскрытым — задай Iconified = false. Если оно должно быть иконкой и раскрываться по тапу — оставь true.

❌ Частая ошибка: добавить SearchView и ждать, что поиск заработает автоматически. Без логики в событиях он только принимает ввод.

❌ Частая ошибка: использовать onQueryTextChange для тяжёлых запросов. Пользователь вводит «телефон» — уходит 7 запросов на сервер. Это неправильно и раздражает пользователя задержками.
