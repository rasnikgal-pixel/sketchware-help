SearchView — поле поиска

SearchView — готовое поле поиска с иконкой лупы. Совмещает в себе EditText и кнопку очистки, и обычно встраивается в тулбар или размещается в разметке отдельным виджетом.

Иконка в палитре — лупа внутри прямоугольника.

Как работает

  • Отображает поле поиска с иконкой лупы слева.
  • При тапе — открывается клавиатура, можно вводить запрос.
  • По мере ввода можно реагировать в реальном времени (событие onQueryTextChange).
  • При нажатии кнопки «Поиск» на клавиатуре — срабатывает событие onQueryTextSubmit.
  • Кнопка «×» справа очищает поле.
  • Может раскрываться по тапу на иконку (если в тулбаре) или быть всегда видимым (если в разметке).

Когда использовать

  • Поиск по списку — фильтрация ListView или RecyclerView.
  • Поиск на сервере — отправка запроса к API.
  • Поиск в базе данных — по названию или тексту.
  • Фильтр в каталоге — поиск товара по имени.
  • Глобальный поиск в приложении — по всем экранам.

Настройки

Настройка Что делает Значения
QueryHint Подсказка внутри поля. Любая строка, например «Поиск товаров…».
Iconified Свёрнутый режим — показывать только иконку лупы. Переключатель: вкл / выкл.
IconifiedByDefault Раскрывать ли поле сразу при запуске. Переключатель: вкл / выкл.
SubmitButtonEnabled Показывать ли кнопку поиска отдельно. Переключатель: вкл / выкл.
Query Текущий введённый запрос. Любая строка.
TextColor / TextSize Цвет и размер текста. HEX, число в sp.
Background Фон виджета. HEX, drawable-ресурс или NONE.
Width / Height Ширина и высота. match_parent или wrap_content.

Свойства виджета

Открой панель свойств, тапнув по SearchView в рабочей области. Ниже — все свойства с описанием. Значения указаны в том виде, в каком они отображаются в Sketchware Pro 7 (на скриншоте пример ID — searchview1).

Основные

Свойство (рус / англ) Что делает Значения Пример
ID Уникальное имя виджета. По этому имени виджет виден на вкладке «События» и в блоках логики. Любая строка без пробелов. По умолчанию — searchview1, searchview2 и т. д. Переименуй в productSearch, если это поиск товаров.
Пользовательские атрибуты Дополнительные XML-атрибуты, которые можно задать вручную. Нужны опытным пользователям. Пары «атрибут = значение». Например, app:queryHint="Поиск", app:iconifiedByDefault="false".
Конвертировать Показывает тип виджета — SearchView. Обычно менять не нужно. SearchView и другие типы виджетов. Оставь как есть.

Layout gravity		 Как виджет выравнивается внутри родителя. none — по умолчанию;

💡 Совет для новичков: ключевые настройки (QueryHint, Iconified, SubmitButtonEnabled) обычно задаются через Пользовательские атрибуты — в виде app:queryHint="Поиск", app:iconifiedByDefault="false". В обычной панели свойств их может не быть.

Как перетащить SearchView на макет

SearchView, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V), Linear(H) или RelativeLayout.
  3. Раскрой категорию Widgets в палитре слева.
  4. Зажми SearchView и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — поле поиска появится в разметке.
  6. Через Пользовательские атрибуты задай app:queryHint (подсказка), app:iconifiedByDefault (раскрыто ли поле сразу), app:submitButtonEnabled (кнопка поиска).
  7. Присвой осмысленный ID — он нужен для логики.
  8. Открой вкладку «События» и добавь:
    • onQueryTextSubmit — реакция на нажатие «Поиск»;
    • onQueryTextChange — реакция на изменение текста в реальном времени.
  9. Внутри событий опиши логику: что фильтровать, куда отправить запрос, что показать.
⚠️ Важно: обычный тап по SearchView в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: SearchView сам не ищет. Он только даёт поле ввода и сообщает логике, какой текст введён. Что делать с этим текстом — полностью на тебе.
⚠️ Важно: событие onQueryTextChange срабатывает на каждый введённый символ. Если в нём идёт запрос к серверу, это создаст нагрузку при быстром вводе. Для серверного поиска лучше использовать onQueryTextSubmit.
💡 Совет: для локальной фильтрации (по списку в приложении) используй onQueryTextChange — так пользователь видит результаты сразу по мере ввода.
💡 Совет: для поиска на сервере используй onQueryTextSubmit — иначе каждый введённый символ полетит на сервер.
💡 Совет: задавай понятный QueryHint — «Поиск товаров», «Поиск в чатах». Универсальное «Поиск…» не помогает пользователю понять, что можно искать.
💡 Совет: если поле поиска всегда нужно раскрытым — задай Iconified = false. Если оно должно быть иконкой и раскрываться по тапу — оставь true.
❌ Частая ошибка: перетащить SearchView и ждать, что поиск заработает автоматически. Без логики в событиях он только принимает ввод.
❌ Частая ошибка: использовать onQueryTextChange для тяжёлых запросов. Пользователь вводит «телефон» — уходит 7 запросов на сервер. Это неправильно и раздражает пользователя задержками.

Резюме

  • SearchView — готовое поле поиска с иконкой лупы и кнопкой очистки.
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • Ключевые настройки (QueryHint, Iconified, SubmitButtonEnabled) задаются через Пользовательские атрибуты.
  • Сам по себе не ищет — нужно описывать логику в событиях.
  • Для локального поиска — onQueryTextChange; для серверного — onQueryTextSubmit.
  • Не используй тяжёлые запросы в onQueryTextChange — событие срабатывает на каждый символ.
  • Задавай понятный QueryHint — что именно ищет пользователь.

Частые ошибки новичков

  • Тапают по SearchView в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Перетащили поле, но не добавили события. Ввод идёт, но поиска нет.
  • Вешают серверный запрос на onQueryTextChange. Каждый введённый символ — запрос на сервер. Нагрузка и тормоза.
  • Не задают QueryHint. Универсальное «Search…» не помогает пользователю.
  • Ищут QueryHint в обычных свойствах. Через «Пользовательские атрибуты» — app:queryHint.
  • Не задают ID. Виджет не появляется в списке событий, логика не подключается.
  • Ждут, что SearchView сам отфильтрует список. Он только отдаёт текст — фильтровать нужно вручную.
