Менеджер сжатия кода

Менеджер сжатия кода — раздел меню «Настройка», через который включается R8 / ProGuard — инструмент для сжатия и обфускации кода приложения. Уменьшает размер APK и затрудняет декомпиляцию.

Иконка в меню — щит с замком.

Что такое R8 / ProGuard

R8 — современный инструмент Google для сжатия и обфускации Android-кода. ProGuard — его предшественник, тоже иногда используется.

Что делает:

  • Удаляет неиспользуемый код — методы, классы, ресурсы, которые не вызываются.
  • Переименовывает классы и методы — MainActivity превращается в a, b, c. Код становится нечитаемым.
  • Сжимает байт-код — уменьшает размер APK.
  • Оптимизирует — улучшает производительность.

Что можно настроить

  • Включить / отключить сжатие.
  • Правила исключения — какие классы не переименовывать.
  • Уровень сжатия — как агрессивно.
  • Обфускацию — переименование.
  • Оптимизацию — удаление неиспользуемого кода.

Зачем это нужно

  • Уменьшить размер APK — иногда на 20–40%.
  • Защитить код — сложнее декомпилировать и понять логику.
  • Защитить API-ключи — строки-ключи сложнее найти.
  • Защитить алгоритмы — бизнес-логику не так просто скопировать.
  • Улучшить производительность — оптимизация байт-кода.

Как включить

  • Открой меню ⋮ → Менеджер сжатия кода.
  • Откроется диалог с настройками R8 / ProGuard.
  • Включи опции:
    • Minify Enabled — сжатие.
    • Shrink Resources — удаление неиспользуемых ресурсов.
    • Obfuscate — обфускация.
  • Добавь правила исключений, если используешь сторонние библиотеки.
  • Нажми «Сохранить».
  • Пересобери проект — теперь APK сжат и обфусцирован.

Правила исключений

Если библиотека ломается после сжатия — добавь правило:

-keep class com.example.library.** { *; }

Это сохранит классы библиотеки без переименования.

Часто требуются исключения для:

  • Firebase — Auth, DB, Storage.
  • Google Ads — AdMob.
  • Retrofit — сетевые запросы.
  • Gson — работа с JSON.
  • Room — база данных.

⚠️ Важно: R8 может сломать приложение, если не указать правила исключений. Некоторые библиотеки используют рефлексию — им нужно сохранить имена классов.

⚠️ Важно: включай сжатие только для релиза. В отладке R8 замедляет сборку и усложняет поиск ошибок.

⚠️ Важно: проверяй приложение после включения сжатия. Возможны ошибки в местах, где используются рефлексия и сериализация.

⚠️ Важно: делай резервную копию перед включением. Если что-то пойдёт не так — вернёшься.

⚠️ Важно: R8 не защищает на 100%. Обфусцированный код можно декомпилировать, хоть и сложнее понять.

💡 Совет: включай R8 только на финальной стадии. Сначала убедись, что приложение работает без сжатия. Потом добавляй.

💡 Совет: проверяй приложение по частям после включения сжатия. Сначала основные экраны, потом Firebase, рекламу, сетевые запросы.

💡 Совет: не включай Shrink Resources сразу. Он может удалить ресурсы, которые используются динамически.

💡 Совет: добавляй правила исключений для каждой библиотеки. Обычно разработчики публикуют готовые правила.

💡 Совет: не бойся экспериментировать. Если что-то сломалось — отключи R8 и вернись к рабочей версии.

💡 Совет: сравни размер APK до и после. Иногда разница минимальна — тогда R8 не нужен.

❌ Частая ошибка: включать R8 без правил исключений. Firebase, AdMob, Retrofit ломаются.

❌ Частая ошибка: не проверять приложение после включения. Ошибки проявляются у пользователей.

❌ Частая ошибка: включать R8 при отладке. Сборка идёт дольше, ошибки сложнее найти.

❌ Частая ошибка: включать Shrink Resources без проверки. Ресурсы, используемые динамически, удаляются.

❌ Частая ошибка: ожидать 100% защиты. Обфускацию можно обойти.

❌ Частая ошибка: не делать резервную копию. Откатить сжатие сложно.
