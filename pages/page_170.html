Редактор ресурсов

Редактор ресурсов — раздел меню «Настройка», через который редактируются XML-файлы ресурсов проекта напрямую: strings.xml, colors.xml, styles.xml, dimens.xml и другие.

Если Менеджер ресурсов — это «форма» для добавления ресурсов через поля, то Редактор ресурсов — это «текстовый редактор» для правки XML-файлов вручную.

Иконка в меню — значок с фигурными скобками.

Что можно делать

  • Просматривать содержимое XML-файлов ресурсов.
  • Редактировать их вручную как текст.
  • Добавлять новые строки, цвета, размеры, стили.
  • Изменять существующие значения.
  • Копировать фрагменты для других проектов.
  • Исправлять ошибки, которые не видны через Менеджер.

Какие файлы редактируются

Файл Что содержит
strings.xml Тексты приложения.
colors.xml Палитра.
dimens.xml Размеры и отступы.
styles.xml Стили виджетов.
themes.xml Темы приложения.
arrays.xml Массивы строк.
menu.xml Файлы меню.
attrs.xml Пользовательские атрибуты.

Зачем это нужно

  • Точный контроль над ресурсами.
  • Правка ошибок, которые возникли при добавлении через Менеджер.
  • Массовые изменения — например, замена цвета во всех ресурсах сразу.
  • Копирование готовых блоков XML из примеров в интернете.
  • Добавление ресурсов, недоступных через стандартный Менеджер.

Как открыть

  1. Открой меню ⋮ → Редактор ресурсов.
  2. Откроется список XML-файлов проекта.
  3. Тапни по нужному файлу — содержимое откроется в текстовом редакторе.
  4. Редактируй как обычный текст.
  5. Нажми «Сохранить» для применения.

Структура XML

Элемент Пример Что это
Корневой тег <resources>...</resources> Обёртка для всех ресурсов.
Строка <string name="hello">Привет</string> Строковый ресурс.
Цвет <color name="primary">#3F51B5</color> Цвет.
Размер <dimen name="padding">16dp</dimen> Размер.
Стиль <style name="MyStyle">...</style> Стиль.

Каждый ресурс имеет имя и значение. Имя — латиница, значение — в зависимости от типа.

⚠️ Важно: не нарушай синтаксис XML. Одна пропущенная закрывающая скобка или кавычка — и весь проект не соберётся.
⚠️ Важно: делай резервную копию перед ручным редактированием. Если что-то пойдёт не так — легко вернуться.
⚠️ Важно: не удаляй ресурсы, которые Sketchware создаёт автоматически. Например, app_name, colorPrimary. Это сломает проект.
⚠️ Важно: не редактируй AndroidManifest.xml через этот раздел. Для манифеста есть отдельный менеджер.
💡 Совет: используй Редактор ресурсов только когда Менеджер ресурсов не справляется. Для обычного добавления строк и цветов хватает Менеджера.
💡 Совет: копируй XML-блоки из проверенных источников. Например, стили Material Design — они есть на сайтах типа material.io.
💡 Совет: проверяй проект после правки — запусти сборку. Ошибка в XML сразу видна.
💡 Совет: если не понимаешь XML — не редактируй вручную. Используй Менеджер ресурсов.
💡 Совет: копируй файл перед экспериментами. Например, colors.xml.bak — если что-то сломается, всегда есть запасной.
💡 Совет: комментируй изменения через <!-- комментарий -->. Так ты потом поймёшь, что менял.
❌ Частая ошибка: пропустить закрывающий тег. Проект не собирается.
❌ Частая ошибка: не сохранить файл после правки. Изменения не применяются.
❌ Частая ошибка: использовать кириллицу в именах ресурсов. Только латиница.
❌ Частая ошибка: удалять стандартные ресурсы. Проект ломается.
❌ Частая ошибка: редактировать без резервной копии. Восстановить сложно.
❌ Частая ошибка: править AndroidManifest.xml здесь. Для манифеста — отдельный раздел.

Резюме

  • Редактор ресурсов — раздел для ручного редактирования XML-файлов ресурсов.
  • Позволяет править strings.xml, colors.xml, dimens.xml, styles.xml и другие.
  • Используется для точного контроля и массовых изменений.
  • Требует понимания XML-синтаксиса.
  • Не удаляй стандартные ресурсы — проект сломается.
  • Делай резервную копию перед экспериментами.
  • Проверяй сборку после правки — ошибка сразу видна.
  • Не редактируй AndroidManifest.xml здесь — для него есть отдельный раздел.

Частые ошибки новичков

  • Пропускают закрывающие теги. Проект не собирается.
  • Не сохраняют файл. Изменения не применяются.
  • Используют кириллицу в именах. Ошибка сборки.
  • Удаляют стандартные ресурсы. Проект ломается.
  • Работают без резервной копии. Восстановить сложно.
  • Правят AndroidManifest.xml здесь. Не тот раздел.
  • Используют редактор для простых задач. Менеджер справится быстрее.
