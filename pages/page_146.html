FragmentAdapter — адаптер для ViewPager

FragmentAdapter — компонент для управления фрагментами. Связывает ViewPager с несколькими Fragment — экранами, которые можно переключать свайпом или через вкладки.

Иконка в диалоге добавления — несколько прямоугольников рядом.

Как работает

  • Связывает ViewPager с набором Fragment (фрагментов).
  • Каждый Fragment — это отдельный экран внутри одной Activity.
  • Пользователь свайпает влево-вправо или тапает по вкладке TabLayout — переключается между фрагментами.
  • Adapter управляет загрузкой и переиспользованием фрагментов.
  • В отличие от Activity, фрагменты легче и быстрее переключаются.

Когда использовать

  • Онбординг — знакомство с приложением в 3–5 слайдах.
  • Табы и вкладки — «Новости», «Популярное», «Избранное» в одном экране.
  • Галерея — просмотр изображений свайпом.
  • Разделы одного приложения — без перехода на новый экран.
  • Адаптивный интерфейс — на планшете два фрагмента рядом, на телефоне — по одному.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова. Например, pagerAdapter.

Основные блоки в логике

  • setViewPager — привязать адаптер к ViewPager.
  • setTabLayout — связать с вкладками TabLayout.
  • addFragment — добавить фрагмент в адаптер.
  • setTitles — задать заголовки вкладок.
  • getItem — получить фрагмент по позиции.
  • getCount — количество фрагментов.

Как использовать

  • Создай Fragment для каждой страницы через Менеджер представлений (тип «Fragment»).
  • В разметке добавь ViewPager (и опционально TabLayout).
  • Подключи компонент FragmentAdapter на вкладке «Компонент».
  • Задай имя — например, adapter.
  • В логике:
    • добавь фрагменты через addFragment;
    • задай заголовки через setTitles;
    • привяжи к ViewPager через setViewPager;
    • если есть TabLayout — свяжи через setTabLayout.

Пример: онбординг

  • Создай 3 Fragment: Slide1, Slide2, Slide3.
  • ViewPager на главном экране.
  • FragmentAdapter — добавь три фрагмента.
  • setViewPager — свяжи.
  • Пользователь свайпает — переключаются слайды.

Пример: вкладки

  • TabLayout + ViewPager на экране.
  • 3 Fragment: «Новости», «Популярное», «Избранное».
  • FragmentAdapter — добавь 3 фрагмента.
  • setTabLayout — свяжи с вкладками.
  • Пользователь тапает по вкладке или свайпает — переключается.

⚠️ Важно: для каждого фрагмента нужен свой Layout (XML-файл). Без разметки фрагмент будет пустым.

⚠️ Важно: FragmentAdapter работает только с ViewPager. Без ViewPager компонент бесполезен.

⚠️ Важно: не путай Fragment и Activity. Фрагмент — это часть экрана, Activity — сам экран. FragmentAdapter управляет фрагментами.

⚠️ Важно: фрагменты не удаляются полностью — они остаются в памяти. Если их много, приложение может «съесть» память.

💡 Совет: для онбординга используй 3–5 фрагментов с картинкой, заголовком и текстом. Внизу — точки-индикаторы и кнопка «Далее».

💡 Совет: для вкладок используй TabLayout + ViewPager. Это стандартный паттерн Android — пользователь и тапает, и свайпает.

💡 Совет: для галереи каждый фрагмент — ImageView с картинкой. Пользователь листает — меняется фото.

💡 Совет: для динамического количества фрагментов (например, зависит от данных) — используй цикл в логике. Добавляй фрагменты по мере необходимости.

💡 Совет: не делай много фрагментов — 5–7 максимум. Больше — сложно ориентироваться пользователю, и приложение тормозит.

💡 Совет: для плавного переключения используй setOffscreenPageLimit — сколько фрагментов держать в памяти. 1–2 — оптимально.

❌ Частая ошибка: не создавать Fragment перед использованием FragmentAdapter. Адаптер не с чем связывать.

❌ Частая ошибка: не привязывать к ViewPager. Компонент «висит» без действия.

❌ Частая ошибка: путать Fragment и Activity. Fragment — часть экрана, Activity — сам экран.

❌ Частая ошибка: делать десятки фрагментов. Приложение тормозит, память забивается.

❌ Частая ошибка: не задавать заголовки для вкладок. Пользователь не понимает, куда тапает.
