Событие onCreate

onCreate — самое первое и самое важное событие жизненного цикла Activity. Срабатывает при создании экрана: когда пользователь запускает приложение или открывает новый экран. Именно с onCreate начинается работа любого экрана.

В Sketchware Pro 7 событие onCreate создаётся автоматически при создании проекта. Оно уже есть в списке событий — не нужно добавлять его вручную.

Когда срабатывает

  • При запуске приложения — когда пользователь тапает по иконке.
  • При переходе на новый экран через Intent.
  • При возврате из фона — если Activity была уничтожена системой.
  • Один раз за время жизни экрана — при его первом появлении.

Что происходит в onCreate

  • Экран создаётся — Android подготавливает разметку, ресурсы, тему.
  • Виджеты из разметки инициализируются — становятся доступны в логике.
  • Переменные и компоненты получают начальные значения.
  • Запускаются первые действия: загрузка данных, настройка UI, проверка разрешений.

Что обычно делают в onCreate

Что делают Зачем
Инициализация переменных Задают начальные значения для счётчиков, флагов, массивов.
Чтение сохранённых данных Из SharedPreferences, базы данных, файлов.
Настройка начального вида Установка текстов, цветов, состояний переключателей.
Проверка разрешений Запрос доступа к камере, геолокации, файлам.
Загрузка данных из сети RequestNetwork с показом ProgressBar.
Настройка компонентов MediaPlayer, TextToSpeech, LocationManager.
Установка слушателей Для компонентов, реагирующих на события.

Как открыть onCreate

  • Открой вкладку «События».
  • Найди в списке onCreate — оно всегда первое.
  • Тапни по стрелке > слева от названия.
  • Откроется блочное полотно — здесь добавляй блоки.
  • Возврат к списку событий — стрелка назад в шапке.

Как добавить блоки в onCreate

  • Перетащи блок из палитры на полотно.
  • Вставь нужные значения в «дырки».
  • Собери логику сверху вниз.

Порядок выполнения

  • Блоки выполняются сверху вниз, один за другим.
  • Первый блок — самый верхний.
  • Если в блоке ошибка — дальнейшие не выполнятся.
  • Общее время выполнения onCreate — обычно до нескольких секунд. Долгие операции (сеть, файлы) лучше выносить в отдельные события.
⚠️ Важно: не запускай тяжёлые операции в onCreate. Если приложение загружает данные из сети в onCreate — экран будет пустым и медленно открываться. Показывай ProgressBar и загружай данные асинхронно.
⚠️ Важно: onCreate срабатывает только один раз. Если нужно обновлять данные при каждом возврате на экран — используй onResume или onStart.
⚠️ Важно: не удаляй onCreate из списка событий. Без него Activity не сможет корректно инициализироваться, и приложение может падать.
⚠️ Важно: если onCreate пустой — это нормально. Экран откроется с разметкой и без логики. Не обязательно добавлять блоки сразу.
💡 Совет: для теста первого запуска добавь в onCreate блок Toast с сообщением. Это простой способ убедиться, что событие работает.
💡 Совет: инициализируй переменные первыми блоками в onCreate. Тогда к моменту других действий они уже будут иметь значения.
💡 Совет: для чтения настроек из SharedPreferences используй блоки в начале onCreate. Так пользователь увидит свои сохранённые параметры сразу при открытии.
💡 Совет: для сетевых запросов показывай ProgressBar в начале onCreate, делай запрос, скрывай ProgressBar в onResponse. Это правильная последовательность.
💡 Совет: не смешивай инициализацию и вычисления. Сначала — все начальные значения, потом — действия с ними.
❌ Частая ошибка: долгая операция в onCreate. Приложение «зависает» на старте, пользователь думает, что оно сломалось.
❌ Частая ошибка: ожидание, что onCreate срабатывает каждый раз при возврате на экран. Нет — только один раз. Для повторов используй onResume.
❌ Частая ошибка: забыть про переменные и пытаться использовать их в других событиях. Если переменная не инициализирована в onCreate — она пустая.
❌ Частая ошибка: не проверять, что уже есть в onCreate при добавлении новой логики. Можно случайно перезаписать начальные значения.

Резюме

  • onCreate — самое первое событие экрана, срабатывает при создании Activity.
  • Создаётся автоматически, не нужно добавлять вручную.
  • Срабатывает один раз за время жизни экрана.
  • Здесь делают инициализацию: переменные, чтение данных, настройка UI, разрешения.
  • Блоки выполняются сверху вниз — порядок важен.
  • Тяжёлые операции нужно выносить из onCreate — иначе экран долго открывается.
  • Для повторов при каждом возврате на экран используй onResume.
  • Для простого теста добавь Toast в onCreate — убедишься, что событие сработало.

Частые ошибки новичков

  • Запускают тяжёлые операции в onCreate. Экран открывается медленно.
  • Ожидают, что onCreate сработает при каждом возврате. Нет — только один раз.
  • Не инициализируют переменные. В других событиях они пустые.
  • Удаляют onCreate из списка. Приложение падает при запуске.
  • Перезаписывают начальные значения при добавлении новой логики. UI показывает не то, что надо.
  • Пытаются сделать всё в onCreate. Логика распухает, легко ошибиться.
  • Не тестируют onCreate через Toast или Log. Ошибки не видны сразу.
