ProgressDialog — окно загрузки

ProgressDialog — компонент для показа индикатора загрузки с возможностью блокировки интерфейса. Отображает всплывающее окно с крутящимся спиннером и текстом — пока идёт длительная операция.

Иконка в диалоге добавления — круг со стрелкой или значок загрузки.

Как работает

  • Открывает всплывающее окно с индикатором загрузки.
  • Показывает сообщение — например, «Загрузка…», «Подождите…».
  • Может блокировать интерфейс — пользователь не может тапать по экрану, пока операция не завершится.
  • Не имеет своих событий — управляется через блоки show и dismiss.
  • Автоматически закрывается только если ты сам его закроешь — не завершается по времени.

Когда использовать

  • Загрузка данных из сети — пока приходит ответ от RequestNetwork.
  • Долгая операция — сохранение, обработка, шифрование.
  • Отправка формы — пока данные уходят на сервер.
  • Инициализация — при первом запуске приложения.
  • Работа с файлами — чтение/запись больших данных.
  • Любое действие, которое длится больше секунды.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова. Например, loadingDialog.

Основные блоки в логике

  • show — показать диалог загрузки.
  • dismiss — закрыть диалог.
  • setTitle — задать заголовок.
  • setMessage — задать текст сообщения.
  • setCancelable — можно ли закрыть тапом вне окна или кнопкой «Назад».

Как использовать

  • Подключи компонент ProgressDialog на вкладке «Компонент».
  • Задай имя — например, loading.
  • В логике:
    • вызови show перед началом долгой операции;
    • выполни операцию (RequestNetwork, файл, вычисление);
    • в завершении операции вызови dismiss.
  • Обязательно закрывай диалог — во всех ветках: успех, ошибка, отмена.

Пример: загрузка с сервера

  • onClick кнопки «Загрузить» → loading.show().
  • Затем RequestNetwork.startRequestNetwork().
  • В onResponse → loading.dismiss() → показ данных.
  • В onErrorResponse → loading.dismiss() → показ ошибки.

Пример: сохранение файла

  • onClick кнопки «Сохранить» → loading.show().
  • Логика сохранения файла.
  • По завершении → loading.dismiss().

⚠️ Важно: диалог не закрывается сам. Если ты вызвал show, а dismiss не вызвал — окно останется висеть, и приложение будет «заблокировано».

⚠️ Важно: закрывай диалог во всех случаях: и при успехе, и при ошибке, и при отмене. Иначе получишь «вечную загрузку».

⚠️ Важно: не используй ProgressDialog для очень долгих операций (больше 10–15 секунд). Пользователь подумает, что приложение «зависло». Лучше — линейный ProgressBar с процентами.

⚠️ Важно: не показывай два ProgressDialog одновременно. Второй вызов show при открытом первом — непредсказуемое поведение.

💡 Совет: для сетевых запросов используй ProgressDialog в связке с RequestNetwork. Показал перед запросом — закрыл в onResponse и onErrorResponse.

💡 Совет: задавай понятное сообщение: «Загрузка погоды», «Отправка данных». Общее «Подождите…» менее информативно.

💡 Совет: задавай setCancelable = false для критичных операций — чтобы пользователь не мог прервать сохранение или отправку.

💡 Совет: задавай setCancelable = true для необязательных операций — чтобы пользователь мог отменить, если передумал.

💡 Совет: для очень быстрых операций (меньше 500 мс) ProgressDialog не нужен. Он появится и исчезнет так быстро, что пользователь не заметит — только визуальное «мигание».

💡 Совет: для долгих операций с прогрессом (скачивание файла) используй ProgressBar с горизонтальным индикатором вместо ProgressDialog. Он показывает процент загрузки.

❌ Частая ошибка: забыть про dismiss. Диалог висит вечно, пользователь не может пользоваться приложением.

❌ Частая ошибка: не закрыть диалог при ошибке. В onErrorResponse забыт dismiss — загрузка продолжается бесконечно.

❌ Частая ошибка: использовать ProgressDialog для долгих операций без прогресса. Пользователь не понимает, работает ли приложение.

❌ Частая ошибка: не задавать сообщение. Диалог с пустым текстом выглядит непонятно.

❌ Частая ошибка: показывать ProgressDialog для операций без реальной загрузки. Например, при обычном переходе между экранами.
