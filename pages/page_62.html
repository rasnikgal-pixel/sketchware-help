SwipeRefreshLayout — обновление свайпом

SwipeRefreshLayout — контейнер с жестом «потянуть вниз для обновления». Классический элемент современных приложений: пользователь делает свайп сверху вниз по экрану — и появляется круглый индикатор загрузки, а содержимое обновляется.

Иконка в палитре — прямоугольник с круговой стрелкой внутри.

Как работает

  • Внутри SwipeRefreshLayout лежит прокручиваемое содержимое — обычно Scroll(V) с Linear(V) внутри или ListView / RecyclerView.
  • Когда пользователь находится в самом верху содержимого и тянет вниз — срабатывает событие onRefresh.
  • Наверху появляется круговой индикатор — стандартный спиннер Android.
  • После того как логика завершит обновление (загрузит данные), индикатор нужно вручную скрыть — через блок setRefreshing(false).
  • Если потянуть вниз, когда список уже прокручен вниз, — ничего не сработает.

Когда использовать

  • Ленты новостей — обновление списка постов.
  • Мессенджеры — проверка новых сообщений.
  • Списки товаров — обновление каталога.
  • Почта, уведомления — перезагрузка входящих.
  • Практически любой список, содержимое которого меняется со временем.

Из чего состоит

  • SwipeRefreshLayout — внешний контейнер с жестом.
  • Один дочерний элемент — прокручиваемое содержимое (Scroll(V), ListView, RecyclerView).
  • Индикатор — стандартный круглый спиннер, отображается сверху.
  • Слушатель (OnRefreshListener) — реагирует на свайп.

Настройки

Настройка Что делает Значения
ColorSchemeColors Цвета индикатора обновления. Один или несколько HEX-цветов.
ProgressBackgroundColor Фон под индикатором. HEX или выбор из палитры.
ProgressViewOffset Вертикальное смещение индикатора. Число в dp.
Enabled Включён ли жест. Переключатель: вкл / выкл.
Width / Height Ширина и высота компонента. match_parent для обоих.
Padding / Margin Внутренние и внешние отступы. Число в dp для каждой стороны.

Свойства контейнера

Открой панель свойств, тапнув по SwipeRefreshLayout в рабочей области. Ниже — все свойства с описанием. Значения указаны в том виде, в каком они отображаются в Sketchware Pro 7 (на скриншоте пример ID — swiperefreshlayout1).

Основные

Свойство (рус / англ) Что делает Значения Пример
ID Уникальное имя компонента. По этому имени он виден на вкладке «События» и в блоках логики. Любая строка без пробелов. По умолчанию — swiperefreshlayout1, swiperefreshlayout2 и т. д. Переименуй в newsRefresh, если это обновление ленты новостей.
Пользовательские атрибуты Дополнительные XML-атрибуты, которые можно задать вручную. Здесь задаются цвета индикатора и смещение. Пары «атрибут = значение». Например, app:progressBackgroundColor="#FFFFFF".
Конвертировать Показывает полный класс компонента: androidx.swiperefreshlayout.widget.SwipeRefreshLayout. SwipeRefreshLayout (AndroidX) и другие. Обычно менять не нужно.

Свойство (рус / англ) Что делает Значения Пример
Ширина
Width		 Насколько широким будет контейнер по горизонтали. match_parent — на всю ширину родителя;
wrap_content — по содержимому;
число в dp.		 match_parent — стандарт.
Высота
Height		 Насколько высоким будет контейнер по вертикали. match_parent, wrap_content, число в dp. match_parent — стандарт, чтобы контейнер занимал всё доступное место.
Внутренний отступ
Padding		 Отступ внутри контейнера — от краёв до содержимого. Формат: «осталось: N, top: N, right: N, bottom: N». Числа в dp для каждой стороны: left («осталось»), top, right, bottom. На скриншоте Padding = 8 со всех сторон.
Внешний отступ
Margin		 Отступ снаружи контейнера — от него до соседних элементов и краёв родителя. Числа в dp для каждой стороны: left («осталось»), top, right, bottom. Обычно 0 — контейнер занимает весь экран.
Гравитация макета
Layout gravity		 Как контейнер выравнивается внутри родителя. none — по умолчанию;
например, center_horizontal.		 Обычно оставляют none.
Вес
Weight		 Доля свободного места родителя, которую займёт контейнер. Работает только внутри родителя с весом. Число. 0 — вес не задан. 1 — контейнер заберёт всё оставшееся место (например, между шапкой и подвалом).

💡 Совет для новичков: ключевые параметры индикатора (ColorSchemeColors, ProgressBackgroundColor, ProgressViewOffset) задаются через Пользовательские атрибуты — их нужно вручную прописать в виде app:progressBackgroundColor="#FFFFFF" или в коде через блоки логики.

Как перетащить SwipeRefreshLayout на макет

SwipeRefreshLayout, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Раскрой категорию AndroidX в палитре слева.
  3. Зажми SwipeRefreshLayout и, не отпуская, перетащи его на макет — обычно внутрь Linear(V) или прямо в корень экрана.
  4. Отпусти в нужном месте — контейнер появится в разметке.
  5. Перетащи внутрь SwipeRefreshLayout один прокручиваемый элемент — обычно Scroll(V) с Linear(V) внутри или ListView.
  6. В свойствах задай базовые параметры: Ширина = match_parent, Высота = match_parent.
  7. Через Пользовательские атрибуты задай цвета индикатора или сделай это в логике через блоки.
  8. Открой вкладку «События» — добавь событие onRefresh.
  9. Внутри onRefresh опиши логику загрузки данных и обязательно добавь блок setRefreshing(false) в конце.
⚠️ Важно: обычный тап по SwipeRefreshLayout в палитре ничего не делает. Контейнер попадает на макет только перетаскиванием.
⚠️ Важно: индикатор обновления не скрывается автоматически. Если в событии onRefresh не вызвать setRefreshing(false), спиннер будет крутиться до перезапуска приложения.
⚠️ Важно: внутри SwipeRefreshLayout может быть только один прокручиваемый дочерний элемент. Если положить несколько — жест работать не будет.
⚠️ Важно: SwipeRefreshLayout рассчитан на вертикальную прокрутку. Для горизонтальной — не подойдёт.
💡 Совет: устанавливай setRefreshing(false) в конце логики, даже если данные не загрузились. Иначе при ошибке сети пользователь останется с «вечным» спиннером.
💡 Совет: не используй SwipeRefreshLayout там, где нет реальной необходимости обновлять данные. Если содержимое статично — жест будет только раздражать.
❌ Частая ошибка: забыть вызвать setRefreshing(false) в конце onRefresh. Индикатор крутится, пользователь думает, что приложение «зависло».

Резюме

  • SwipeRefreshLayout — контейнер с жестом «потянуть вниз для обновления».
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • Внутри может быть только один прокручиваемый дочерний элемент — обычно Scroll(V) с Linear(V) или ListView.
  • Срабатывает только когда содержимое прокручено в самый верх.
  • Требует события onRefresh и блока setRefreshing(false) в конце — иначе индикатор зависнет.
  • Рассчитан только на вертикальный жест.

Частые ошибки новичков

  • Тапают по SwipeRefreshLayout в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Забывают вызвать setRefreshing(false). Индикатор крутится бесконечно.
  • Кладут внутрь несколько дочерних элементов. Жест не работает — нужен ровно один.
  • Используют без прокручиваемого содержимого. Жест не сработает, если содержимое не прокручивается.
  • Пытаются обновлять горизонтальные списки. SwipeRefreshLayout — только для вертикали.
  • Не добавляют событие onRefresh. Свайп срабатывает, спиннер появляется, но данные не обновляются.
  • Ищут ColorSchemeColors в обычных свойствах. Их нужно задавать через «Пользовательские атрибуты» или через блоки логики.
