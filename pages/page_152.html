Firebase Auth — авторизация Firebase

Firebase Auth — облачная авторизация пользователей. Позволяет регистрировать и входить по email и паролю, не создавая собственный сервер. Firebase берёт на себя хранение учётных данных, проверку паролей и безопасность.

Иконка в диалоге добавления — логотип Firebase.

Как работает

  • Регистрация — пользователь создаёт аккаунт по email и паролю.
  • Вход — проверка существующего аккаунта.
  • Выход — завершение сессии.
  • Сброс пароля — отправка письма для восстановления.
  • Проверка email — подтверждение адреса письмом.
  • Текущий пользователь — получить данные авторизованного пользователя.
  • Все данные хранятся в Firebase — не нужно писать свой сервер.

Когда использовать

  • Приложения с личным кабинетом — у каждого пользователя свои данные.
  • Мессенджеры и соцсети — учётные записи.
  • Дневники и заметки — личные записи под аккаунтом.
  • Обучающие приложения — прогресс пользователя.
  • Приложения с подпиской — привязка оплаты к аккаунту.
  • Облачные хранилища — доступ к своим файлам с любого устройства.
  • Любое приложение, где нужны личные аккаунты.

Основные блоки в логике

Блок Что делает
createUserWithEmailAndPassword Регистрация.
signInWithEmailAndPassword Вход.
signOut Выход.
sendPasswordResetEmail Сброс пароля.
getCurrentUser Получить текущего пользователя.
getUid Получить ID пользователя.
getEmail Получить email.
isEmailVerified Проверить, подтверждён ли email.

События Firebase Auth

Событие Когда срабатывает
onAuthSuccess Успешная авторизация (регистрация или вход).
onAuthFailed Ошибка авторизации.
onEmailVerified Email подтверждён.

Как использовать

  1. Зарегистрируйся в Firebase Console.
  2. В разделе Authentication включи способ входа Email/Password.
  3. Скачай google-services.json и подключи его в Sketchware Pro 7.
  4. Подключи компонент Firebase Auth на вкладке «Компонент».
  5. Задай имя — например, auth.
  6. Добавь разрешение INTERNET.
  7. В логике:
    • регистрация — createUserWithEmailAndPassword с email и паролем из EditText;
    • вход — signInWithEmailAndPassword;
    • выход — signOut;
    • в onAuthSuccess — перейди на главный экран;
    • в onAuthFailed — покажи сообщение об ошибке.

Пример: вход по email и паролю

  • EditText для email, EditText для пароля.
  • Button «Войти» → onClick → signInWithEmailAndPassword.
  • onAuthSuccess → перейти на главный экран.
  • onAuthFailed → показать сообщение «Неверный email или пароль».

Пример: проверка при запуске

  • В onCreate — getCurrentUser.
  • Если пользователь уже вошёл — сразу открыть главный экран.
  • Если нет — показать экран входа.
⚠️ Важно: правила безопасности в Firebase Console должны разрешать работу с Auth. По умолчанию они настроены верно, но проверь.
⚠️ Важно: не храни пароли в своём коде или Firebase DB. Только через Firebase Auth. Он хеширует и защищает пароли.
⚠️ Важно: проверяй email перед использованием. Пользователь может зарегистрироваться с вымышленным адресом. Для критичных операций — используй sendEmailVerification.
⚠️ Важно: не показывай пользователю конкретные ошибки Firebase. Сообщение «Неверный пароль» или «Email уже занят» может помочь злоумышленнику. Показывай общее: «Ошибка входа».
⚠️ Важно: пароль должен быть надёжным. Firebase требует минимум 6 символов. Рекомендуй пользователю хотя бы 8 и с разными символами.
💡 Совет: для проверки email используй sendEmailVerification после регистрации. Пользователь получит письмо со ссылкой — по ней подтвердит адрес.
💡 Совет: для сохранения сессии Firebase помнит пользователя автоматически. При следующем запуске getCurrentUser вернёт его — не нужно заставлять входить заново.
💡 Совет: для сброса пароля используй sendPasswordResetEmail. Firebase отправит письмо со ссылкой для смены пароля.
💡 Совет: для профиля пользователя используй Firebase DB — храни там дополнительные данные: имя, аватар, возраст. А в Auth — только email и пароль.
💡 Совет: для выхода предусмотри кнопку в настройках. Пользователь должен иметь возможность сменить аккаунт.
💡 Совет: валидируй email перед отправкой. Регулярное выражение на формат name@domain.com. Если email неправильный — Firebase вернёт ошибку.
❌ Частая ошибка: не включить Email/Password в Firebase Console. Регистрация и вход не работают.
❌ Частая ошибка: хранить пароли в базе. Только Firebase Auth — безопасно.
❌ Частая ошибка: показывать конкретные ошибки («Неверный пароль», «Email занят»). Это помогает злоумышленнику подбирать учётные данные.
❌ Частая ошибка: не проверять текущего пользователя при запуске. Пользователь входит каждый раз заново.
❌ Частая ошибка: не предусмотреть выход. Пользователь не может сменить аккаунт.
❌ Частая ошибка: не валидировать email. Firebase вернёт ошибку, но лучше проверить заранее.

Резюме

  • Firebase Auth — облачная авторизация по email и паролю.
  • Основные блоки: createUserWithEmailAndPassword, signInWithEmailAndPassword, signOut, sendPasswordResetEmail, getCurrentUser, getUid, getEmail.
  • Основные события: onAuthSuccess, onAuthFailed, onEmailVerified.
  • Требует включения Email/Password в Firebase Console.
  • Не храни пароли — только Firebase Auth.
  • Не показывай конкретные ошибки — общее сообщение безопаснее.
  • Проверяй getCurrentUser при запуске — сохраняй сессию.
  • Для профиля — Firebase DB, для учётных данных — Auth.

Частые ошибки новичков

  • Не включают Email/Password в Console. Авторизация не работает.
  • Хранят пароли в базе. Грубая ошибка.
  • Показывают конкретные ошибки. Утечка информации злоумышленнику.
  • Не проверяют текущего пользователя при запуске. Вход каждый раз.
  • Не предусматривают выход. Нельзя сменить аккаунт.
  • Не валидируют email. Ошибки при отправке.
  • Используют слабые пароли. Firebase требует минимум 6 символов.
