ViewPager — страницы со свайпом

ViewPager — контейнер для горизонтальной прокрутки страниц. Пользователь свайпает влево-вправо и переключается между несколькими экранами, каждый из которых — отдельная «страница».

Иконка в палитре — прямоугольник с двумя стрелками влево-вправо.

Как работает

  • Отображает одну страницу за раз.
  • Пользователь свайпает влево или вправо — переключается на соседнюю страницу.
  • Каждая страница — это отдельный Layout или Fragment.
  • Содержимое страниц задаётся в логике через адаптер.
  • Может синхронизироваться с TabLayout — тогда вкладки сверху показывают текущую страницу и позволяют переключаться тапом.

Когда использовать

  • Онбординг — знакомство с приложением из 3–5 слайдов.
  • Галерея — пролистывание изображений.
  • Разделы одного экрана — «Новости», «Популярное», «Избранное» вместе с TabLayout.
  • Карусель баннеров — реклама или промо-блоки.
  • Пошаговые формы — заполнение по шагам: шаг 1, шаг 2, шаг 3.

Основные свойства

  • Adapter — задаётся в логике, не в свойствах.
  • CurrentItem — текущая страница (индекс).
  • OffscreenPageLimit — сколько страниц держать в памяти рядом с текущей.
  • Background — фон контейнера.
  • Width / Height — match_parent обычно.

Как добавить

  • Выбери контейнер, куда хочешь положить ViewPager. Обычно — корневой Linear(V).
  • Тап по ViewPager в палитре — компонент добавится внутрь.
  • Присвой id — для работы в логике.
  • Создай Layout или Fragment для каждой страницы в Менеджере представлений.
  • Открой вкладку «События» и добавь в onCreate:
    • блок setViewPagerAdapter — подключить адаптер;
    • блок setViewPagerData — задать список страниц.
  • Опционально — добавь TabLayout сверху и свяжи его с ViewPager через специальный блок.

⚠️ Важно: ViewPager не работает без адаптера. Без указания страниц в логике он пустой.

⚠️ Важно: для большого количества страниц задавай OffscreenPageLimit небольшим (1 или 2). Иначе приложение будет держать в памяти все страницы и потреблять много RAM.

⚠️ Важно: ViewPager не вставляй внутрь Scroll(H) — конфликт жестов. Горизонтальная прокрутка родителя «съест» свайп страниц.

💡 Совет: для онбординга используй ViewPager с 3 страницами и точками-индикаторами внизу (реализуются отдельно через Linear(H) с точками и логику).

💡 Совет: для разделов внутри одного экрана связка TabLayout + ViewPager — стандарт Android. Вкладки сверху, содержимое переключается и свайпом, и тапом.

💡 Совет: для галереи изображений используй ViewPager с каждой страницей = ImageView. Обязательно добавь индикатор текущей позиции (например, «3 / 10»).

💡 Совет: не делай 20 страниц в одном ViewPager. Если разделов больше 5 — подумай, нужен ли ViewPager вообще. Может, лучше BottomNavigationView или боковое меню.

❌ Частая ошибка: добавить ViewPager и забыть про адаптер в логике. Компонент пустой, свайп ничего не листает.

❌ Частая ошибка: вкладывать ViewPager в Scroll(H). Свайп работает нестабильно: либо прокручивается родитель, либо переключается страница — непредсказуемо.
