ViewPager — страницы со свайпом

ViewPager — контейнер для горизонтальной прокрутки страниц. Пользователь свайпает влево-вправо и переключается между несколькими экранами, каждый из которых — отдельная «страница».

Иконка в палитре — прямоугольник с двумя стрелками влево-вправо.

Как работает

  • Отображает одну страницу за раз.
  • Пользователь свайпает влево или вправо — переключается на соседнюю страницу.
  • Каждая страница — это отдельный Layout или Fragment.
  • Содержимое страниц задаётся в логике через адаптер.
  • Может синхронизироваться с TabLayout — тогда вкладки сверху показывают текущую страницу и позволяют переключаться тапом.

Когда использовать

  • Онбординг — знакомство с приложением из 3–5 слайдов.
  • Галерея — пролистывание изображений.
  • Разделы одного экрана — «Новости», «Популярное», «Избранное» вместе с TabLayout.
  • Карусель баннеров — реклама или промо-блоки.
  • Пошаговые формы — заполнение по шагам: шаг 1, шаг 2, шаг 3.

Настройки

Настройка Что делает Значения
Adapter Связывает данные со страницами. Задаётся в логике. PagerAdapter, FragmentPagerAdapter.
CurrentItem Текущая страница (индекс). Число от 0 до количества страниц − 1.
OffscreenPageLimit Сколько страниц держать в памяти рядом с текущей. Число. Обычно 1–2.
Background Фон контейнера. HEX или drawable-ресурс.
Width / Height Ширина и высота. Обычно match_parent.

Свойства виджета

Основные

Свойство (рус / англ) Что делает Значения Пример
ID Уникальное имя виджета. По этому имени виджет виден на вкладке «События» и в блоках логики. Любая строка без пробелов. По умолчанию — viewpager1, viewpager2 и т. д. Переименуй в onboarding, если это онбординг.
Пользовательские атрибуты Дополнительные XML-атрибуты, которые можно задать вручную. Нужны опытным пользователям. Пары «атрибут = значение». Например, android:clipToPadding="false".
Конвертировать Показывает полный класс: androidx.viewpager.widget.ViewPager. ViewPager и другие типы виджетов. Оставь как есть.
Пользовательский вид
Custom view		 Свой Layout для страницы (если страница — макет, а не Fragment). none — стандартный; любой XML-макет. Оставь none, если страницы задаются через адаптер.

Свойства макета

Свойство (рус / англ) Что делает Значения Пример
Ширина
Width		 Насколько широким будет контейнер по горизонтали. match_parent — на всю ширину родителя;
wrap_content — по содержимому;
число в dp.		 match_parent — стандарт.
Высота
Height		 Насколько высоким будет контейнер по вертикали. match_parent, wrap_content, число в dp. match_parent — чтобы страницы занимали весь экран.
Внутренний отступ
Padding		 Отступ внутри виджета. Формат: «осталось: N, top: N, right: N, bottom: N». Числа в dp для каждой стороны: left («осталось»), top, right, bottom. На скриншоте Padding = 8 со всех сторон.
Внешний отступ
Margin		 Отступ снаружи виджета — от него до соседних элементов. Числа в dp для каждой стороны: left («осталось»), top, right, bottom. Обычно 0.
Гравитация макета
Layout gravity		 Как виджет выравнивается внутри родителя. none — по умолчанию;
например, center_horizontal.		 Обычно оставляют none.
Вес
Weight		 Доля свободного места родителя, которую займёт виджет. Работает только внутри родителя с весом. Число. 0 — вес не задан. 1 — виджет заберёт всё оставшееся место.

Свойство (рус / англ) Что делает Значения Пример
Ресурс фона
Background resource		 Картинка-фон виджета из ресурсов проекта. NONE — без фона;
любой drawable-ресурс.		 Обычно оставляют NONE.
Цвет фона
Background color		 Заливка виджета сплошным цветом. NONE — без цвета;
HEX или выбор из палитры.		 Белый фон — #FFFFFF.
Enabled
Включено		 Реагирует ли виджет на свайп. Переключатель: вкл — активен;
выкл — заблокирован.		 На скриншоте — включено.
Вращение
Rotation		 Поворот виджета вокруг центра. Градусы. 0 — без поворота. Обычно оставляют 0.
Прозрачность
Alpha		 Насколько виджет прозрачен. Число от 0.0 (полностью прозрачный) до 1.0 (полностью непрозрачный). 1.0 — стандарт.
TranslationX Сдвиг виджета по горизонтали без изменения его места в разметке. Число в dp. 0.0 — без сдвига. 20.0 — визуально сдвинется на 20 dp вправо.
TranslationY Сдвиг виджета по вертикали без изменения его места в разметке. Число в dp. 0.0 — без сдвига. -10.0 — визуально поднимется на 10 dp.
ScaleX Масштаб по горизонтали — растягивает или сжимает виджет по ширине. Число. 1.0 — исходный размер. 1.5 — ширина увеличится в 1,5 раза.
ScaleY Масштаб по вертикали — растягивает или сжимает виджет по высоте. Число. 1.0 — исходный размер. 0.5 — высота уменьшится вдвое.
💡 Совет для новичков: в панели свойств задаётся только внешний вид. Страницы и адаптер задаются в логике — через блоки setViewPagerAdapter или setViewPagerData. Каждую страницу нужно создать отдельным макетом или Fragment.

Как перетащить ViewPager на макет

ViewPager, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V) или RelativeLayout. Обычно ViewPager — единственный элемент экрана.
  3. Раскрой категорию Списки в палитре слева.
  4. Зажми ViewPager и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — контейнер страниц появится в разметке.
  6. Присвой осмысленный ID — он нужен для логики.
  7. Создай Layout или Fragment для каждой страницы в Менеджере представлений.
  8. Открой вкладку «События» и добавь в onCreate:
    • блок setViewPagerAdapter — подключить адаптер;
    • блок setViewPagerData — задать список страниц.
  9. Опционально — добавь TabLayout сверху и свяжи его с ViewPager через специальный блок.
⚠️ Важно: обычный тап по ViewPager в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: ViewPager не работает без адаптера. Без указания страниц в логике он пустой.
⚠️ Важно: для большого количества страниц задавай OffscreenPageLimit небольшим (1 или 2). Иначе приложение будет держать в памяти все страницы и потреблять много RAM.
⚠️ Важно: ViewPager не вставляй внутрь Scroll(H) — конфликт жестов. Горизонтальная прокрутка родителя «съест» свайп страниц.
💡 Совет: для онбординга используй ViewPager с 3 страницами и точками-индикаторами внизу (реализуются отдельно через Linear(H) с точками и логику).
💡 Совет: для разделов внутри одного экрана связка TabLayout + ViewPager — стандарт Android. Вкладки сверху, содержимое переключается и свайпом, и тапом.
💡 Совет: для галереи изображений используй ViewPager с каждой страницей = ImageView. Обязательно добавь индикатор текущей позиции (например, «3 / 10»).
💡 Совет: не делай 20 страниц в одном ViewPager. Если разделов больше 5 — подумай, нужен ли ViewPager вообще. Может, лучше BottomNavigationView или боковое меню.
❌ Частая ошибка: перетащить ViewPager и забыть про адаптер в логике. Компонент пустой, свайп ничего не листает.
❌ Частая ошибка: вкладывать ViewPager в Scroll(H). Свайп работает нестабильно: либо прокручивается родитель, либо переключается страница — непредсказуемо.

Резюме

  • ViewPager — контейнер для горизонтальной прокрутки страниц со свайпом.
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • Работает только через адаптер, задаваемый в логике.
  • Каждая страница — отдельный Layout или Fragment.
  • Идеален для онбординга, галерей, разделов с TabLayout.
  • OffscreenPageLimit = 1–2 — для экономии памяти.
  • Не вкладывай ViewPager в Scroll(H) — конфликт жестов.
  • Не используй для 20+ страниц — подумай о другой навигации.

Частые ошибки новичков

  • Тапают по ViewPager в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Перетащили ViewPager, но не задали адаптер. Свайп ничего не листает.
  • Не создали макеты страниц. Адаптеру нечего показывать.
  • Вкладывают ViewPager в Scroll(H). Свайп работает нестабильно.
  • Ставят 10+ страниц. Тяжело для памяти, неудобно пользователю.
  • Забывают про индикатор текущей страницы. Пользователь не понимает, где он.
  • Не задают ID. Логика не может обратиться к компоненту.
