OTPView — поле OTP-кода

OTPView — поле для ввода одноразового кода (OTP). Представляет собой ряд отдельных ячеек, в которые пользователь вводит цифры по одной — как при подтверждении номера телефона по SMS или входе по email-коду.

Иконка в палитре — ряд отдельных прямоугольников с цифрами.

Как работает

  • Отображает несколько отдельных ячеек — обычно 4–6, по одной цифре в каждой.
  • Пользователь вводит цифры — курсор автоматически переходит к следующей ячейке.
  • Backspace — удаляет цифру и возвращается к предыдущей ячейке.
  • После заполнения всех ячеек срабатывает событие — можно проверить код.
  • Может вставлять код из буфера обмена автоматически (если включено).
  • Часто используется с автозаполнением из SMS — код подставляется сам.

Когда использовать

  • Подтверждение номера телефона — SMS-код.
  • Подтверждение email — код на почту.
  • Двухфакторная аутентификация — второй фактор входа.
  • Сброс пароля — код для смены пароля.
  • Одноразовые приглашения — вход по коду-приглашению.
  • Платёжные подтверждения — код из банковского приложения.

Настройки

Настройка Что делает Значения
OtpCount Количество ячеек. Обычно 4, 6 или 8.
OtpTextColor Цвет вводимых цифр. HEX или выбор из палитры.
OtpTextSize Размер цифр. Число в sp.
OtpBackgroundColor Фон ячеек. HEX или выбор из палитры.
BorderColor Цвет границы ячеек. HEX или выбор из палитры.
BorderWidth Толщина границы. Число в dp.
CornerRadius Радиус скругления ячеек. Число в dp.
ShowUnderline Показывать ли подчёркивание под ячейками. Переключатель: вкл / выкл.
AutoFocus Автоматически открывать клавиатуру при появлении виджета. Переключатель: вкл / выкл.
HideLineWhenFilled Скрывать подчёркивание, когда ячейка заполнена. Переключатель: вкл / выкл.
Width / Height Ширина и высота. Обычно match_parent по ширине, wrap_content по высоте.

Свойства виджета

Открой панель свойств, тапнув по OTPView в рабочей области. Ниже — все свойства с описанием. Значения указаны в том виде, в каком они отображаются в Sketchware Pro 7 (на скриншоте пример ID — otpview1).

Основные

Свойство (рус / англ) Что делает Значения Пример
ID Уникальное имя виджета. По этому имени виджет виден на вкладке «События» и в блоках логики. Любая строка без пробелов. По умолчанию — otpview1, otpview2 и т. д. Переименуй в smsCode, если это код из SMS.
Пользовательские атрибуты Дополнительные XML-атрибуты. Здесь задаётся количество ячеек, цвета, границы. Пары «атрибут = значение». Например, app:otp_count="6", app:border_color="#2196F3".
Конвертировать Показывает полный класс компонента: affan.ahmad.otp.OTPView. OTPView и другие типы виджетов. Оставь как есть.

💡 Совет для новичков: ключевые параметры (OtpCount, OtpTextColor, OtpTextSize, BorderColor, BorderWidth, CornerRadius) задаются через Пользовательские атрибуты — в виде app:otp_count="6", app:border_color="#2196F3". Проверка кода — в логике через событие onOtpCompletion.

Как перетащить OTPView на макет

OTPView, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V) или RelativeLayout.
  3. Раскрой категорию Библиотеки в палитре слева.
  4. Зажми OTPView и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — поле кода появится в разметке.
  6. Через Пользовательские атрибуты задай app:otp_count="6", app:border_width="2dp", app:corner_radius="8dp" и цвета.
  7. Присвой осмысленный ID — он нужен для логики.
  8. Открой вкладку «События» и добавь событие onOtpCompletion — оно срабатывает, когда пользователь ввёл все цифры.
  9. Внутри события сравни введённый код с ожидаемым и выполни действие.
⚠️ Важно: обычный тап по OTPView в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: проверка кода делается в логике. OTPView только принимает ввод, но не знает, какой код правильный.
⚠️ Важно: никогда не храни правильный код в открытом виде в приложении. Лучше проверяй на сервере через RequestNetwork. Если код фиксированный (например, для демо) — это плохой пример для реального приложения.
⚠️ Важно: не используй слишком короткий код. 4 цифры — 10 000 комбинаций, подбирается быстро. Минимум — 6 цифр.
💡 Совет: задавай OtpCount = 6 — стандарт для SMS-кодов. Такой код выглядит привычно и достаточно безопасен.
💡 Совет: делай ячейки с заметными границами (BorderWidth = 2dp) и скруглениями (CornerRadius = 8dp). Это выглядит современно и удобно для тапа.
💡 Совет: после ввода кода автоматически проверяй его — не заставляй пользователя ещё нажимать кнопку «Проверить». Событие onOtpCompletion срабатывает, как только введена последняя цифра.
💡 Совет: показывай таймер для повторной отправки кода: «Отправить код повторно можно через 60 секунд». Так пользователь не будет спамить запросами.
💡 Совет: для демонстрации можно использовать фиксированный код — например, 123456. Но в реальном приложении код всегда проверяется на сервере.
❌ Частая ошибка: хранить правильный код в приложении. Любой, кто декомпилирует APK, увидит его.
❌ Частая ошибка: не ограничивать число попыток. Если пользователь может вводить код бесконечно, его можно перебрать.
❌ Частая ошибка: использовать слишком длинные коды (10–12 цифр). Пользователю тяжело вводить, это раздражает.
❌ Частая ошибка: забывать про событие onOtpCompletion. Код вводится, но ничего не происходит.

Резюме

  • OTPView — поле для ввода одноразового кода из нескольких отдельных ячеек.
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • Ключевые параметры (OtpCount, цвета, границы) задаются через Пользовательские атрибуты.
  • Проверка кода — в логике, через событие onOtpCompletion.
  • Никогда не храни правильный код в приложении — проверяй на сервере.
  • Стандарт — 6 цифр, границы 2dp, скругления 8dp.
  • Ограничивай число попыток и добавляй таймер повторной отправки.

Частые ошибки новичков

  • Тапают по OTPView в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Хранят правильный код в приложении. APK легко декомпилируется.
  • Не добавляют событие onOtpCompletion. Код вводится, но не проверяется.
  • Ищут OtpCount и цвета в обычных свойствах. Через «Пользовательские атрибуты» — app:otp_count, app:border_color.
  • Используют 4 цифры. Легко подобрать перебором.
  • Не ограничивают число попыток. Код можно подбирать бесконечно.
  • Не задают ID. Логика не может обратиться к виджету.
