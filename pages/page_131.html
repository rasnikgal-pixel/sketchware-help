Dialog — диалоговое окно

Dialog — компонент для показа всплывающего диалогового окна. Показывает сообщение, задаёт вопрос, предлагает выбор — поверх текущего экрана. Пользователь отвечает, диалог закрывается.

Иконка в диалоге добавления — квадрат с полосой внизу (как окно).

Как работает

  • Открывает всплывающее окно в центре экрана.
  • Содержит заголовок, сообщение и кнопки (обычно 2–3).
  • Пользователь тапает по кнопке — срабатывает соответствующее событие.
  • Может быть информационным (только OK) или вопросом (Да / Нет).
  • Закрывается автоматически после нажатия кнопки или тапа вне окна (если разрешено).

Когда использовать

  • Подтверждение действий — «Удалить запись?».
  • Сообщения об ошибках — «Не удалось подключиться».
  • Информационные окна — «Изменения сохранены».
  • Выбор пользователя — «Сохранить, Отменить, Выйти».
  • Важные предупреждения — «Вы уверены? Действие необратимо».
  • Диалог ввода — реже, обычно для этого EditText в основной разметке.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова. Например, confirmDialog.

Основные блоки в логике

  • show — показать диалог.
  • setTitle — задать заголовок.
  • setMessage — задать текст сообщения.
  • setPositiveButton — настроить положительную кнопку.
  • setNegativeButton — настроить отрицательную кнопку.
  • setNeutralButton — настроить нейтральную кнопку.
  • dismiss — закрыть диалог программно.

События диалога

  • onDialogPositiveClick — при нажатии положительной кнопки (Да, ОК, Принять).
  • onDialogNegativeClick — при нажатии отрицательной кнопки (Нет, Отмена).
  • onDialogNeutralClick — при нажатии нейтральной кнопки (Позже, Пропустить).

Как использовать

  • Подключи компонент Dialog на вкладке «Компонент».
  • Задай имя — например, myDialog.
  • В Менеджере ресурсов → Менеджер строк задай тексты: заголовок, сообщение, кнопки. Либо пиши их прямо в блоках.
  • В категории «Компонент» вкладки «События» добавь события:
    • onDialogPositiveClick — что делать при «Да»;
    • onDialogNegativeClick — что делать при «Нет».
  • В логике вызови блок show — например, в onClick кнопки «Удалить».

Пример: подтверждение удаления

  • Кнопка «Удалить» → onClick → блок show для myDialog.
  • Заголовок: «Удаление».
  • Сообщение: «Удалить запись? Действие необратимо».
  • Положительная кнопка: «Удалить».
  • Отрицательная кнопка: «Отмена».
  • В onDialogPositiveClick — выполни удаление.
  • В onDialogNegativeClick — ничего (просто закрой диалог).

⚠️ Важно: тексты кнопок задаются в блоках (или через ресурсы). Без заданных надписей диалог может показать пустые кнопки.

⚠️ Важно: не показывай больше одного диалога одновременно. Второй вызов show, пока первый открыт — поведение непредсказуемо.

⚠️ Важно: диалог не заменяет экран. Для полноценного нового интерфейса используй Activity или Fragment.

⚠️ Важно: настройка закрытия диалога при тапе вне окна — в новых версиях Android эта опция может быть выключена по умолчанию. Проверь в свойствах компонента.

💡 Совет: для подтверждения опасных действий используй два диалога: сначала предупреждение, после подтверждения — выполнение.

💡 Совет: не злоупотребляй диалогами. Если приложение постоянно что-то спрашивает — это раздражает. Оставляй диалоги только для действительно важных решений.

💡 Совет: для информационных сообщений (без выбора) достаточно одной кнопки «ОК» — не создавай лишние «Нет».

💡 Совет: для сложных форм ввода используй отдельный экран, а не диалог. Диалоги плохо подходят для больших форм.

💡 Совет: тексты в диалогах пиши кратко и ясно. «Удалить запись?» — хорошо. «Вы действительно хотите безвозвратно удалить эту запись?» — слишком длинно.

❌ Частая ошибка: не добавлять события диалога. Пользователь нажимает «Да», но ничего не происходит.

❌ Частая ошибка: не задавать текст сообщения. Диалог открывается пустым — пользователь не понимает, что от него хотят.

❌ Частая ошибка: показывать диалог при каждом действии. Пользователь раздражается.

❌ Частая ошибка: называть кнопки неясно. «ОК / Отмена» — понятно. «Да / Нет» на вопрос «Продолжить удаление?» — путает, потому что вопрос обратный.
