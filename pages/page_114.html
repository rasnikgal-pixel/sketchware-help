Компонент

Компонент — третья категория в левом меню вкладки «События». Здесь собраны события сервисов, подключённых на вкладке «Компонент»: работа с сетью, базами данных, камерой, звуком, уведомлениями, рекламой и Firebase.

Если Активность — про жизненный цикл экрана, View — про виджеты, то Компонент — про внутренние сервисы приложения. Это невидимая часть, которая работает в фоне и обеспечивает функционал.

Список событий категории

Точный список зависит от того, какие компоненты подключены. Наиболее частые:

Компонент Событие Когда срабатывает
RequestNetwork onResponse При получении успешного ответа от сервера.
RequestNetwork onErrorResponse При ошибке сетевого запроса.
SharedPreferences — Работа через блоки getString, putString и т. д.
Timer onTimerTick Срабатывает на каждом «тике» таймера.
Timer onTimerFinished При завершении таймера.
Dialog onDialogPositiveClick При нажатии положительной кнопки.
Dialog onDialogNegativeClick При нажатии отрицательной кнопки.
Dialog onDialogNeutralClick При нажатии нейтральной кнопки.
MediaPlayer onPrepared Когда медиа готово к воспроизведению.
MediaPlayer onCompletion При завершении воспроизведения.
MediaPlayer onError При ошибке воспроизведения.
Camera onPictureTaken После снимка.
Camera onCameraError При ошибке.
LocationManager onLocationChanged При изменении местоположения.
LocationManager onProviderDisabled При отключении провайдера (например, GPS).
TextToSpeech onSpeechFinished После завершения озвучивания.
SpeechToText onSpeechResult При распознавании речи.
Firebase DB onDataChange При получении данных.
Firebase DB onCancelled При ошибке.
Firebase Auth onAuthSuccess Успешная авторизация.
Firebase Auth onAuthFailed Ошибка авторизации.
Notification — Управление через блоки.
ProgressDialog — Управление через show, dismiss.

Когда что использовать

Событие Зачем использовать
onResponse Обработка данных из сети: парсинг JSON, отображение в интерфейсе.
onErrorResponse Сообщение об ошибке, скрытие ProgressBar.
onTimerTick Обновление счётчика, обновление UI каждую секунду.
onDialogPositiveClick / onDialogNegativeClick Реакция на выбор пользователя в диалоге.
onPictureTaken Сохранить снимок, показать его на экране.
onLocationChanged Обновить карту, показать координаты.
onSpeechResult Использовать распознанный текст в логике.

Как добавить событие

  • Убедись, что нужный компонент подключён на вкладке «Компонент».
  • Тапни по категории «Компонент» в левом меню.
  • В открывшемся диалоге — список компонентов и доступных для них событий.
  • Отметь нужные галочками.
  • Нажми «Добавить» — события появятся в списке центральной области.
⚠️ Важно: категория «Компонент» пуста, пока в проекте нет подключённых компонентов. Сначала добавь компонент на вкладке «Компонент», потом возвращайся сюда.
⚠️ Важно: не все компоненты имеют события. Например, SharedPreferences, Notification, Vibrator — управляются только через блоки, но не имеют своих событий.
⚠️ Важно: события компонентов привязываются к конкретному компоненту. Если у тебя два RequestNetwork, то события onResponse будут отдельно для каждого — нужно указывать, к какому компоненту привязано событие.
💡 Совет: для сетевых запросов обязательно добавляй оба события: onResponse и onErrorResponse. Иначе при ошибке сети ничего не произойдёт — пользователь будет ждать вечно.
💡 Совет: для таймеров используй onTimerTick для обновления интерфейса, а onTimerFinished — для логики завершения.
💡 Совет: для диалогов добавляй все нужные события сразу: если у диалога три кнопки — три события. Иначе нажатия на некоторые кнопки ничего не сделают.
💡 Совет: не добавляй события компонентов «на всякий случай». Каждое событие — метод в коде. Мусорные события увеличивают APK и замедляют сборку.
❌ Частая ошибка: добавлять событие без подключённого компонента. Категория «Компонент» будет пустой, и событие добавить не получится.
❌ Частая ошибка: не обрабатывать ошибки сети. При сбое приложение «зависает» без сообщения пользователю.
❌ Частая ошибка: путать событие компонента и блок компонента. Событие — реакция на действие (например, «ответ получен»). Блок — команда (например, «отправить запрос»).
❌ Частая ошибка: не указывать, к какому компоненту относится событие, если их несколько. Sketchware может привязать событие не к тому экземпляру.

Резюме

  • Компонент — категория событий сервисов, подключённых на вкладке «Компонент».
  • События этой категории реагируют на действия сервисов: ответ сети, тик таймера, выбор в диалоге.
  • Список событий зависит от подключённых компонентов: RequestNetwork, Timer, Dialog, Camera, Firebase и другие.
  • Не все компоненты имеют события: например, SharedPreferences и Notification работают только через блоки.
  • Если у тебя несколько компонентов одного типа — события привязываются к конкретному экземпляру.
  • Обязательно обрабатывай onErrorResponse для сетевых запросов.
  • Не добавляй события «про запас» — только те, что действительно нужны.
  • Для добавления события сначала подключи компонент, потом добавь событие.

Частые ошибки новичков

  • Пытаются добавить событие без подключённого компонента. Категория пуста.
  • Не обрабатывают onErrorResponse. При ошибке сети ничего не происходит.
  • Путают событие и блок компонента. Событие — реакция, блок — команда.
  • Не указывают, к какому экземпляру относится событие. Логика срабатывает неправильно.
  • Добавляют события «про запас». Мусор в коде, тяжелее APK.
  • Ищут события SharedPreferences. Их нет — работа только через блоки.
  • Не добавляют все нужные события Dialog. Часть кнопок диалога не работает.
