Менеджер чтения Logcat

Менеджер чтения Logcat — раздел меню «Настройка», через который читаются логи приложения в реальном времени. Здесь видно всё, что происходит во время работы: действия пользователя, ошибки, сетевые запросы, системные сообщения.

Иконка в меню — журнал или список строк.

Что такое Logcat

Logcat — системный журнал Android, куда приложение и система пишут сообщения. Каждое действие оставляет след: запуск Activity, нажатие, ошибка, ответ от сервера.

Сообщения делятся по уровням:

  • Verbose (V) — всё подряд, максимально подробно.
  • Debug (D) — отладочные сообщения.
  • Info (I) — информационные.
  • Warning (W) — предупреждения.
  • Error (E) — ошибки.
  • Fatal (F) — критические сбои.

Зачем нужен Logcat

  • Найти причину падения — приложение вылетело, а почему — неясно. Logcat покажет стек вызовов.
  • Проверить работу кода — например, приходит ли ответ от сервера.
  • Отладить логику — увидеть, что происходит между блоками.
  • Проверить сетевые запросы — URL, ответы, ошибки.
  • Проверить Firebase — авторизация, база данных, ошибки.
  • Проверить рекламу — загрузилась ли, показалась ли.

Как открыть

  • Открой меню ⋮ → Менеджер чтения Logcat.
  • Откроется окно с логами в реальном времени.
  • Вверху — фильтры по уровню (Verbose, Debug, Info, Warning, Error).
  • Строки обновляются автоматически по мере работы приложения.
  • Тап по строке — раскрывает подробности.

Что можно увидеть

  • Запуск Activity — onCreate, onStart, onResume и другие события.
  • Нажатия кнопок — если ты добавил вывод в лог.
  • Сетевые запросы — URL, метод, статус ответа.
  • Ошибки — тип исключения, стек вызовов.
  • Firebase — успешные авторизации, ошибки, события.
  • Реклама — загрузка, показ, ошибки.
  • Предупреждения системы — утечки памяти, проблемы с потоками.

Как использовать

  • Запусти приложение через кнопку «Запустить».
  • Открой Logcat в Sketchware.
  • Выполни действие, которое нужно проверить.
  • Смотри, какие строки появляются в логе.
  • Ищи строки с уровнем Error или Fatal — там обычно причина проблемы.

Пример: приложение падает

  • Открываешь Logcat.
  • Фильтруешь по Error.
  • Видишь строку: NullPointerException at MainActivity.java:45.
  • Открываешь MainActivity.java — строка 45.
  • Там блок, который обращается к пустому значению.
  • Исправляешь логику — добавляешь проверку.

Пример: сеть не работает

  • Отправляешь запрос через RequestNetwork.
  • Смотришь Logcat.
  • Видишь: Connection timed out — сервер не отвечает.
  • Или UnknownHostException — неверный URL.
  • Или Permission denied — нет разрешения INTERNET.

Как добавить свой лог

  • В логике используй блок Log или Toast — вывод в лог.
  • Log.d("TAG", "значение") — запишет сообщение в Logcat.
  • Полезно для отладки переменных.

⚠️ Важно: Logcat обновляется в реальном времени. Читай его, пока приложение работает.

⚠️ Важно: логов много. Не пытайся прочитать всё — фильтруй по уровню или по тегу.

⚠️ Важно: логи не сохраняются надолго. При перезапуске приложения или устройства — журнал очищается.

⚠️ Важно: не все ошибки попадают в Logcat. Некоторые проявляются только у пользователей.

⚠️ Важно: на релизе отключай свои отладочные логи. Они замедляют работу и могут раскрыть внутреннюю информацию.

💡 Совет: фильтруй по Error при поиске причины падения. Это сэкономит время.

💡 Совет: добавляй свои логи через блок Log перед подозрительными блоками. Так увидишь, до какого места код дошёл.

💡 Совет: не выводи в лог чувствительные данные — пароли, токены. Логи могут быть доступны.

💡 Совет: используй теги для своих логов. Например, Log.d("MyApp", "сообщение"). Легче фильтровать.

💡 Совет: если приложение падает при запуске — Logcat покажет ошибку раньше, чем ты успеешь что-то сделать.

💡 Совет: сравнивай логи до и после изменения. Видно, как изменение повлияло.

💡 Совет: не пугайся красных строк. Часть из них — обычные предупреждения системы.

❌ Частая ошибка: игнорировать Logcat. Это самый полезный инструмент отладки.

❌ Частая ошибка: читать весь лог подряд. Фильтруй по уровню.

❌ Частая ошибка: выводить пароли в лог. Логи могут быть видны другим.

❌ Частая ошибка: не использовать свои логи для отладки. Добавь Log.d в ключевых местах.

❌ Частая ошибка: оставлять отладочные логи в релизе. Замедляют работу, раскрывают информацию.

❌ Частая ошибка: паниковать при виде красных строк. Многие ошибки — некритичные.
