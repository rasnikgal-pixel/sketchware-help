Менеджер AndroidManifest

Менеджер AndroidManifest — раздел меню «Настройка», через который редактируется AndroidManifest.xml — главный файл конфигурации Android-приложения.

AndroidManifest.xml — это «паспорт» приложения. В нём описано всё: имя пакета, версии, разрешения, Activity, сервисы, тема. Без корректного манифеста приложение не соберётся и не установится.

Иконка в меню — значок с буквой M или XML.

Что содержит манифест

Элемент Что описывает
Имя пакета (package) Уникальный идентификатор приложения.
Версии versionCode и versionName.
Разрешения (uses-permission) Какие функции доступны приложению.
Activity Все экраны приложения.
Сервисы Фоновые компоненты.
Провайдеры Общие данные между приложениями.
Тема приложения Какая тема используется.
Иконка и название Как приложение выглядит на устройстве.

Зачем редактировать

  • Добавить Activity вручную, если не создаётся через Менеджер представлений.
  • Изменить тему приложения.
  • Добавить разрешения, которых нет в Менеджере разрешений.
  • Настроить intent-filter — для открытия ссылок, файлов.
  • Задать launchMode — как Activity ведёт себя при запуске.
  • Настроить configChanges — что происходит при повороте экрана.

Основные элементы

Элемент Что описывает
<manifest> Корневой элемент.
<uses-permission> Разрешение.
<application> Описание приложения.
<activity> Activity (экран).
<service> Сервис.
<receiver> Приёмник широковещательных сообщений.
<provider> Контент-провайдер.
<intent-filter> Фильтр для неявных Intent.

Как открыть

  1. Открой меню ⋮ → Менеджер AndroidManifest.
  2. Откроется содержимое AndroidManifest.xml в текстовом редакторе.
  3. Редактируй как текст.
  4. Нажми «Сохранить» — изменения применяются.

Как использовать

  • Добавить разрешение — вставь строку: 
    <uses-permission android:name="android.permission.НАЗВАНИЕ" />
  • Изменить тему — в теге <application> измени android:theme.
  • Настроить Activity — добавь <activity> с нужными параметрами.
  • Проверить корректность — после правки пересобери проект.
⚠️ Важно: одна ошибка в синтаксисе — и проект не соберётся. XML чувствителен к каждой кавычке и скобке.
⚠️ Важно: делай резервную копию перед редактированием. Откатить изменения сложно.
⚠️ Важно: не удаляй стандартные Activity и разрешения, которые добавляет Sketchware. Приложение перестанет работать.
⚠️ Важно: не редактируй манифест, если не понимаешь структуру. В большинстве случаев задачи решаются через Менеджер разрешений и Менеджер представлений.
⚠️ Важно: проверяй проект после каждой правки. Ошибки видны только при сборке.
💡 Совет: открывай манифест только когда стандартные средства не справляются. Например, для добавления нового разрешения, которого нет в Менеджере.
💡 Совет: копируй фрагменты манифеста из проверенных источников — Stack Overflow, документации Google. Не пиши XML-структуры с нуля.
💡 Совет: сохраняй копию манифеста в отдельном файле. Если что-то сломается — вернёшься к рабочей версии.
💡 Совет: комментируй изменения через <!-- комментарий -->. Так поймёшь, что менял.
💡 Совет: для открытия ссылок в приложении — добавь intent-filter с android:scheme. Например, для ссылок myapp://.
💡 Совет: для настройки поведения при повороте — используй android:configChanges. Это уменьшит пересоздание Activity.
❌ Частая ошибка: пропустить кавычку или закрывающий тег. Проект не собирается.
❌ Частая ошибка: удалить стандартные разрешения. Приложение работает неправильно.
❌ Частая ошибка: не делать резервную копию. Восстановить проект сложно.
❌ Частая ошибка: редактировать манифест без понимания. Ошибки трудно найти.
❌ Частая ошибка: не пересобирать проект после правки. Изменения не применяются.
❌ Частая ошибка: писать XML на глаз. Синтаксис строгий, никаких вольностей.

Резюме

  • Менеджер AndroidManifest — раздел для ручного редактирования AndroidManifest.xml.
  • Манифест описывает: имя пакета, версии, разрешения, Activity, сервисы, тему.
  • Используется для правок, недоступных через стандартные средства.
  • Требует понимания XML-синтаксиса — ошибка ломает сборку.
  • Не удаляй стандартные элементы — приложение не соберётся.
  • Делай резервную копию перед правкой.
  • Комментируй изменения — потом легче понять, что менял.
  • Пересобирай проект после каждой правки.

Частые ошибки новичков

  • Пропускают кавычки и теги. Проект не собирается.
  • Удаляют стандартные разрешения. Приложение работает неправильно.
  • Не делают резервную копию. Восстановить сложно.
  • Правят без понимания. Ошибки трудно найти.
  • Не пересобирают после правки. Изменения не применяются.
  • Пишут XML на глаз. Синтаксис строгий.
  • Используют для простых задач. Менеджер разрешений справится быстрее.
