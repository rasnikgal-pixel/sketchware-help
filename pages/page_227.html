Логика MainActivity

Логика — вкладка, где описывается поведение приложения. Здесь мы отвечаем на вопросы: что происходит при запуске экрана? что при нажатии на кнопку? что при выборе элемента списка?

Логика строится из событий — точек входа. Внутри каждого события — цепочка блоков, которые выполняются сверху вниз. Блоки перетаскиваются из палитры на блочное полотно, как виджеты на макет.

В MainActivity у нас будет четыре события:

  1. При создании / (onCreate) — загрузка списка проектов, применение темы.
  2. Нажатие кнопки «Тема» / (btnTheme onClick) — переключение светлой/тёмной темы.
  3. Нажатие кнопки «+ Создать» / (btnCreate onClick) — создание нового проекта.
  4. Нажатие на элемент списка / (listProjects onItemClick) — открытие проекта в редакторе.

Прежде чем начать, разберёмся с базовыми понятиями логики.

Как открыть логику экрана

  1. Открой вкладку «События».
  2. Переключись на нужный экран через селектор внизу (или через Менеджер представлений).
  3. Ты увидишь список событий текущего экрана.

Как добавить событие

  1. В левом меню выбери категорию:
    • Активность — события экрана.
    • View — события виджетов.
    • Компонент — события сервисов.
  2. Нажми «+» внизу справа.
  3. В диалоге отметь нужные события.
  4. Нажми «Добавить».
Подсказка для новичка. Событие При создании / (onCreate) уже создано автоматически. Остальные — добавляются вручную.

Что такое событие

Событие — это действие или ситуация, на которую реагирует приложение. Например: «экран создан», «пользователь нажал кнопку», «текст изменился». Событие — это точка входа в логику. Без него блоки не выполняются.

Основные события Activity:

Событие Когда срабатывает
При создании / (onCreate)При создании экрана. Самый первый и самый важный.
При запуске / (onStart)При появлении экрана на устройстве.
При возобновлении / (onResume)При возврате на экран.
При паузе / (onPause)Когда пользователь уходит с экрана.
При остановке / (onStop)Когда экран стал невидим.
При уничтожении / (onDestroy)При закрытии экрана.
При нажатии «Назад» / (onBackPressed)При нажатии системной кнопки «Назад».

Что такое блок

Блок — это отдельная команда. Каждый блок делает что-то конкретное: устанавливает текст, показывает сообщение, читает данные, складывает числа. Блоки собираются в цепочку — она выполняется сверху вниз.

Блоки бывают разных форм:

  • Последовательные — вставляются друг под друга. Основные команды.
  • Вложенные — имеют «карман» для других блоков (условия, циклы).
  • Значения — вставляются в «дырки» других блоков, возвращают результат.
Подсказка для новичка. Блоки попадают на полотно только перетаскиванием. Тап по блоку в палитре ничего не делает. Нужно зажать блок пальцем и перетащить на полотно события.

Событие 1. При создании / (onCreate)

Когда срабатывает: при первом открытии MainActivity. Это происходит, когда пользователь запускает приложение, и когда он возвращается на главный экран с других экранов (если Activity была пересоздана).

Что делает: загружает список проектов из хранилища, применяет сохранённую тему, заполняет ListView.

Порядок блоков:

  1. Прочитать из хранилища флаг тёмной темы — Прочитать булево / (Get Boolean), ключ theme_dark, значение по умолчанию false. Результат в переменную isDark.
  2. Если isDark == true — вызвать блок Установить ночной режим / (Set Night Mode) со значением Да / (Yes). Если false — со значением Нет / (No).
  3. Прочитать из хранилища строку projects_list — Прочитать строку / (Get String), значение по умолчанию "". Результат в rawList.
  4. Если rawList == "" — заполнить ListView одной строкой «Пока нет проектов». Для этого использовать блок Установить список / (Set List Data).
  5. Иначе — разбить строку по разделителю ;;; через блок Разделить / (Split). Получить список items. Заполнить ListView через Установить список / (Set List Data).

Что важно понять:

  • onCreate срабатывает один раз за время жизни экрана. Если пользователь вернётся на MainActivity из редактора, и Activity не была уничтожена — onCreate не сработает повторно.
  • Разделитель ;;; выбран не случайно. Это три точки с запятой — редкая комбинация, которая не встретится в обычных названиях проектов.
  • Значение по умолчанию при чтении обязательно. Без него при первом запуске Прочитать строку / (Get String) вернёт ошибку или пустое значение — непредсказуемо.

Псевдокод onCreate:

// ──── ШАГ 1. Читаем сохранённый флаг тёмной темы ────
// Обращаемся к хранилищу.
// Ключ "theme_dark" — по нему хранится значение.
// false — значение по умолчанию, если ключа ещё нет (первый запуск).
isDark = getBoolean("theme_dark", false)

// ──── ШАГ 2. Применяем тему ────
// Если сохранён флаг тёмной темы — включаем ночной режим.
if (isDark == true) {
    setNightMode(YES)
} else {
    setNightMode(NO)
}

// ──── ШАГ 3. Читаем список проектов ────
// Пустая строка — значение по умолчанию для первого запуска.
rawList = getString("projects_list", "")

// ──── ШАГ 4. Проверяем, есть ли проекты ────
if (rawList == "") {
    // Проектов нет — показываем заглушку в списке.
    listProjects.setListData(["Пока нет проектов"])
} else {
    // Проекты есть — разбиваем строку по разделителю ;;;.
    // Получаем массив строк, где каждая строка — один проект.
    items = rawList.split(";;;")

    // Заполняем ListView.
    listProjects.setListData(items)
}

Событие 2. Нажатие кнопки «Тема» / (btnTheme onClick)

Когда срабатывает: при тапе по кнопке «Тема» в шапке главного экрана.

Что делает: переключает светлую/тёмную тему, сохраняет выбор, перезапускает экран для применения.

Порядок блоков:

  1. Прочитать из хранилища текущий флаг — Прочитать булево / (Get Boolean), ключ theme_dark, значение по умолчанию false. Результат в isDark.
  2. Если isDark == true:
    • Записать false в ключ theme_dark через Записать булево / (Put Boolean).
    • Установить ночной режим — Нет / (No).
  3. Иначе:
    • Записать true в ключ theme_dark.
    • Установить ночной режим — Да / (Yes).
  4. Перезапустить текущий экран — Пересоздать / (Recreate). Это применит тему.

Что важно понять:

  • Смена темы не применяется мгновенно. Нужно пересоздать Activity — Пересоздать / (Recreate). Это делает Android сам: закрывает и заново открывает экран с новой темой.
  • Флаг сохраняется в хранилище — чтобы при следующем запуске приложение вспомнило выбор пользователя.
  • Логика «прочитать — перевернуть — записать» — это классический приём для переключателя.

Псевдокод onClick btnTheme:

// ──── ШАГ 1. Читаем текущее значение флага ────
// isDark будет true, если тёмная тема включена.
isDark = getBoolean("theme_dark", false)

// ──── ШАГ 2. Переключаем флаг и применяем тему ────
if (isDark == true) {
    // Если тема была тёмной — переключаем на светлую.
    putBoolean("theme_dark", false)
    setNightMode(NO)
} else {
    // Если тема была светлой — переключаем на тёмную.
    putBoolean("theme_dark", true)
    setNightMode(YES)
}

// ──── ШАГ 3. Пересоздаём Activity для применения темы ────
// recreate() закрывает текущий экран и создаёт его заново.
// Уже с новой темой — потому что флаг в хранилище изменился.
recreate()

Событие 3. Нажатие кнопки «+ Создать» / (btnCreate onClick)

Когда срабатывает: при тапе по кнопке «+ Создать» внизу главного экрана.

Что делает: открывает диалог ввода имени и автора проекта, затем сохраняет новый проект в хранилище и обновляет список.

Порядок блоков:

  1. Настроить и показать диалог — Диалог / (Dialog) → Установить заголовок / (Set Title), Установить сообщение / (Set Message), Показать / (Show).
  2. В событии При нажатии положительной / (onDialogPositiveClick):
    • Прочитать текст из полей — Получить текст / (Get Text) для inputName и inputAuthor.
    • Если name == "" — показать сообщение «Введите имя проекта» и не продолжать.
    • Сгенерировать уникальный ID проекта — Получить текущее время в миллисекундах / (Get Current Time Millis).
    • Собрать строку записи: name + ";;;" + author + ";;;" + id.
    • Прочитать текущий список projects_list.
    • Если список пуст — записать в projects_list строку записи.
    • Иначе — записать rawList + ";;;" + entry.
    • Сохранить метаданные проекта по отдельным ключам.
    • Обновить ListView.
    • Показать сообщение «Проект создан».

Что важно понять:

  • Диалог — это отдельный компонент. В свойствах задаётся, какие поля ввода он показывает. Обычно используется настройка через пользовательские атрибуты.
  • ID проекта генерируется из текущего времени в миллисекундах. Это гарантирует уникальность.
  • Структура данных: список проектов хранится одной строкой, где записи разделены ;;;. Каждая запись — три поля через ;;;.
  • После создания проекта нужно обновить ListView. Он не обновляется автоматически.

Псевдокод onClick btnCreate:

// ──── ШАГ 1. Настраиваем диалог ────
// Заголовок и кнопки задаются для компонента myDialog.
myDialog.setTitle("Новый проект")
myDialog.setPositiveButton("Создать")
myDialog.setNegativeButton("Отмена")

// Диалог содержит два EditText. Они добавлены через пользовательские атрибуты
// с id inputName и inputAuthor.

// ──── ШАГ 2. Показываем диалог ────
myDialog.show()

// ──── ШАГ 3. Обработка нажатия «Создать» ────
// В событии onDialogPositiveClick:

// Читаем текст из полей диалога.
name = inputName.getText()
author = inputAuthor.getText()

// Проверяем, что имя не пустое.
if (name == "") {
    Toast("Введите имя проекта")
    return
}

// Генерируем уникальный ID проекта.
id = getCurrentTimeMillis()

// Собираем строку записи.
entry = name + ";;;" + author + ";;;" + id

// Читаем текущий список проектов.
rawList = getString("projects_list", "")

// Добавляем новую запись.
if (rawList == "") {
    putString("projects_list", entry)
} else {
    putString("projects_list", rawList + ";;;" + entry)
}

// Сохраняем метаданные проекта отдельными ключами.
putString("project_" + id + "_name", name)
putString("project_" + id + "_author", author)
putString("project_" + id + "_structure", "")
putString("project_" + id + "_pages", "")

// ──── ШАГ 4. Обновляем список на экране ────
rawList = getString("projects_list", "")
items = rawList.split(";;;")
listProjects.setListData(items)

// ──── ШАГ 5. Показываем подтверждение ────
Toast("Проект создан")

Событие 4. Нажатие на элемент списка / (listProjects onItemClick)

Когда срабатывает: при тапе по любому элементу списка проектов.

Что делает: открывает EditorActivity для выбранного проекта и передаёт ему ID проекта.

Порядок блоков:

  1. Получить текст нажатого элемента — Получить элемент / (Get Item At) для listProjects с позицией position. Результат в entry.
  2. Разбить строку по ;;; через Разделить / (Split). Получить массив parts.
  3. Взять третий элемент массива — это ID проекта — id = parts[2].
  4. Сохранить ID последнего проекта в хранилище: Записать строку / (Put String), ключ last_project_id, значение id.
  5. Установить экран для перехода — Установить экран / (Set Screen) для компонента goToScreen, экран — EditorActivity.
  6. Добавить данные для передачи — Добавить данные / (Put Extra), ключ project_id, значение id.
  7. Запустить экран — Запустить экран / (Start Activity).

Что важно понять:

  • Позиция (position) — это номер нажатого элемента в списке. Начинается с 0.
  • Мы не передаём весь текст элемента в редактор — только ID. В редакторе по ID мы прочитаем имя, автора и структуру проекта из хранилища. Это надёжнее.
  • Мы сохраняем last_project_id — это пригодится, если пользователь вернётся к проекту позже.

Псевдокод onItemClick listProjects:

// ──── ШАГ 1. Получаем текст нажатого элемента ────
// position — это номер элемента, который пришёл в событие.
entry = listProjects.getItemAt(position)

// ──── ШАГ 2. Разбиваем строку на части ────
// Каждая запись — три поля, разделённые ;;;.
// parts[0] — имя, parts[1] — автор, parts[2] — id.
parts = entry.split(";;;")

// ──── ШАГ 3. Берём ID проекта ────
id = parts[2]

// ──── ШАГ 4. Сохраняем ID последнего проекта ────
// Пригодится, если пользователь вернётся к проекту.
putString("last_project_id", id)

// ──── ШАГ 5. Готовим переход ────
// Указываем, какой экран открыть.
goToScreen.setScreen(EditorActivity)

// Передаём ID проекта в новый экран.
goToScreen.putExtra("project_id", id)

// ──── ШАГ 6. Открываем экран ────
goToScreen.startActivity()

Сводная таблица событий MainActivity

Событие Когда срабатывает Что делает Основные компоненты
onCreate При открытии экрана Загрузка списка проектов, применение темы getBoolean, getString, setListData, setNightMode
btnTheme onClick Тап по кнопке «Тема» Переключение светлой/тёмной темы getBoolean, putBoolean, setNightMode, recreate
btnCreate onClick Тап по кнопке «+ Создать» Создание нового проекта myDialog, putString, getString, Toast

Что важно понять про логику MainActivity

Первое — события не смешиваются. Каждое событие — отдельный метод. Блоки одного события не видят переменные другого. Если нужно передать данные из onCreate в onClick — используй хранилище или глобальные переменные (переменные уровня Activity).

Второе — порядок блоков критичен. Сначала читаем, потом проверяем, потом действуем. Если переставить местами, приложение будет работать неправильно.

Третье — обновление ListView делается вручную. ListView не «следит» за данными в хранилище. После каждого изменения нужно заново вызвать Установить список / (Set List Data).

Четвёртое — проверки обязательны. Пустая строка, отсутствие данных, отмена действия — всё это нужно обрабатывать. Иначе приложение упадёт или покажет непонятное поведение.

Совет. После того как опишешь все события — собери проект и проверь. Создай проект, перезапусти приложение, проверь, что он сохранился. Удали проект, проверь, что удалился. Переключи тему, перезапусти — проверь, что тема запомнилась.
Частая ошибка. Забыть про проверку на пустую строку при чтении из хранилища. Если данных нет (первый запуск) и значение по умолчанию не задано — приложение может упасть или показать пустой экран без объяснений. Всегда указывай значение по умолчанию.
