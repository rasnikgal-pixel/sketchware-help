SeekBar — ползунок

SeekBar — ползунок для выбора значения из диапазона. Пользователь тянет ползунок влево или вправо, задавая число в определённых пределах.

Иконка в палитре — горизонтальная линия с круглым ползунком.

Как работает

  • Представляет диапазон значений — обычно от 0 до 100, но можно задать любой.
  • Пользователь тянет ползунок — значение меняется.
  • Текущее значение можно прочитать в логике через блок getProgress.
  • При движении ползунка срабатывает событие onProgressChanged — можно реагировать в реальном времени.
  • При отпускании ползунка срабатывает onStopTrackingTouch — удобно для сохранения значения.

Когда использовать

  • Громкость — регулятор звука.
  • Яркость — настройка экрана.
  • Размер шрифта — выбор из диапазона.
  • Рейтинг — оценка от 1 до 10.
  • Фильтр цены — выбор максимальной цены.
  • Прогресс воспроизведения — позиция в аудио или видео.
  • Любое числовое значение с диапазоном.

Настройки

Min Минимальное значение диапазона. Число. Обычно 0.
ProgressTint Цвет пройденной части полосы. HEX или выбор из палитры.
ProgressBackgroundTint Цвет оставшейся части полосы. HEX или выбор из палитры.

Padding / Margin Внутренние и внешние отступы. Число в dp для каждой стороны.
Width / Height Ширина и высота. match_parent по ширине, wrap_content по высоте.

Как перетащить SeekBar на макет

SeekBar, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V), Linear(H) или RelativeLayout.
  3. Раскрой категорию Widgets в палитре слева.
  4. Зажми SeekBar и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — ползунок появится в разметке.
  6. Тапни по нему и задай Max — например, 100.
  7. Задай Прогресс — стартовое значение, обычно 0 или 50.
  8. Присвой осмысленный ID — он нужен для логики.
  9. Открой вкладку «События» — добавь событие onProgressChanged (реакция в реальном времени) или onStopTrackingTouch (реакция при отпускании).
⚠️ Важно: обычный тап по SeekBar в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: без onProgressChanged ползунок двигается визуально, но ничего не делает. Логику нужно описывать вручную.
⚠️ Важно: Max нельзя задать меньше Progress. Если Progress = 50, а Max = 10 — значение обрежется до 10. Проверяй порядок настройки.
💡 Совет: показывай текущее значение рядом с ползунком через TextView. Пользователь не понимает, что значит «ползунок на 60%» — добавь «60%» или «60 из 100».
💡 Совет: для выбора громкости или яркости используй Progress = 50, Max = 100 — нейтральный старт. Пользователь сам решит, в какую сторону двигать.
💡 Совет: для действий, которые тяжело выполнять в реальном времени (например, отправка запроса на сервер), используй onStopTrackingTouch, а не onProgressChanged. Событие onProgressChanged срабатывает десятки раз в секунду при движении — сервер не выдержит.
❌ Частая ошибка: пытаться получить значение сразу при запуске экрана. Событие onProgressChanged не сработает, пока пользователь не тронет ползунок. Для начального значения читай свойство Progress в onCreate.
❌ Частая ошибка: забывать, что Max — это максимальное значение, а не количество шагов. Для диапазона от 0 до 5 ставь Max = 5, а не Max = 6.

Резюме

  • SeekBar — ползунок для выбора значения из диапазона.
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • Ключевые свойства: Max (максимум) и Прогресс (стартовое значение).
  • Значение читается в логике через блок getProgress.
  • Событие onProgressChanged — реакция в реальном времени; onStopTrackingTouch — при отпускании.
  • Для тяжёлых действий используй onStopTrackingTouch.
  • Показывай текущее значение рядом с ползунком через TextView.

Частые ошибки новичков

  • Тапают по SeekBar в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Не добавляют событие onProgressChanged. Ползунок двигается, но значение не считывается.
  • Задают Max меньше Progress. Значение обрезается — ползунок не сдвинуть дальше.
  • Пытаются получить значение при запуске. Событие не сработает, пока пользователь не тронет ползунок. Читай Progress в onCreate.
  • Вешают тяжёлую логику на onProgressChanged. Событие срабатывает десятки раз в секунду — сервер/приложение зависнет.
  • Не задают Max. Остаётся 100 по умолчанию — не всегда то, что нужно.
  • Не показывают текущее значение. Пользователь не понимает, что выбрал.
