Cloud Message — push-уведомления

Cloud Message — компонент для push-уведомлений через Firebase Cloud Messaging (FCM). Позволяет отправлять сообщения пользователям даже когда приложение закрыто.

Иконка в диалоге добавления — логотип Firebase.

Как работает

  • Приложение регистрируется в FCM при запуске.
  • Firebase выдаёт токен устройства — уникальный идентификатор.
  • Токен сохраняется (обычно в Firebase DB под профилем пользователя).
  • С сервера или из Firebase Console отправляется push-уведомление.
  • Уведомление приходит на устройство — даже если приложение закрыто.
  • Пользователь тапает — приложение открывается на нужном экране.

Когда использовать

  • Новости и обновления — «Вышла новая версия».
  • Напоминания — «Не забудьте про задачу».
  • Акции и скидки — «Только сегодня скидка 50%».
  • Сообщения в чате — новое сообщение от собеседника.
  • Заказы — «Ваш заказ готов».
  • События — «Началась прямая трансляция».
  • Любые уведомления с сервера.

Настройки при добавлении

Настройка Что задаёт Пример
Имя компонента Идентификатор для вызова в логике. fcm.

Основные блоки в логике

Блок Что делает
subscribeToTopic Подписаться на тему (например, «новости»).
unsubscribeFromTopic Отписаться.
getToken Получить токен устройства.

События Cloud Message

Событие Когда срабатывает
onMessageReceived Пришло сообщение в приложение (когда оно открыто).
onNewToken Firebase выдал новый токен устройства.
onNotificationOpened Пользователь тапнул по уведомлению.

Как использовать

  1. Зарегистрируйся в Firebase Console.
  2. Включи Cloud Messaging в проекте.
  3. Скачай google-services.json и подключи в Sketchware Pro 7.
  4. Подключи компонент Cloud Message на вкладке «Компонент».
  5. Задай имя — например, fcm.
  6. Добавь разрешение POST_NOTIFICATIONS для Android 13+.
  7. В onCreate — получи токен через getToken и сохрани его в Firebase DB.
  8. В категории «Компонент» добавь события:
    • onMessageReceived — обработка входящего сообщения;
    • onNewToken — сохранение обновлённого токена;
    • onNotificationOpened — обработка тапа по уведомлению.

Пример: подписка на тему

  • Пользователь включает «Новости» в настройках.
  • Вызови subscribeToTopic("news").
  • Теперь при отправке из Firebase Console в тему news — пользователь получит уведомление.

Пример: персональные push

  • При регистрации сохраняй токен пользователя в Firebase DB под его UID.
  • С сервера отправляй уведомления по конкретным токенам.

Отправка уведомлений

Способ Как
Firebase Console Cloud Messaging → «Отправить сообщение» → выбери тему или токен.
API POST-запрос на https://fcm.googleapis.com/fcm/send с ключом сервера.
Свой сервер На своём бэкенде вызови FCM API.
⚠️ Важно: для Android 13+ нужно разрешение POST_NOTIFICATIONS. Без него уведомления не показываются.
⚠️ Важно: токен устройства меняется. При onNewToken — обязательно обновляй сохранённый токен в базе. Иначе старые пользователи перестанут получать уведомления.
⚠️ Важно: не отправляй слишком много уведомлений. Пользователь отключит их или удалит приложение.
⚠️ Важно: уведомление должно быть полезным. Не отправляй «Заходите в приложение» без повода — это раздражает.
⚠️ Важно: согласие пользователя — пользователь должен иметь возможность отключить уведомления в настройках приложения. Обязательно предусмотри эту опцию.
💡 Совет: для групп пользователей используй темы (subscribeToTopic). Например, «новости», «акции», «обновления». Пользователь сам выбирает интересные темы.
💡 Совет: для персональных уведомлений используй токен конкретного устройства. Сохраняй его в Firebase DB под UID пользователя.
💡 Совет: для уведомлений по времени используй FCM вместе с расписанием на сервере. Например, отправляй каждое утро в 9:00.
💡 Совет: для открытия нужного экрана при тапе по уведомлению используй onNotificationOpened. Определи, куда перейти, по данным уведомления.
💡 Совет: для отладки используй Firebase Console → Cloud Messaging → тестовое сообщение на конкретный токен. Быстро проверяешь работу.
💡 Совет: не спамь уведомлениями — один push в день обычно достаточно. Для срочных новостей — можно чаще, но не превращай это в поток.
❌ Частая ошибка: не обновлять токен при onNewToken. Старые токены перестают работать — пользователь не получает уведомления.
❌ Частая ошибка: не запрашивать POST_NOTIFICATIONS для Android 13+. Уведомления не показываются.
❌ Частая ошибка: спамить уведомлениями. Пользователь отключает их — и все будущие сообщения пропадают.
❌ Частая ошибка: не обрабатывать тап по уведомлению. Пользователь тапает — приложение открывается на главном экране, а не на нужном.
❌ Частая ошибка: не предусмотреть отписку. Пользователь не может отключить уведомления, кроме как в системных настройках.
❌ Частая ошибка: отправлять уведомления без согласия. В некоторых странах это нарушение законов о рекламе.

Резюме

  • Cloud Message — push-уведомления через Firebase Cloud Messaging.
  • Основные блоки: subscribeToTopic, unsubscribeFromTopic, getToken.
  • Основные события: onMessageReceived, onNewToken, onNotificationOpened.
  • Требует регистрации в Firebase и файла google-services.json.
  • Нужно разрешение POST_NOTIFICATIONS для Android 13+.
  • Токен устройства меняется — обновляй при onNewToken.
  • Для групп — темы (топики), для персональных — токены.
  • Не спамь — пользователь отключит уведомления.

Частые ошибки новичков

  • Не обновляют токен. Пользователь перестаёт получать уведомления.
  • Не запрашивают POST_NOTIFICATIONS. Уведомления не показываются на Android 13+.
  • Спамят уведомлениями. Пользователь отключает их.
  • Не обрабатывают onNotificationOpened. Открывается не тот экран.
  • Не предусматривают отписку. Пользователь не может отказаться.
  • Отправляют без согласия. Нарушение законов о рекламе.
  • Не используют темы. Не могут эффективно группировать подписчиков.
