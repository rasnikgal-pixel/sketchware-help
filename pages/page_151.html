Firebase DB — облачная база данных

Firebase DB — облачная база данных в реальном времени. Данные хранятся в JSON-дереве и синхронизируются между всеми устройствами мгновенно: изменение на одном — сразу видно на других.

Иконка в диалоге добавления — логотип Firebase.

Как работает

  • Хранит данные в облаке в виде структуры «ключ — значение».
  • Синхронизируется в реальном времени — как чат: изменения появляются у всех пользователей мгновенно.
  • Работает без своего сервера — Google всё берёт на себя.
  • Поддерживает оффлайн — данные сохраняются локально и синхронизируются при подключении.
  • Событие onDataChange срабатывает при каждом изменении данных.

Когда использовать

  • Чаты и мессенджеры — сообщения между пользователями.
  • Списки задач — синхронизация между устройствами.
  • Совместная работа — редактирование одного документа.
  • Приложения-заметки — облачное хранение.
  • Игры — таблица лидеров, рейтинг.
  • Дашборды — данные обновляются в реальном времени.
  • Любое приложение, где данные должны быть в облаке.

Настройки при добавлении

Настройка Что задаёт Пример
Имя компонента Идентификатор для вызова в логике. firebaseDB, db.
URL базы Адрес проекта в Firebase. https://myapp.firebaseio.com.
Путь Где именно в дереве хранятся данные. /users, /tasks.

Основные блоки в логике

Блок Что делает
setValue Записать значение по пути.
updateChildren Обновить несколько полей сразу.
push Добавить запись с уникальным ключом.
removeValue Удалить запись.
addValueEventListener Слушать изменения.
addListenerForSingleValueEvent Прочитать один раз.

События Firebase DB

Событие Когда срабатывает
onDataChange Данные изменились или получены.
onCancelled Ошибка чтения или записи.

Как использовать

  1. Зарегистрируйся в Firebase Console (console.firebase.google.com).
  2. Создай проект и добавь Realtime Database.
  3. Скачай google-services.json и подключи его в Sketchware Pro 7.
  4. Добавь разрешение INTERNET.
  5. Подключи компонент Firebase DB на вкладке «Компонент».
  6. Задай имя — например, db.
  7. В логике:
    • для сохранения — setValue по пути /users/Иван;
    • для чтения — addValueEventListener по пути;
    • в onDataChange — обрабатывай полученные данные.
  8. Настрой правила безопасности в Firebase Console — без них база открыта всем.

Пример: список задач

  • Кнопка «Добавить» → push в /tasks с новым значением.
  • ListView → addValueEventListener на /tasks.
  • В onDataChange — получи список задач и заполни ListView.
  • Задачи синхронизируются между всеми устройствами.
⚠️ Важно: правила безопасности — критично. По умолчанию база открыта всем. Настрой правила: разреши доступ только авторизованным пользователям.
⚠️ Важно: данные хранятся как дерево. Продумай структуру заранее. Глубокая вложенность замедляет работу.
⚠️ Важно: не храни в базе пароли и секреты. Для авторизации — Firebase Auth. Для чувствительных данных — шифрование.
⚠️ Важно: событие onDataChange срабатывает многократно — на каждое изменение. Логика внутри должна быть быстрой, иначе приложение тормозит.
⚠️ Важно: лимиты Firebase. Бесплатно — 1 ГБ хранилища, 10 ГБ трафика в месяц. При превышении — платно. Следи за用量.
💡 Совет: для структуры данных используй короткие пути: /users/{uid}, /tasks/{taskId}. Не делай глубокую вложенность.
💡 Совет: для оффлайн-режима включи setPersistenceEnabled = true. Данные будут доступны без интернета и синхронизируются при подключении.
💡 Совет: для больших списков используй FirebaseRecyclerAdapter — он оптимизирован для работы с базой.
💡 Совет: для поиска храни данные в структурированном виде. Например, по индексам — по имени, дате, категории. Прямой поиск по всей базе медленный.
💡 Совет: для отладки используй Firebase Console — там видно всё дерево данных в реальном времени. Удобно проверять, что записалось.
💡 Совет: не пиши всё в один узел. Например, /tasks — список, /users — пользователи, /settings — настройки. Так проще.
❌ Частая ошибка: не настроить правила безопасности. База открыта всем — любой может читать и писать.
❌ Частая ошибка: неправильная структура данных. Всё в один узел — сложно искать, медленно работает.
❌ Частая ошибка: хранить пароли в базе. Для авторизации — Firebase Auth.
❌ Частая ошибка: превысить бесплатный лимит. Следи за用量 в Firebase Console.
❌ Частая ошибка: не обрабатывать onCancelled. При ошибке чтения/записи приложение молчит.
❌ Частая ошибка: ожидать мгновенной синхронизации при плохой сети. Данные появятся, когда установится соединение.

Резюме

  • Firebase DB — облачная база данных в реальном времени.
  • Данные синхронизируются между устройствами мгновенно.
  • Основные блоки: setValue, updateChildren, push, removeValue, addValueEventListener, addListenerForSingleValueEvent.
  • Основные события: onDataChange, onCancelled.
  • Требует регистрации в Firebase и файла google-services.json.
  • Правила безопасности — критичны. Без них база открыта всем.
  • Не храни пароли — для этого Firebase Auth.
  • Следи за лимитами — бесплатно только до определённого объёма.

Частые ошибки новичков

  • Не настраивают правила безопасности. База открыта всем.
  • Неправильная структура данных. Всё в один узел.
  • Хранят пароли в базе. Грубая ошибка безопасности.
  • Превышают бесплатный лимит. Начинают платить.
  • Не обрабатывают onCancelled. Ошибки не видны.
  • Ждут мгновенной синхронизации при плохой сети. Данные приходят с задержкой.
  • Тяжёлая логика в onDataChange. Приложение тормозит при каждом изменении.
