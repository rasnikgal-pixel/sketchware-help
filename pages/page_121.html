Компоненты

Компоненты — это вкладка проекта, где подключаются невидимые сервисы приложения: работа с сетью, базой данных, камерой, звуком, уведомлениями, рекламой, Firebase. В отличие от виджетов, компоненты не отображаются на экране — они работают в фоне и обеспечивают функционал.

Дизайнер отвечает за внешний вид, логика — за действия, а компоненты — за возможности. Хочешь работать с интернетом — подключай RequestNetwork. Хочешь сохранять настройки — SharedPreferences. Хочешь показывать рекламу — InterstitialAd.

Из чего состоит вкладка «Компонент»

Элемент Что делает
Пустой экран На старте на вкладке нет ни одного компонента.
Надпись «Нет компонентов для отображения» Если компонентов ещё нет.
Кнопка «+» в правом нижнем углу Открывает диалог добавления компонента.
Сетка компонентов После добавления каждый компонент появляется в виде плитки с иконкой и именем.
Раскрывающаяся стрелка ∨ на каждом компоненте Открывает пункт «Удалить компонент».

Из чего состоит диалог добавления

  • Сетка иконок — все доступные компоненты, сгруппированные по назначению.
  • Категории компонентов:
    • Основные — 20+ компонентов: Intent, SharedPreferences, FilePicker, Calendar, Vibrator, Timer, Dialog, MediaPlayer, SoundPool, ObjectAnimator, Camera, Gyroscope, TextToSpeech, SpeechToText, RequestNetwork, BluetoothConnect, LocationManager, ProgressDialog, DatePickerDialog, TimePickerDialog, Notification, FragmentAdapter.
    • Реклама — 2 компонента: InterstitialAd, RewardedVideoAd.
    • Firebase — 6 компонентов: Firebase DB, Firebase Auth, Firebase Storage, PhoneAuth, Cloud Message, Google Login.
    • Другое — 1 компонент: AsyncTask.

Что важно понимать

  • Компонент подключается один раз на проект или на экран — в зависимости от типа. Например, SharedPreferences — общий для всего приложения, а RequestNetwork — отдельный экземпляр для каждого запроса.
  • Каждому компоненту даётся имя (идентификатор) — по нему он вызывается в логике.
  • После подключения компонента в логике появляются новые блоки, связанные с ним. В шапке всплывает сообщение: «В редакторе логики добавлены новые блоки».
  • Компонент не работает сам по себе — его нужно вызывать через блоки в событиях.

Что можно делать с компонентами

Действие Как сделать
Удалить Тап по стрелке ∨ → «Удалить компонент».
Переименовать Только через удаление и повторное добавление с новым именем.
Настроить Некоторые компоненты имеют параметры, задаваемые при добавлении или в логике.
Использовать в логике Через блоки, появляющиеся в палитре.

Что будет разобрано

  • Что такое компонент — базовое понятие и назначение.
  • Чем отличается от виджета — ключевое различие.
  • Категория «Основные» — 20+ компонентов базового набора.
  • Категория «Реклама» — 2 рекламных компонента.
  • Категория «Firebase» — 6 компонентов облачных сервисов.
  • Категория «Другое» — компонент AsyncTask.
  • Удаление компонента — как убрать компонент из проекта.
💡 Совет: после прохождения раздела ты научишься подключать компоненты, использовать их в логике и понимать, какие возможности даёт каждый из них. Без компонентов приложение остаётся «игрушкой» — с ними оно становится полноценным инструментом.

Резюме

  • Компоненты — вкладка для подключения невидимых сервисов приложения.
  • Компоненты не отображаются на экране — они работают в фоне.
  • На вкладке: пустой экран, кнопка «+» для добавления, сетка добавленных компонентов.
  • Категории в диалоге добавления: Основные, Реклама, Firebase, Другое.
  • После добавления компонент появляется в логике новыми блоками.
  • Компонент нужно вызывать в событиях — сам он не работает.
  • Удалить компонент — через стрелку ∨ → «Удалить компонент».
  • Дизайнер — внешний вид; Логика — действия; Компоненты — возможности.

Частые ошибки новичков

  • Ожидают, что компонент сам что-то сделает. Его нужно вызывать в логике.
  • Путают компоненты с виджетами. Компоненты не видны на экране.
  • Не замечают, что после подключения компонента появляются новые блоки. Не используют их.
  • Пытаются переименовать компонент без удаления. Так нельзя — удалить и создать заново.
  • Добавляют все компоненты «про запас». Утяжеляют APK.
  • Не читают сообщение «В редакторе логики добавлены новые блоки». Пропускают важное уведомление.
  • Не понимают, что RequestNetwork — отдельный компонент на каждый запрос. Работают с одним и удивляются, что не срабатывает.
