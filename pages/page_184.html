Менеджер коллекций

Менеджер коллекций — раздел меню «Настройка», где хранятся сохранённые коллекции блоков и фрагментов логики. Это «личная библиотека» готовых решений, которые можно использовать в разных проектах.

Иконка в меню — стопка карточек или папка с закладками.

Что такое коллекции

  • Сохранённые фрагменты логики — блоки, которые часто используются.
  • Готовые шаблоны — например, «показать диалог подтверждения», «отправить запрос к API».
  • Наборы блоков для повторяющихся задач.
  • Личная библиотека — как у программистов есть свои сниппеты.

Что можно сохранять

  • Группы блоков — например, обработка формы входа.
  • События целиком — например, готовый onClick для кнопки.
  • Фрагменты с параметрами — с возможностью подстановки значений.
  • Свои More Block — пользовательские блоки.

Зачем это нужно

  • Экономия времени — не собирать одно и то же заново.
  • Единый стиль — одинаковые решения во всех проектах.
  • Обмен опытом — делиться коллекциями с другими.
  • Сохранение удачных решений — если блок сработал хорошо, сохрани его.
  • Обучение — примеры логики для будущих проектов.

Как открыть

  • Открой меню ⋮ → Менеджер коллекций.
  • Откроется список твоих сохранённых коллекций.
  • Тапни по коллекции — просмотр содержимого.
  • Используй контекстное меню для импорта, экспорта, удаления.

Как сохранить коллекцию

  • Открой событие в логике, где есть нужные блоки.
  • Выдели фрагмент (или всё событие).
  • Используй опцию «Сохранить в коллекцию».
  • Дай название — понятное, чтобы потом найти.
  • Нажми «Сохранить».
  • Коллекция появится в Менеджере коллекций.

Как использовать коллекцию

  • Открой Менеджер коллекций.
  • Найди нужную.
  • Тапни — откроется содержимое.
  • Используй опцию «Вставить» в текущий проект.
  • Или импортируй в другой проект.

Примеры полезных коллекций

  • Диалог подтверждения — Dialog + обработка кнопок.
  • Запрос к API — RequestNetwork + onResponse + парсинг JSON.
  • Сохранение в SharedPreferences — запись и чтение.
  • Проверка интернета — есть ли соединение.
  • Отправка email — через Intent.
  • Открытие ссылки — через Intent.ACTION_VIEW.
  • Смена языка — стандартный шаблон.
  • Показ уведомления — Notification + канал.

⚠️ Важно: коллекции сохраняются в Sketchware, а не в проекте. Они доступны во всех проектах приложения.

⚠️ Важно: при удалении Sketchware коллекции могут пропасть. Регулярно делай резервные копии или экспорт.

⚠️ Важно: не все блоки сохраняются корректно. Если в коллекции есть ссылка на конкретный виджет (button1), в другом проекте она может не сработать.

⚠️ Важно: импорт коллекций может требовать настройки. Виджеты и компоненты в новом проекте имеют другие id.

💡 Совет: создай несколько коллекций для разных задач: «Диалоги», «Сеть», «Firebase», «Уведомления». Так проще искать.

💡 Совет: давай понятные имена коллекциям. «Запрос к API погоды» лучше, чем «Коллекция 1».

💡 Совет: экспортируй коллекции в файл — на случай переустановки Sketchware. Обычно есть опция «Экспорт».

💡 Совет: делись коллекциями с другими разработчиками. Это ускоряет работу и помогает учиться.

💡 Совет: проверяй коллекцию перед вставкой. Убедись, что все виджеты и компоненты есть в новом проекте.

💡 Совет: не храни в коллекции ничего связанного с конкретным проектом (например, ID Firebase). Такие данные лучше вставлять вручную.

💡 Совет: регулярно обновляй коллекции. Если нашёл лучшее решение — сохрани его, старую версию удали.

❌ Частая ошибка: не использовать коллекции. Собираешь одно и то же в каждом проекте.

❌ Частая ошибка: хранить всё в одной коллекции. Сложно найти нужное.

❌ Частая ошибка: использовать непонятные имена. «Коллекция 1», «Коллекция 2» — неудобно.

❌ Частая ошибка: не делать резервные копии. При переустановке Sketchware коллекции пропадают.

❌ Частая ошибка: вставлять коллекцию без проверки. Виджеты могут отсутствовать, логика сломается.

❌ Частая ошибка: хранить в коллекции ID конкретных проектов (Firebase, AdMob). В новом проекте они не сработают.
