RelativeLayout — относительный макет

RelativeLayout — макет относительного позиционирования. Каждый дочерний элемент внутри него привязывается к другим элементам или к краям контейнера. Это самый гибкий, но и самый сложный контейнер в Sketchware.

Иконка в палитре — прямоугольник с квадратом в центре.

Как работает

  • Внутри RelativeLayout нет автоматического порядка. Виджеты не выстраиваются «в столбик» или «в строку».
  • Положение каждого виджета задаётся правилами привязки — относительно родителя или относительно другого виджета.
  • Если правил нет — виджет оказывается в левом верхнем углу контейнера.
  • Несколько виджетов без правил накладываются друг на друга.

Основные правила привязки

  • alignParentTop — прижать к верхнему краю контейнера.
  • alignParentBottom — прижать к нижнему краю.
  • alignParentLeft / alignParentStart — к левому краю.
  • alignParentRight / alignParentEnd — к правому краю.
  • centerInParent — по центру контейнера.
  • centerHorizontal — по центру по горизонтали.
  • centerVertical — по центру по вертикали.
  • above / below — над или под указанным виджетом.
  • toLeftOf / toRightOf — слева или справа от указанного виджета.
  • alignTop / alignBottom / alignLeft / alignRight — выравнивание относительно другого виджета.

Комбинируя правила, можно строить сложные вёрстки: шапка с кнопкой справа, картинка слева с текстом справа, кнопка внизу по центру.

Когда использовать

  • Шапка экрана — заголовок по центру, кнопка справа, стрелка назад слева.
  • Карточка — изображение слева, текст справа, дата в углу.
  • Экран с кнопкой внизу — контент сверху, кнопка прижата к нижнему краю.
  • Сложные формы — когда Linear(V) и Linear(H) не справляются.
  • Наложение элементов — текст поверх картинки, значок в углу аватара.

Как перетащить RelativeLayout на макет

  1. Открой вкладку «Дизайнер».
  2. Раскрой категорию Layouts в палитре слева.
  3. Зажми RelativeLayout и, не отпуская, перетащи его на макет.
  4. Отпусти в нужном месте — контейнер появится в разметке.
  5. Перетаскивай внутрь нужные виджеты (TextView, Button, ImageView и другие).
  6. Тапни по каждому виджету и в панели свойств задай правила привязки: alignParentTop, centerInParent, below, toRightOf и другие.
⚠️ Важно: обычный тап по RelativeLayout в палитре ничего не делает. Контейнер попадает на макет только перетаскиванием. То же правило — для виджетов внутри него.

Свойства контейнера

Открой панель свойств, тапнув по контейнеру в рабочей области. Ниже — все свойства с описанием. Значения указаны в том виде, в каком они отображаются в Sketchware Pro 7 (на скриншоте пример ID — relativelayout2).

Основные

Свойство (рус / англ) Что делает Значения Пример
ID Уникальное имя контейнера. По этому имени контейнер виден на вкладке «События» и в блоках логики. Любая строка без пробелов. По умолчанию — relativelayout1, relativelayout2 и т. д. Переименуй в headerBar, если это шапка экрана.
Пользовательские атрибуты Дополнительные XML-атрибуты, которые можно задать вручную. Нужны опытным пользователям. Пары «атрибут = значение». Например, android:background="#FFFFFF".
Конвертировать Превратить этот контейнер в другой тип макета (например, в LinearLayout). RelativeLayout, LinearLayout и другие. Если вёрстка стала проще — переключи на LinearLayout.

Свойства макета

Свойство (рус / англ) Что делает Значения Пример
Ширина
Width		 Насколько широким будет контейнер по горизонтали. match_parent — на всю ширину родителя;
wrap_content — по содержимому;
число в dp.		 match_parent, чтобы контейнер занял всю ширину экрана.
Высота
Height		 Насколько высоким будет контейнер по вертикали. match_parent, wrap_content, число в dp. wrap_content — высота подстроится под содержимое.
Внутренний отступ
Padding		 Отступ внутри контейнера — от его краёв до содержимого. Формат: «осталось: N, top: N, right: N, bottom: N». Числа в dp для каждой стороны: left («осталось»), top, right, bottom. Padding 16 со всех сторон — содержимое не липнет к краям.
Внешний отступ
Margin		 Отступ снаружи контейнера — от него до соседних элементов и краёв родителя. Числа в dp для каждой стороны: left («осталось»), top, right, bottom. Margin bottom 8 — контейнер сдвинется на 8 dp вверх от нижнего элемента.
Гравитация макета
Layout gravity		 Как контейнер выравнивается внутри родителя: по левому краю, центру, правому и т. п. none — по умолчанию;
например, center, center_horizontal, right.		 center — контейнер встанет по центру родителя.
Вес
Weight		 Доля свободного места родителя, которую займёт этот контейнер. Работает только внутри родителя с весом. Число. 0 — вес не задан. 1 — контейнер заберёт всё оставшееся место в родителе.

Свойство (рус / англ) Что делает Значения Пример
Ресурс фона
Background resource		 Картинка-фон контейнера из ресурсов проекта. NONE — без фона;
любой drawable-ресурс.		 Установи NONE, если фон не нужен.
Цвет фона
Background color		 Заливка контейнера сплошным цветом. NONE — без цвета;
HEX или выбор из палитры (например, #FFFFFF).		 Белый фон для шапки — #FFFFFF.
Enabled
Включено		 Реагирует ли контейнер и его содержимое на нажатия и тапы. Переключатель: вкл — активен;
выкл — заблокирован.		 Выключи, если нужно показать шапку, но запретить нажатия.
Вращение
Rotation		 Поворот контейнера вокруг центра. Градусы. 0 — без поворота. 90 — контейнер развернётся на 90°.
Прозрачность
Alpha		 Насколько контейнер и его содержимое прозрачны. Число от 0.0 (полностью прозрачный) до 1.0 (полностью непрозрачный). 0.5 — половина прозрачности.
TranslationX Сдвиг контейнера по горизонтали без изменения его места в разметке (визуальный сдвиг). Число в dp. 0.0 — без сдвига. 20.0 — контейнер визуально сдвинется на 20 dp вправо.
TranslationY Сдвиг контейнера по вертикали без изменения его места в разметке. Число в dp. 0.0 — без сдвига. -10.0 — визуально поднимется на 10 dp.
ScaleX Масштаб по горизонтали — растягивает или сжимает контейнер по ширине. Число. 1.0 — исходный размер. 1.5 — ширина увеличится в 1,5 раза.
ScaleY Масштаб по вертикали — растягивает или сжимает контейнер по высоте. Число. 1.0 — исходный размер. 0.5 — высота уменьшится вдвое.
💡 Совет для новичков: свойства самого RelativeLayout — обычные. Главное — не они, а правила привязки у дочерних виджетов. Именно их задают в свойствах каждого виджета внутри контейнера.

Практический пример: шапка экрана

  1. Перетащи на макет Linear(V) — он будет корневым.
  2. Внутрь перетащи RelativeLayout — это будет шапка.
  3. Внутрь шапки перетащи ImageView — это будет стрелка назад.
  4. Тапни по ImageView и задай правило alignParentLeft (и centerVertical, если нужно по центру по вертикали).
  5. Перетащи внутрь шапки TextView с заголовком.
  6. Тапни по TextView и задай правило centerInParent — заголовок встанет по центру.
  7. Перетащи внутрь шапки Button — например, «Готово».
  8. Тапни по Button и задай правила alignParentRight + centerVertical.

Готово: стрелка слева, заголовок по центру, кнопка справа — всё в одной строке.

⚠️ Важно: без правил привязки все виджеты окажутся в левом верхнем углу и наложатся друг на друга. Это самая частая причина «пропавших» элементов в RelativeLayout. Проверь свойства каждого дочернего виджета.
⚠️ Важно: ссылаться можно только на виджеты, которые уже добавлены в разметку. Если указать below="@id/button1", а button1 ещё нет — сборка выдаст ошибку.
💡 Совет: используй RelativeLayout только тогда, когда понимаешь, зачем он нужен. Для 90% экранов достаточно вложенных Linear(V) и Linear(H). Они проще и предсказуемее.
💡 Совет: не смешивай wrap_content и правила привязки к обоим краям (alignParentLeft + alignParentRight) — виджет растянется на всю ширину контейнера, что не всегда ожидаемо.

Резюме

  • RelativeLayout — контейнер, где каждый виджет привязывается к другим виджетам или краям родителя.
  • Перетаскивается на макет так же, как любой другой виджет — перетаскиванием, а не тапом.
  • Внутри нет автоматического порядка — положение задаётся правилами привязки у каждого дочернего виджета.
  • Главные правила: alignParentTop / Bottom / Left / Right, centerInParent, below, above, toLeftOf, toRightOf.
  • Без правил виджеты слипаются в левом верхнем углу.
  • Дополнительное свойство изображения — Enabled: включает и выключает реакцию контейнера на тапы.
  • Используй для сложной вёрстки: шапки, карточки, наложения элементов. Для простых экранов хватит Linear.

Частые ошибки новичков

  • Тапают по RelativeLayout в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Перетаскивают внутрь виджеты без правил привязки. Все слипаются в левом верхнем углу.
  • Ссылаются на несуществующий id. below="@id/button1" при отсутствии button1 — ошибка сборки.
  • Комбинируют alignParentLeft + alignParentRight у одного виджета с wrap_content — виджет растягивается на всю ширину.
  • Используют RelativeLayout там, где хватило бы Linear(V). Вёрстка запутывается в привязках.
  • Задают правила в неправильном порядке. Сначала перетаскивают виджет-якорь, потом тот, что ссылается на него. Иначе ссылаться не на что.
