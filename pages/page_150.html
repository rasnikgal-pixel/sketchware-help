Категория «Firebase»

Firebase — третья категория в диалоге добавления компонентов. Здесь собраны облачные сервисы Google: база данных, авторизация, хранилище файлов, push-уведомления. Firebase позволяет строить приложения с синхронизацией данных между устройствами и облачными функциями.

Это самая мощная категория компонентов. Она превращает локальное приложение в сетевое — с общим доступом к данным, авторизацией пользователей, облачным хранением.

Из чего состоит категория

В категории Firebase шесть компонентов:

  • Firebase DB — облачная база данных в реальном времени. Данные синхронизируются между всеми устройствами мгновенно.
  • Firebase Auth — авторизация пользователей по email и паролю. Регистрация, вход, восстановление пароля.
  • Firebase Storage — облачное хранилище файлов. Картинки, документы, видео — в облаке.
  • PhoneAuth — авторизация по номеру телефона. Код приходит по SMS.
  • Cloud Message — push-уведомления. Сообщения приходят даже когда приложение закрыто.
  • Google Login — вход через аккаунт Google. Один тап — и пользователь авторизован.

Зачем нужен Firebase

  • Облачная база данных — данные доступны с любого устройства.
  • Авторизация — не нужно писать свой сервер для логина и регистрации.
  • Хранилище файлов — можно загружать и хранить файлы без своего сервера.
  • Push-уведомления — отправка сообщений пользователям удалённо.
  • Общий доступ к данным — несколько пользователей видят одни и те же записи.
  • Синхронизация — изменения на одном устройстве сразу видны на других.

Что важно понимать

  • Firebase требует регистрации в консоли Firebase (console.firebase.google.com).
  • Нужен файл google-services.json — без него Firebase не подключается.
  • У каждого компонента — свой API-ключ и настройки в консоли.
  • Firebase — бесплатен для небольших проектов, но есть лимиты. За превышение — платно.
  • Правила безопасности — критически важны. По умолчанию база данных открыта — любой может читать и писать. Настрой правила доступа.

⚠️ Важно: без регистрации в Firebase компоненты не работают. Приложение соберётся, но данные не будут синхронизироваться.

⚠️ Важно: правила безопасности — критичны. Открытая база данных = утечка данных пользователей. Настрой правила до публикации.

⚠️ Важно: Firebase не работает без интернета. Приложение должно корректно обрабатывать потерю сети — показывать сообщение, кэшировать данные.

💡 Совет: для первого проекта начни с Firebase Auth + Firebase DB. Это основа: пользователь входит, данные сохраняются в облаке.

💡 Совет: используй Firebase Storage для картинок и файлов, а Firebase DB — для текстовых данных и структур. Так экономишь трафик и место.

💡 Совет: не храни пароли в Firebase DB. Для паролей — только Firebase Auth. Он хеширует и защищает данные.

❌ Частая ошибка: забыть про правила безопасности. База данных открыта — любой может её читать и писать. Утечка данных и потенциальный бан.

❌ Частая ошибка: не регистрировать приложение в Firebase. Без google-services.json компоненты не работают.

❌ Частая ошибка: хранить пароли в Firebase DB. Это грубейшее нарушение безопасности.

❌ Частая ошибка: превышать бесплатный лимит без мониторинга. Firebase бесплатен до определённых объёмов, дальше — платно.
