Что такое компонент

Компонент — это невидимый сервис в приложении, который обеспечивает функционал: работу с сетью, базой данных, камерой, звуком, уведомлениями, рекламой, Firebase. Компоненты не отображаются на экране и не имеют визуального представления — но именно они дают приложению реальные возможности.

Простой пример: у тебя есть TextView и Button. Пользователь вводит текст, нажимает кнопку — и текст должен сохраниться, чтобы при следующем запуске он был на месте. Для этого нужен компонент SharedPreferences. Виджеты показывают, компонент запоминает.

Где живут компоненты

  • На вкладке «Компонент» — здесь ты подключаешь нужные сервисы.
  • В логике — через блоки, которые появляются после подключения.
  • В фоне — в момент работы приложения, без участия пользователя.

Чем компонент отличается от виджета

Свойство Виджет Компонент
Видимость Виден на экране (TextView, Button, ImageView). Невидим (RequestNetwork, Camera, SharedPreferences).
Как добавляется На вкладке «Дизайнер» через перетаскивание. На вкладке «Компонент» через кнопку «+».
Работа Пользователь взаимодействует напрямую. Работает в фоне, управляется логикой.

Какие задачи решают компоненты

Задача Компонент
Работа с интернетом RequestNetwork отправляет запросы к серверу.
Хранение данных SharedPreferences — локально; Firebase DB — в облаке.
Работа с устройством Camera, Vibrator, LocationManager, TextToSpeech.
Медиа MediaPlayer, SoundPool для звуков и музыки.
Уведомления Notification показывает системные уведомления.
Диалоги Dialog, ProgressDialog, DatePickerDialog, TimePickerDialog.
Реклама InterstitialAd, RewardedVideoAd для монетизации.
Firebase Авторизация, база данных, хранилище, push-уведомления.

Как работает компонент

  • Подключается на вкладке «Компонент» через кнопку «+».
  • Получает имя — идентификатор, по которому вызывается в логике.
  • В логике появляются специальные блоки для работы с этим компонентом.
  • В событиях ты вызываешь блоки — компонент выполняет действие.
  • Некоторые компоненты также имеют свои события (например, onResponse у RequestNetwork).

Простой пример

Задача: сохранить текст из EditText при нажатии кнопки — и восстановить его при следующем запуске.

  • Компонент: SharedPreferences — хранилище данных.
  • Виджеты: EditText, Button.
  • Логика:
    • в onCreate — читаем сохранённое значение и ставим его в EditText;
    • в onClick кнопки — читаем текст из EditText и сохраняем в SharedPreferences.

Так простой компонент превращает приложение в инструмент, который помнит данные между запусками.

⚠️ Важно: компонент не работает сам по себе. Без вызова в логике он просто «висит» в проекте и ничего не делает.
⚠️ Важно: каждому компоненту даётся уникальное имя (идентификатор). Если в проекте два RequestNetwork, они должны иметь разные имена.
⚠️ Важно: при удалении компонента все блоки, связанные с ним, тоже удаляются из логики. Это может сломать события, где использовался этот компонент.
💡 Совет: подключай компоненты по мере необходимости. Не добавляй все сразу «на всякий случай» — это создаёт мусор в проекте и увеличивает APK.
💡 Совет: давай компонентам понятные имена: prefs (для SharedPreferences), weatherRequest (для сетевого запроса), myTimer (для таймера). Тогда в логике легче ориентироваться.
💡 Совет: изучай компоненты по одному. Начни с SharedPreferences и RequestNetwork — они используются в 90% проектов.
💡 Совет: перед добавлением компонента посмотри его описание в диалоге. Там указано, что компонент делает и какие даёт возможности.
❌ Частая ошибка: добавлять компонент и не использовать его в логике. Лишний компонент — лишний вес APK без пользы.
❌ Частая ошибка: удалять компонент, не проверив, где он используется. Связанные блоки в логике тоже удалятся, и приложение может «сломаться».
❌ Частая ошибка: путать виджет и компонент. TextView — виджет, SharedPreferences — компонент. Они добавляются в разных вкладках.
❌ Частая ошибка: думать, что компонент работает автоматически. Компонент — это инструмент, которым управляет логика.

Резюме

  • Компонент — невидимый сервис приложения, обеспечивающий функционал.
  • Компоненты не отображаются на экране — но дают приложению реальные возможности.
  • Подключаются на вкладке «Компонент» через кнопку «+».
  • Получают уникальное имя, по которому вызываются в логике.
  • После подключения в палитре логики появляются новые блоки.
  • Компонент не работает сам — вызывай его через блоки в событиях.
  • Основные задачи компонентов: сеть, хранение данных, камера, звук, уведомления, реклама, Firebase.
  • Ключевое отличие от виджета: виджет виден, компонент работает в фоне.

Частые ошибки новичков

  • Добавляют компонент и не используют. Мусор в проекте.
  • Удаляют компонент, не проверив логику. Ломают связанные события.
  • Путают виджет и компонент. Добавляют в разных вкладках.
  • Ждут, что компонент работает сам. Нужно вызывать через блоки.
  • Дают компонентам нечёткие имена. Потом сложно найти нужный.
  • Используют одинаковые имена для двух одинаковых компонентов. Sketchware их путает.
  • Забывают, что при удалении компонента пропадают его блоки. Логика ломается.
