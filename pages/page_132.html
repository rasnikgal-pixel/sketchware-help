MediaPlayer — проигрывание аудио

MediaPlayer — компонент для воспроизведения аудио и видео. Работает с музыкой, звуками, аудиофайлами и видео. Управляет воспроизведением: play, pause, stop, seek, loop.

Иконка в диалоге добавления — плёнка или плеер.

Как работает

  • Воспроизводит аудио и видео из разных источников: файл в памяти, ресурс приложения, сеть.
  • Может играть один раз или в цикле (loop).
  • Позволяет ставить на паузу, продолжать, останавливать воспроизведение.
  • Позволяет перемотать на нужную позицию (в миллисекундах).
  • Может менять громкость.
  • При завершении воспроизведения срабатывает событие onCompletion.

Когда использовать

  • Музыкальный плеер — воспроизведение треков.
  • Звуковое сопровождение игры — фоновая музыка.
  • Уведомления — звук при событии.
  • Обучающие приложения — озвученные уроки.
  • Медитационные приложения — фоновые звуки.
  • Аудиокниги — с управлением позицией.
  • Видеоплеер — воспроизведение видеофайлов.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова. Например, musicPlayer.

Основные блоки в логике

  • setSource / setDataSource — задать источник (путь или URL).
  • prepare — подготовить воспроизведение.
  • start — начать воспроизведение.
  • pause — пауза.
  • stop — остановить и сбросить.
  • reset — вернуть в исходное состояние.
  • release — освободить ресурсы (когда плеер больше не нужен).
  • seekTo — перемотать к позиции (мс).
  • setLooping — включить/выключить повтор.
  • setVolume — задать громкость.
  • getDuration — получить длительность трека.
  • getCurrentPosition — получить текущую позицию.
  • isPlaying — проверить, играет ли сейчас.

События MediaPlayer

  • onPrepared — плеер готов к воспроизведению.
  • onCompletion — воспроизведение завершено.
  • onError — ошибка воспроизведения.
  • onBufferingUpdate — обновление буфера (при потоке из сети).

Как использовать

  • Подключи компонент MediaPlayer на вкладке «Компонент».
  • Задай имя — например, player.
  • Загрузка локального файла:
    • скопируй файл в res/raw через Менеджер ресурсов;
    • используй блок setSource с указанием raw и имени файла.
  • Загрузка из сети:
    • используй setSource с URL;
    • требуется разрешение INTERNET.
  • В категории «Компонент» добавь событие onPrepared — только там можно начинать воспроизведение.
  • Вызови start для запуска.

Пример: воспроизведение трека

  • В onCreate вызови setSource и prepare.
  • В onPrepared вызови start.
  • В onClick кнопки «Пауза» — pause.
  • В onClick кнопки «Стоп» — stop.
  • В onCompletion — покажи сообщение или перезапусти трек.

⚠️ Важно: start нельзя вызвать до onPrepared. Иначе воспроизведение не начнётся или приложение упадёт. Всегда дожидайся готовности.

⚠️ Важно: не забывай про release при уходе с экрана. Без освобождения ресурсов воспроизведение может продолжаться в фоне и расходовать батарею.

⚠️ Важно: для воспроизведения из интернета нужно разрешение INTERNET в Менеджере разрешений.

⚠️ Важно: одновременное воспроизведение через несколько MediaPlayer может вызвать конфликты. Обычно для коротких звуков используется SoundPool, а MediaPlayer — для длинных треков.

💡 Совет: для фоновой музыки устанавливай setLooping = true. Так трек будет играть по кругу без остановки.

💡 Совет: для коротких звуков (клик, всплеск) используй SoundPool — он быстрее и легче для коротких эффектов.

💡 Совет: останавливай воспроизведение в onPause или onStop. Иначе музыка продолжит играть, когда пользователь ушёл с экрана.

💡 Совет: для прогресса воспроизведения используй Timer + блок getCurrentPosition. Обновляй SeekBar каждую секунду.

💡 Совет: для выбора трека используй FilePicker или ListView с треками. Не зашивай путь в код — дай пользователю выбрать.

❌ Частая ошибка: вызывать start до onPrepared. Воспроизведение не начнётся, возможна ошибка.

❌ Частая ошибка: не освобождать ресурсы при выходе с экрана. Плеер продолжает работать в фоне.

❌ Частая ошибка: использовать MediaPlayer для коротких звуков. Для этого лучше SoundPool.

❌ Частая ошибка: забыть про разрешение INTERNET для потокового аудио. Плеер не запустится.

❌ Частая ошибка: не обрабатывать onError. При ошибке плеер молчит, а пользователь не понимает, что произошло.
