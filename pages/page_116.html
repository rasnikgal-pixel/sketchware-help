More Block

Свой блок — пятая, последняя категория в левом меню вкладки «События». Здесь собраны пользовательские блоки, созданные вручную. В английской версии Sketchware они называются More Block — отсюда и второе название.

Пользовательский блок — это набор команд, сохранённый под своим именем. Если в логике часто повторяется одна и та же последовательность блоков, её можно собрать один раз в свой блок и вызывать по имени. Это экономит время и упрощает структуру проекта.

Что такое свой блок

  • Своя команда с собственным именем, которую можно вызывать из любого события.
  • Обёртка для часто повторяющейся логики.
  • Аналог функции в обычном программировании.
  • Может принимать параметры — значения, которые передаются при вызове.
  • Может возвращать значение — результат выполнения.

Когда использовать

  • Повторяющаяся логика — например, показать сообщение об ошибке в разных событиях.
  • Сложные вычисления — вынести в отдельный блок для чистоты.
  • Группировка действий — например, «сохранить данные», «загрузить настройки».
  • Многократные проверки — «валидация формы», «проверка соединения».

Форма создания блока

Поле Что задаёт Значения / ограничения
Имя блока Название, под которым блок появится в палитре. До 60 символов. Должно быть уникальным.
Тип блока (Moreblock type) Что блок возвращает. Void — ничего;
Строка — текст;
Число — число;
Булев — true / false;
Карта, Список строк, Список карт, View — сложные типы.
Добавить переменную Параметры блока — значения, которые передаются при вызове. Тип (Булев, Строка, Число) + «Имя переменной» + «Текст метки». Кнопка «+» добавляет параметр.
Пользовательский параметр Дополнительная настройка блока. Поле «Параметр», поле «Имя переменной», кнопка «+».
Кнопки внизу Управление созданием блока. Отмена — закрыть без сохранения;
Добавить — создать блок.

Как создать свой блок

  1. Тапни по категории «Свой блок» в левом меню.
  2. Откроется диалог «Выберите More Block» с полем поиска.
  3. Внизу или сверху — кнопка «+ Добавить» (или аналогичная) для создания нового блока.
  4. Откроется форма создания:
    • Имя блока — название, под которым блок появится в палитре. До 60 символов.
    • Select Moreblock type — тип возвращаемого значения:
      • Void — ничего не возвращает;
      • Строка — возвращает текст;
      • Число — возвращает число;
      • Булев — возвращает true или false.
    • Добавить переменную — параметры блока. Выбор типа (Булев, Строка, Число), поле «Имя переменной» и поле «Текст метки». Справа — кнопка «+» для добавления.
    • Пользовательский параметр — дополнительная настройка. Поле «Параметр», поле «Имя переменной», кнопка «+».
    • Внизу — кнопки «Отмена» и «Добавить».
  5. После создания блок появится в списке и станет доступен для добавления в события.
  6. Внутри нового блока (как в событии) — блочное полотно, куда вставляются команды.
  7. Из других событий блок вызывается как обычный блок из палитры.
⚠️ Важно: имя блока должно быть уникальным. Если создать два блока с одинаковым именем — Sketchware не сможет их различить при вызове.
⚠️ Важно: тип возвращаемого значения определяет, как блок будет использоваться. Void — вызывается как команда. Строка, Число, Булев — вставляется в «дырки» других блоков.
⚠️ Важно: параметры (переменные) — это значения, которые блок принимает при вызове. Например, блок «Показать ошибку» с параметром текст — можно вызвать с разными сообщениями.
⚠️ Важно: внутри пользовательского блока доступны только его собственные параметры и глобальные переменные. Локальные переменные события снаружи не видны.
💡 Совет: не создавай слишком много своих блоков. Если блок используется только в одном месте — он не нужен. Оптимально — для логики, которая повторяется 3+ раза.
💡 Совет: давай блокам понятные имена: showError, saveData, checkNetwork. Тогда в палитре блоков их легко найти.
💡 Совет: для простых операций (одно-два действия) свой блок не нужен. Он оправдан, когда внутри 5+ команд или когда логика повторяется.
💡 Совет: если твой блок возвращает значение — используй его как значение в других блоках. Например, свой блок getGreeting(name) возвращает строку «Привет, Иван!» — вставляй его прямо в Toast или setText.
💡 Совет: создавай отдельные блоки для работы с данными: «загрузить настройки», «сохранить настройки», «сбросить данные». Тогда события будут короткими и понятными.
❌ Частая ошибка: создавать блок для одной команды. Например, свой блок «показать сообщение» — это просто Toast. Лучше вызывай Toast напрямую.
❌ Частая ошибка: забывать про параметры. Если блок должен работать с разными значениями — добавь параметры, иначе он будет «зашит» под конкретное значение.
❌ Частая ошибка: дублировать блоки с одинаковой логикой. Если создал блок — используй его везде, а не копируй ту же логику в разные события.
❌ Частая ошибка: пытаться обратиться из своего блока к локальным переменным события, которое его вызвало. Так нельзя — блок видит только то, что передано через параметры.

Резюме

  • Свой блок (More Block) — пользовательская команда, сохранённая под именем.
  • Используется для часто повторяющейся логики — аналог функции в программировании.
  • Создаётся через форму: имя, тип возвращаемого значения, параметры.
  • Типы: Void (команда), Строка, Число, Булев (значения), плюс сложные типы.
  • Параметры передают значения при вызове — например, текст для сообщения об ошибке.
  • Внутри блока — своё блочное полотно, как у события.
  • Вызывается из любого события как обычный блок из палитры.
  • Оправдан только для логики, которая повторяется или сложна (5+ команд).

Частые ошибки новичков

  • Создают блок для одной команды. Проще вызвать эту команду напрямую.
  • Забывают про параметры. Блок «зашит» под одно значение, а нужно разное.
  • Дублируют блоки. Создали блок — используйте его везде.
  • Пытаются читать локальные переменные события. Блок видит только свои параметры.
  • Дают блокам нечёткие имена. Потом сложно найти в палитре.
  • Создают слишком много своих блоков. Проект усложняется, а пользы нет.
  • Забывают задать тип возвращаемого значения. Блок не работает так, как ожидалось.
