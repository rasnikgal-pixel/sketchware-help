Категория Списки

Списки — четвёртая категория в палитре виджетов. В ней собраны компоненты для отображения множества однотипных элементов: строк, плиток, карточек, страниц. Вместо того чтобы вручную добавлять сотню TextView друг под другом, ты используешь один компонент-список, а данные подставляешь в логике.

Это ключевая категория для приложений с лентами, каталогами, чатами, новостями, настройками — всем, где содержимое представлено повторяющимися блоками.

Из чего состоит категория

В категории Списки пять компонентов. Ниже они собраны в таблицу с кратким описанием.

Компонент Что это Когда использовать
ListView Вертикальный список строк. Классический компонент для отображения простых списков. Простые списки из одной строки текста: меню настроек, города, категории.
GridView Сетка элементов. Раскладывает содержимое по колонкам и строкам. Галереи, каталоги плиткой, клавиатуры с иконками.
RecyclerView Современный список с гибкой настройкой. Замена ListView в новых приложениях. Сложные карточки, ленты, чаты, любые списки с разными типами строк.
Spinner Выпадающий список. Пользователь тапает — открывается меню с вариантами. Выбор одного из нескольких вариантов: страна, пол, категория.
ViewPager Горизонтальная прокрутка страниц. Используется для свайпа между экранами. Онбординг, слайдер с картинками, переключение разделов свайпом.

Зачем нужны списки

  • Производительность. Список создаёт только видимые элементы, а остальные «подгружает» по мере прокрутки. Сотни TextView так не работают.
  • Динамические данные. Содержимое задаётся в логике — из базы, из сети, из файла.
  • Единый шаблон. Все элементы списка выглядят одинаково — меняется только содержимое.
  • Реакция на тапы. У списков есть встроенные события: onItemClick, onItemSelected.

Что важно понимать

  • Все компоненты этой категории работают только вместе с логикой. Без настройки адаптера список будет пустым.
  • Adapter (адаптер) — посредник между данными и списком. Он превращает массив данных в строки / плитки / карточки.
  • У каждого компонента свой адаптер: у ListView — ArrayAdapter, у RecyclerView — RecyclerView.Adapter.
  • Элементы списка не задаются в Дизайнере — они формируются в логике через шаблон (Layout) или стандартный вид Android.

Как перетащить компонент из этой категории на макет

Все компоненты этой категории попадают на экран только перетаскиванием (drag & drop). Обычный тап по виджету в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V), Linear(H) или RelativeLayout.
  3. Раскрой категорию Списки в палитре слева.
  4. Зажми нужный компонент (например, ListView) и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — компонент появится в разметке.
  6. Присвой осмысленный ID — он нужен для работы в логике.
  7. Открой вкладку «События» и добавь логику: загрузку данных в список и обработку тапов по элементам.
⚠️ Важно: обычный тап по виджету в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: для большинства списков нужна логика. Просто перетащить ListView в разметку недостаточно — он будет пустым, пока в него не загрузят данные.
💡 Совет: для простых списков (одна строка текста) используй ListView — минимум логики. Для сложных карточек — RecyclerView. Для сетки — GridView. Для выбора одного варианта — Spinner.
💡 Совет: для свайпа между разделами внутри одного экрана используй ViewPager в связке с TabLayout.
❌ Частая ошибка: перетаскивать ListView и RecyclerView на один и тот же экран. Они конфликтуют по прокрутке и мешают друг другу.

Резюме

  • Списки — категория компонентов для отображения множества однотипных элементов.
  • В ней пять компонентов: ListView, GridView, RecyclerView, Spinner, ViewPager.
  • Компоненты перетаскиваются на макет только перетаскиванием, а не тапом.
  • Все списки работают через адаптер — посредник между данными и виджетом.
  • Содержимое списков задаётся в логике, а не в свойствах.
  • Для простых списков — ListView; для сложных — RecyclerView; для сетки — GridView; для выбора — Spinner; для свайпа — ViewPager.
  • Не размещай ListView и RecyclerView на одном экране — они конфликтуют.

Частые ошибки новичков

  • Тапают по компоненту в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Перетащили ListView и ждут, что он покажет данные. Без логики и адаптера список пустой.
  • Ищут содержимое списка в свойствах. Данные задаются только в логике.
  • Ставят ListView и RecyclerView на одном экране. Прокрутка конфликтует.
  • Используют ListView для сложных карточек. Лучше подходит RecyclerView.
  • Используют Spinner для множественного выбора. Спиннер — только один вариант.
  • Путают ViewPager с горизонтальной прокруткой картинок. ViewPager — для страниц; для галереи лучше Scroll(H).
