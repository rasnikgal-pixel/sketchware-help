Firebase Storage — облачное хранилище

Firebase Storage — облачное хранилище файлов. Позволяет загружать и хранить изображения, документы, видео, аудио — без собственного сервера. Файлы доступны по ссылке с любого устройства.

Иконка в диалоге добавления — логотип Firebase.

Как работает

  • Хранит файлы в облаке Google.
  • Загружает файлы с устройства в Storage.
  • Скачивает файлы по ссылке.
  • Удаляет ненужные файлы.
  • Возвращает URL файла — по нему можно показать картинку в ImageView или передать в RequestNetwork.
  • Поддерживает правила безопасности — кто может читать и записывать.

Когда использовать

  • Аватарки пользователей — картинки профиля в облаке.
  • Фотоальбомы — загрузка и хранение изображений.
  • Документы — PDF, DOC, TXT.
  • Медиа — видео и аудио.
  • Резервные копии — сохранение файлов приложения в облако.
  • Обмен файлами — между пользователями.
  • Загрузка контента — пользовательский контент.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова. Например, storage.
  • URL хранилища — адрес из Firebase Console (обычно gs://имя-проекта.appspot.com).

Основные блоки в логике

  • uploadFile — загрузить файл в облако.
  • downloadFile — скачать файл из облака.
  • deleteFile — удалить файл.
  • getDownloadUrl — получить ссылку на файл.
  • getReference — получить ссылку на папку или файл.

События Firebase Storage

  • onSuccess — операция успешно завершена.
  • onFailure — ошибка.
  • onProgress — прогресс загрузки (в процентах).

Как использовать

  • Зарегистрируйся в Firebase Console.
  • Включи Storage в проекте.
  • Скачай google-services.json и подключи в Sketchware Pro 7.
  • Настрой правила безопасности — кто может читать и записывать.
  • Подключи компонент Firebase Storage на вкладке «Компонент».
  • Задай имя — например, storage.
  • Добавь разрешение INTERNET.
  • В логике:
    • загрузка — uploadFile с указанием пути и файла;
    • получение ссылки — getDownloadUrl;
    • скачивание — downloadFile;
    • в onSuccess — обработай результат (URL, файл).

Пример: загрузка аватарки

  • Пользователь выбирает картинку через FilePicker.
  • Button «Загрузить» → uploadFile в /avatars/{uid}.jpg.
  • В onSuccess — получи URL через getDownloadUrl.
  • Сохрани URL в Firebase DB под профилем пользователя.
  • Покажи картинку из URL в ImageView.

Пример: скачивание документа

  • Пользователь тапает по элементу списка.
  • downloadFile из /documents/file.pdf.
  • В onSuccess — открой файл или покажи ссылку.

⚠️ Важно: правила безопасности — критично. По умолчанию Storage открыт только для авторизованных пользователей. Настрой правила под свои задачи.

⚠️ Важно: бесплатный лимит Firebase — 5 ГБ хранилища, 1 ГБ/день скачивания. При превышении — платно.

⚠️ Важно: загружай сжатые картинки. Полноразмерные фото 5 МБ займут весь лимит за пару загрузок.

⚠️ Важно: не загружай личные файлы без согласия пользователя. Это нарушение приватности и правил Google Play.

⚠️ Важно: не храни чувствительные данные в Storage без шифрования. Файлы доступны по ссылке, если правила открыты.

💡 Совет: для аватарок используй формат .jpg и сжимай до 500×500 пикселей. Такой размер достаточен для профиля и весит мало.

💡 Совет: для галереи изображений используй Storage вместе с Firebase DB. В базе — метаданные (имя, дата, автор), в Storage — сами файлы.

💡 Совет: для загрузки с прогрессом используй событие onProgress. Показывай ProgressBar с процентом.

💡 Совет: для удаления файлов используй deleteFile. Не оставляй мусор в облаке — он занимает лимит.

💡 Совет: для правил безопасности используй шаблон: «только авторизованные пользователи могут читать и писать в свою папку». Например, /users/{uid}/...

💡 Совет: не загружай файлы без интернета. Проверяй соединение перед uploadFile.

❌ Частая ошибка: не настроить правила безопасности. Storage открыт — любой может загрузить или скачать файлы.

❌ Частая ошибка: загружать полноразмерные фото. Лимит 5 ГБ забивается за несколько загрузок.

❌ Частая ошибка: не сжимать картинки перед загрузкой. Медленная загрузка и большой расход трафика.

❌ Частая ошибка: не обрабатывать onFailure. При ошибке загрузки приложение молчит.

❌ Частая ошибка: не удалять ненужные файлы. Мусор в облаке занимает лимит.

❌ Частая ошибка: не показывать прогресс загрузки. Пользователь не понимает, что происходит, и уходит.
