AsyncTask — фоновая задача

AsyncTask — компонент для выполнения фоновых задач. Позволяет делать длительные операции — вычисления, работу с файлами, сложные манипуляции — без «зависания» интерфейса. Пользователь продолжает работать с приложением, пока задача выполняется в фоне.

Иконка в диалоге добавления — логотип Firebase с круговой стрелкой (или похожий значок фоновой задачи).

Как работает

  • Запускает фоновую задачу — отдельно от главного потока.
  • Интерфейс не блокируется — кнопки нажимаются, экран прокручивается.
  • По завершении задачи срабатывает событие — можно показать результат.
  • Может обновлять прогресс — например, ProgressBar в реальном времени.
  • Есть три фазы: onPreExecute (подготовка), doInBackground (работа), onPostExecute (результат).

Когда использовать

  • Тяжёлые вычисления — например, обработка больших массивов.
  • Работа с большими файлами — чтение, запись, парсинг.
  • Сложные манипуляции с данными — сортировка тысяч элементов.
  • Обработка изображений — сжатие, фильтрация, сохранение.
  • Долгие операции с базой данных — массовые запросы.

Не используй для сетевых запросов — для них есть RequestNetwork, он уже асинхронный.

Настройки при добавлении

Настройка Что задаёт Пример
Имя компонента Идентификатор для вызова в логике. myTask, heavyTask.

Основные блоки в логике

Блок Что делает
execute Запустить задачу.
publishProgress Обновить прогресс (внутри задачи).
cancel Отменить задачу.

События AsyncTask

Событие Когда срабатывает
onPreExecute Выполняется до начала задачи. Здесь готовят интерфейс: показывают ProgressBar, блокируют кнопки.
doInBackground Основная задача. Здесь выполняется тяжёлая работа.
onProgressUpdate Обновление прогресса. Здесь меняют ProgressBar.
onPostExecute Выполняется после задачи. Здесь показывают результат, скрывают ProgressBar.
onCancelled Вызывается при отмене задачи.

Как использовать

  1. Подключи компонент AsyncTask на вкладке «Компонент».
  2. Задай имя — например, heavyTask.
  3. В категории «Компонент» добавь события:
    • onPreExecute — показ ProgressBar;
    • doInBackground — сама тяжёлая операция;
    • onPostExecute — обработка результата;
    • onProgressUpdate — если нужно обновлять прогресс.
  4. В логике вызови execute — например, по кнопке.
  5. Внутри doInBackground выполни работу.
  6. В onPostExecute — используй результат.

Пример: обработка большого файла

  • Кнопка «Обработать» → heavyTask.execute().
  • onPreExecute — показать ProgressBar, заблокировать кнопку.
  • doInBackground — прочитать файл, обработать данные.
  • onProgressUpdate — обновить ProgressBar в процессе.
  • onPostExecute — показать результат, скрыть ProgressBar, разблокировать кнопку.
⚠️ Важно: не обновляй интерфейс в doInBackground. Этот метод работает в фоновом потоке — обращение к виджетам приведёт к ошибке. Обновляй UI только в onPreExecute, onProgressUpdate и onPostExecute.
⚠️ Важно: не используй AsyncTask для сетевых запросов. Для этого есть RequestNetwork — он уже работает в фоне и правильно обрабатывает ответы.
⚠️ Важно: не запускай AsyncTask из AsyncTask. Вложенные задачи создают путаницу и непредсказуемое поведение.
⚠️ Важно: не забывай про отмену. Если пользователь ушёл с экрана — отмени задачу через cancel. Иначе она продолжит работать впустую.
⚠️ Важно: AsyncTask устарел в современном Android. Google рекомендует использовать Executor или Coroutine. Но в Sketchware Pro 7 AsyncTask — единственный доступный инструмент для фоновых задач.
💡 Совет: для простых операций AsyncTask не нужен. Большинство действий Sketchware выполняет достаточно быстро и без него.
💡 Совет: для сетевых запросов используй RequestNetwork — он асинхронный и правильно обрабатывает ответы. Не нужно оборачивать его в AsyncTask.
💡 Совет: для прогресса используй publishProgress внутри doInBackground. Промежуточное значение — в onProgressUpdate. Пользователь увидит, как задача движется.
💡 Совет: для отмены задачи — предусмотри кнопку «Отмена». Если задача долгая, пользователь должен иметь возможность её прервать.
💡 Совет: для проверки результата используй onPostExecute — там ты имеешь доступ к UI и можешь показать данные.
❌ Частая ошибка: обновлять UI в doInBackground. Приложение падает с ошибкой «только главный поток может обращаться к UI».
❌ Частая ошибка: использовать AsyncTask для сетевых запросов. Это лишний код — RequestNetwork делает то же самое проще.
❌ Частая ошибка: не отменять задачи при уходе с экрана. Задача продолжает работать, расходуя ресурсы.
❌ Частая ошибка: запускать AsyncTask из AsyncTask. Приводит к путанице и ошибкам.
❌ Частая ошибка: не показывать прогресс. Пользователь не понимает, работает ли задача.

Резюме

  • AsyncTask — компонент для выполнения фоновых задач.
  • Не блокирует интерфейс — пользователь продолжает работать.
  • Основные блоки: execute, publishProgress, cancel.
  • Основные события: onPreExecute, doInBackground, onProgressUpdate, onPostExecute, onCancelled.
  • Не обновляй UI в doInBackground — только в главном потоке.
  • Не используй для сетевых запросов — для них RequestNetwork.
  • Отменяй задачу при уходе с экрана.
  • Для простых операций AsyncTask не нужен.

Частые ошибки новичков

  • Обновляют UI в doInBackground. Приложение падает.
  • Используют AsyncTask для сетевых запросов. Нужен RequestNetwork.
  • Не отменяют задачу при уходе с экрана. Ресурсы расходуются зря.
  • Запускают AsyncTask из AsyncTask. Путаница и ошибки.
  • Не показывают прогресс. Пользователь не видит, что происходит.
  • Используют для простых операций. Избыточно и без пользы.
  • Забывают onPostExecute. Результат задачи не обрабатывается.
