Логика PreviewActivity

PreviewActivity — экран предпросмотра HTML. Открывается по кнопке «Предпросмотр» из редактора. Показывает, как выглядит HTML-код, который написал пользователь.

Это самый простой экран по логике во всём проекте. Всего три события, и они короткие. Сложность — не в самих событиях, а в понимании того, как HTML передаётся из редактора в WebView через Intent.

Как открыть логику этого экрана

  1. Открой вкладку «События».
  2. Переключись на экран preview.xml через селектор внизу (или через Менеджер представлений).
  3. Ты увидишь список событий только этого экрана.

События PreviewActivity

У этого экрана всего три события:

  1. При создании / (onCreate) — загрузка HTML в WebView при открытии экрана.
  2. Нажатие btnPreviewBack / (onClick) — возврат в редактор по кнопке «←».
  3. При нажатии «Назад» / (onBackPressed) — обработка системной кнопки «Назад».

Событие 1. При создании / (onCreate)

Когда срабатывает: при открытии экрана PreviewActivity.

Что делает: получает HTML-код из Intent, настраивает WebView, загружает HTML для отображения.

Порядок блоков:

  1. Получить данные / (Get Extra) из компонента goToScreen. Ключ: html_content. Значение по умолчанию: пустая строка "". Результат в переменную html.
  2. Если / (If) html == "": установить html = "<h1>Нет содержимого</h1>".
  3. Включить JavaScript / (Set JavaScript Enabled) для виджета webPreview. Значение: Да / (Yes).
  4. Поддержка зума / (Set Support Zoom) для виджета webPreview. Значение: Да / (Yes).
  5. Загрузить HTML / (Load HTML) для виджета webPreview. Параметры:
    • Содержимое: html.
    • Тип: text/html.
    • Кодировка: UTF-8.

Псевдокод onCreate:

// ──── ШАГ 1. Получаем HTML из Intent ────
// Редактор передал HTML при переходе через Put Extra.
html = goToScreen.getExtra("html_content")

// ──── ШАГ 2. Проверяем, что HTML не пустой ────
if (html == "") {
    html = "<h1>Нет содержимого</h1>"
}

// ──── ШАГ 3. Настраиваем WebView ────
// Включаем выполнение JavaScript на странице.
webPreview.setJavaScriptEnabled(YES)

// Разрешаем масштабирование жестом «щипок».
webPreview.setSupportZoom(YES)

// ──── ШАГ 4. Загружаем HTML ────
// Передаём строку как HTML-контент с указанием кодировки.
webPreview.loadHtml(html, "text/html", "UTF-8")

Что важно понять:

  • HTML передаётся из редактора через Intent. Если пользователь как-то попал сюда напрямую — сработает заглушка «Нет содержимого».
  • JavaScript включается, потому что многие HTML-страницы используют его для анимаций, интерактивных элементов и форматирования.
  • Зум нужен, чтобы пользователь мог увеличить мелкий текст.
  • Загрузка через Load HTML — самый быстрый способ: не нужно сохранять файл, потом читать его обратно.
  • Кодировка UTF-8 важна — без неё русские буквы в HTML могут отобразиться «кракозябрами».

Событие 2. Нажатие btnPreviewBack / (onClick)

Когда срабатывает: при тапе по кнопке «←» в шапке экрана предпросмотра.

Что делает: закрывает PreviewActivity и возвращает пользователя в EditorActivity.

Порядок блоков:

  1. Завершить / (Finish) для компонента goToScreen.

Псевдокод onClick btnPreviewBack:

// Закрываем текущий экран. Android вернёт пользователя в редактор.
goToScreen.finish()

Что важно понять:

  • Блок Завершить / (Finish) закрывает текущий экран. Android автоматически возвращает пользователя на предыдущий экран в стеке — то есть в редактор.
  • Не нужно вызывать Intent вручную — система сама помнит, откуда пришёл пользователь.
  • Это работает, потому что редактор открыл предпросмотр через Start Activity, не удаляя себя из стека.

Событие 3. При нажатии «Назад» / (onBackPressed)

Когда срабатывает: при нажатии системной кнопки «Назад» на телефоне.

Что делает: проверяет, есть ли в WebView история навигации. Если есть — возвращается на предыдущую страницу внутри WebView. Если нет — закрывает экран и возвращает в редактор.

Порядок блоков:

  1. Если / (If) Может вернуться назад / (Can Go Back) для виджета webPreview: вызвать Вернуться назад / (Go Back) для виджета webPreview.
  2. Иначе / (Else): вызвать Завершить / (Finish) для компонента goToScreen.

Псевдокод onBackPressed:

// Если WebView может вернуться по своей истории — возвращаемся.
if (webPreview.canGoBack()) {
    webPreview.goBack()
} else {
    // Иначе закрываем экран и возвращаемся в редактор.
    goToScreen.finish()
}

Что важно понять:

  • Это событие нужно, если HTML содержит ссылки или переходы между страницами. Тогда кнопка «Назад» сначала возвращает по истории WebView, а не сразу закрывает экран.
  • Если HTML статичный (без ссылок) — событие всё равно полезно: кнопка «Назад» сразу закроет экран.
  • Без этого события системная кнопка «Назад» просто закроет экран — что тоже работает, но менее удобно, если пользователь открыл несколько страниц внутри WebView.

Что важно понять про логику PreviewActivity

Первое — это самый простой экран по логике. Всего три события, и они короткие. Всё, что делает PreviewActivity, — показывает HTML и возвращает пользователя назад.

Второе — HTML приходит из редактора. PreviewActivity не хранит данные и не сохраняет их. Она только показывает то, что передано через Intent.

Третье — событие onBackPressed критично для UX. Без него системная кнопка «Назад» просто закроет экран. С ним — сначала вернёт по истории WebView, и только потом закроет. Это стандартное поведение браузеров и приложений с WebView.

Четвёртое — не забывай про разрешение INTERNET. Если HTML содержит картинки с внешних серверов или подключает внешние стили — WebView не загрузит их без разрешения INTERNET. В Менеджере разрешений убедись, что INTERNET включён.

Пятое — кодировка. UTF-8 в блоке Load HTML обязательна. Иначе русский текст в HTML превратится в набор непонятных символов.

Внимание. WebView по умолчанию не позволяет переходы по внешним ссылкам внутри приложения. Если пользователь тапнет по ссылке в HTML, WebView может попытаться открыть её внутри себя или заблокировать. Если хочешь, чтобы ссылки открывались в браузере — нужна дополнительная логика через событие shouldOverrideUrlLoading. В HelpStudio этого нет — здесь просто показывается HTML.
Совет. Проверь работу предпросмотра на разных HTML: простой текст, заголовки, ссылки, картинки. Убедись, что всё отображается правильно. Если что-то не так — открой Logcat и посмотри, что пишет WebView.
