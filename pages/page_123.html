Чем отличается от виджета

Виджет и компонент — две разные сущности в Sketchware Pro 7, хотя обе относятся к наполнению приложения. Понять разницу важно, потому что путаница между ними — одна из частых причин, почему приложение «не работает».

Главное отличие

  • Виджет — видимый элемент интерфейса. Пользователь видит его на экране и взаимодействует с ним.
  • Компонент — невидимый сервис. Пользователь не видит его, но результат работы проявляется через виджеты.

Сравнительная таблица

Критерий Виджет Компонент
Видимость Видим на экране. Невидим.
Где подключается На вкладке «Дизайнер» — перетаскивается в разметку. На вкладке «Компонент» — через кнопку «+».
Взаимодействие с пользователем Напрямую — пользователь видит и нажимает. Косвенно — через логику.
Работа Показывает данные, принимает ввод. Работает в фоне: интернет, база, камера, звук.
Управление Свойства виджета + логика. Только логика — через блоки.
Результат Виден сразу, если виджет на экране. Появляется через виджеты или события.

Примеры

Виджеты:

  • TextView — показывает текст.
  • Button — кнопка для нажатия.
  • EditText — поле ввода.
  • ImageView — отображает картинку.
  • ListView — список элементов.

Компоненты:

  • SharedPreferences — хранилище данных.
  • RequestNetwork — сетевые запросы.
  • Camera — доступ к камере.
  • Vibrator — управление вибрацией.
  • Intent — переход между экранами.

Что делают виджеты

  • Отображают что-то пользователю.
  • Принимают ввод от пользователя.
  • Реагируют на действия: нажатия, свайпы, ввод текста.
  • Меняются в логике: текст, цвет, видимость.

Что делают компоненты

  • Работают в фоне, не видны на экране.
  • Обеспечивают функционал: интернет, база данных, звук, камера.
  • Управляются через логику: вызов блока — действие компонента.
  • Возвращают результат через события (например, onResponse у RequestNetwork).

Аналогия

Представь приложение как автомобиль:

  • Виджеты — руль, педали, приборная панель. Водитель их видит и использует.
  • Компоненты — двигатель, тормозная система, электроника. Водитель их не видит, но они обеспечивают движение.

Без виджетов пользователь не поймёт, как управлять приложением. Без компонентов приложение не сможет ничего делать.

Как это работает вместе

Пример: приложение «Погода».

  • Виджеты: EditText (город), Button (найти), TextView (результат), ImageView (иконка погоды).
  • Компоненты: RequestNetwork (запрос к API погоды), SharedPreferences (сохранение последнего города).
  • Логика: кнопка вызывает RequestNetwork → получает ответ → парсит данные → заполняет TextView и ImageView.

Виджеты показывают, компоненты — работают. Логика — связывает их.

⚠️ Важно: виджеты без компонентов могут только показывать статику. Всё, что требует данных, действий или работы с устройством — через компоненты.
⚠️ Важно: компоненты без виджетов будут работать в фоне, но пользователь не увидит результата. Например, RequestNetwork получит ответ, но если данные не вывести в TextView — пользователь ничего не узнает.
⚠️ Важно: не путай места подключения. Виджеты добавляются в «Дизайнере», компоненты — на вкладке «Компонент». Если искать виджет в списке компонентов — его там нет.
💡 Совет: думай о виджетах как о лице приложения, а о компонентах — как о руках. Лицо показывает, руки делают.
💡 Совет: для простого экрана сначала добавляй виджеты — станет ясно, какой функционал нужен. Потом подключай компоненты под этот функционал.
💡 Совет: не добавляй компонент «на всякий случай». Если не знаешь, зачем он — не подключай. Лишние компоненты увеличивают APK.
💡 Совет: не пытайся вставить компонент в разметку. Компоненты невидимы — их место только в логике.
❌ Частая ошибка: искать SharedPreferences в палитре виджетов. Он в компонентах, не в виджетах.
❌ Частая ошибка: пытаться отобразить RequestNetwork на экране. Компонент невидим — данные выводятся через виджеты.
❌ Частая ошибка: добавлять виджеты через вкладку «Компонент». Там их нет — виджеты только в Дизайнере.
❌ Частая ошибка: думать, что компонент заработает сам. Компонент — инструмент. Логика — то, что им управляет.

Резюме

  • Виджет — видимый элемент интерфейса, добавляется на вкладке «Дизайнер».
  • Компонент — невидимый сервис, подключается на вкладке «Компонент».
  • Виджеты показывают, принимают ввод, реагируют на действия пользователя.
  • Компоненты работают в фоне: интернет, база данных, камера, звук, уведомления.
  • Логика связывает их: вызывает компоненты и меняет виджеты.
  • Виджеты без компонентов — статичны; компоненты без виджетов — невидимы.
  • Не путай места подключения: разные вкладки.
  • Простой пример «Погода» показывает, как это работает вместе.

Частые ошибки новичков

  • Ищут SharedPreferences среди виджетов. Это компонент.
  • Пытаются отобразить RequestNetwork на экране. Он невидим.
  • Добавляют виджеты через «Компонент». Их там нет.
  • Ждут, что компонент работает сам. Нужно вызывать через логику.
  • Забывают, что компоненты возвращают результат через виджеты. Данные не видны пользователю.
  • Не понимают, зачем нужен компонент. Добавляют «про запас» и создают мусор.
  • Путают компонент с событием. onResponse — событие компонента, а не сам компонент.
