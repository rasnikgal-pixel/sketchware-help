Активность

Активность — первая и самая важная категория в левом меню вкладки «События». Здесь собраны события жизненного цикла экрана: от создания до уничтожения. Каждое событие — это точка, в которой можно «вклиниться» в работу приложения и выполнить свои действия.

Activity (активность) — это один экран приложения. У каждой активности есть свой жизненный цикл: она создаётся, появляется, становится активной, приостанавливается, останавливается и в конце уничтожается. События этой категории позволяют реагировать на каждый этап.

Список событий категории

Событие Когда срабатывает
Import Добавить свои импорты (Java-пакеты, классы). Полезно для использования сторонних библиотек.
initializeLogic Вызывается при создании Activity. Служебное событие, обычно не используется вручную.
onCreate Самое первое событие. Срабатывает при создании экрана. Основное место для инициализации.
onStart При появлении экрана на устройстве.
onResume При возобновлении работы (после паузы или сворачивания).
onPause При паузе (пользователь свернул приложение или перешёл на другой экран).
onStop Когда экран стал полностью невидим.
onDestroy При уничтожении экрана (закрытие приложения или переход на новый экран).
onBackPressed При нажатии системной кнопки «Назад».
onActivityResult При получении результата из другой Activity (например, после выбора файла).
onPostCreate Вызывается после завершения onCreate и onStart.
onSaveInstanceState При сохранении состояния (например, при повороте экрана).
onRestoreInstanceState При восстановлении состояния.
onCreateOptionsMenu При создании меню опций (верхнее меню в тулбаре).
onOptionsItemSelected При выборе пункта меню опций.
onCreateContextMenu При создании контекстного меню (по долгому нажатию).
onContextItemSelected При выборе пункта контекстного меню.
onTabLayoutNewTabAdded Возвращает имя текущей вкладки TabLayout.

Когда что использовать

Событие Зачем использовать
onCreate Инициализация переменных, чтение настроек, загрузка данных.
onStart Обновление данных при возврате на экран.
onResume Запуск анимаций, воспроизведение музыки.
onPause Пауза музыки, сохранение промежуточных данных.
onStop Остановка длительных процессов.
onDestroy Освобождение ресурсов.
onBackPressed Перехват кнопки «Назад» (например, показать диалог подтверждения).
onActivityResult Обработка результата из другой Activity.
onCreateOptionsMenu / onOptionsItemSelected Работа с меню в тулбаре.

Как добавить событие

  • Тап по категории «Активность» в левом меню.
  • В открывшемся диалоге — список событий с чекбоксами.
  • Отметь нужные события галочками.
  • Нажми «Добавить» — они появятся в центре экрана в виде плиток.
⚠️ Важно: не добавляй все события сразу. Каждое событие — это метод в коде, даже пустое. Много лишних событий — APK тяжелее, сборка дольше.
⚠️ Важно: onCreate — самое важное событие. Без него приложение не запустится корректно. Оно создаётся автоматически при создании проекта — не удаляй его.
⚠️ Важно: события onSaveInstanceState и onRestoreInstanceState работают только при повороте экрана или смене конфигурации. В простых приложениях редко используются.
💡 Совет: в onCreate задавай всё, что должно быть готово к моменту появления экрана: начальные значения переменных, тексты полей, состояния переключателей.
💡 Совет: для сохранения данных при уходе с экрана используй onPause или onStop. Это надёжнее, чем сохранять только при нажатии кнопки «Сохранить».
💡 Совет: для остановки музыки при сворачивании приложения используй onPause. Иначе музыка продолжит играть в фоне.
💡 Совет: не запускай тяжёлые процессы в onCreate — приложение будет долго открываться. Если нужно загрузить данные из сети — делай это асинхронно, показывая ProgressBar.
❌ Частая ошибка: добавлять событие onCreate повторно. Оно уже есть в проекте по умолчанию. Второе не появится, но и не принесёт пользы.
❌ Частая ошибка: не использовать onCreate и пытаться инициализировать переменные в других событиях. Логика становится запутанной.
❌ Частая ошибка: путать onPause и onStop. onPause срабатывает при любом уходе с экрана, onStop — только когда экран полностью невидим. Для большинства задач достаточно onPause.
❌ Частая ошибка: добавлять все события жизненного цикла сразу и оставлять их пустыми. Это «мусор» в проекте.

Резюме

  • Активность — категория событий жизненного цикла экрана.
  • Activity — один экран приложения, у которого есть фазы: создание, отображение, пауза, уничтожение.
  • Ключевые события: onCreate (создание), onStart (появление), onResume (возобновление), onPause (пауза), onStop (невидим), onDestroy (уничтожение).
  • onCreate — самое важное: здесь делается вся инициализация.
  • onPause — надёжное место для сохранения данных при уходе с экрана.
  • onBackPressed — перехват кнопки «Назад».
  • onCreateOptionsMenu и onOptionsItemSelected — работа с меню в тулбаре.
  • onSaveInstanceState и onRestoreInstanceState нужны только при повороте экрана.
  • Не добавляй все события сразу — только те, которые действительно нужны.

Частые ошибки новичков

  • Добавляют onCreate повторно. Оно уже есть в проекте по умолчанию.
  • Не используют onCreate для инициализации. Логика расползается по другим событиям.
  • Путают onPause и onStop. Для большинства задач достаточно onPause.
  • Добавляют все события жизненного цикла сразу. Мусор в коде и вес APK.
  • Инициализируют переменные в onClick. Логика ломается при первом открытии экрана.
  • Запускают тяжёлые процессы в onCreate. Экран долго открывается.
  • Забывают обрабатывать onActivityResult. Результат из другой Activity теряется.
