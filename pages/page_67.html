MultiAutoCompleteTextView — несколько автоподсказок

MultiAutoCompleteTextView — расширенная версия AutoCompleteTextView, которая поддерживает несколько значений в одном поле. Пользователь вводит первое слово, выбирает из подсказок, ставит разделитель — и продолжает вводить следующее.

Иконка в палитре — поле с двумя вертикальными метками и выпадающим списком.

Как работает

  • Пользователь вводит текст — появляется выпадающий список подсказок, как у обычного AutoCompleteTextView.
  • После выбора или ввода значения пользователь ставит разделитель (обычно запятую).
  • Начинает вводить следующее значение — снова появляются подсказки.
  • В поле накапливается список значений через запятую: Москва, Казань, Сочи.
  • Каждое значение можно удалить вручную, стерев его.

Когда использовать

  • Ввод тегов — несколько меток в одном поле.
  • Список получателей — email-адреса через запятую.
  • Множественный выбор городов — когда нужно несколько вариантов.
  • Категории и ключевые слова — например, теги статьи.

По сути — «поле ввода тегов», как в блогах или на сайтах.

Из чего состоит

  • MultiAutoCompleteTextView — само поле.
  • Список подсказок — задаётся в логике.
  • Токенайзер (Tokenizer) — определяет, какой символ считать разделителем между значениями. Обычно запятая.
  • Выпадающий список — появляется при вводе каждого нового значения.

Настройки

Настройка Что делает Значения
Hint Подсказка внутри поля. Любая строка.
Text Начальные значения. Любая строка.
InputType Тип ввода. text, textEmailAddress и другие.
TextColor / TextSize Цвет и размер текста. HEX, число в sp.
Threshold Минимальное число символов для старта автодополнения. Число. Обычно 1 или 2.
DropDownWidth / DropDownBackground Параметры выпадающего списка. Число в dp, HEX.
Width / Height Ширина и высота. match_parent или wrap_content.
MaxLines / MinLines Ограничения по высоте (обычно многострочный). Число.

Как перетащить MultiAutoCompleteTextView на макет

MultiAutoCompleteTextView, как и любой другой виджет, попадает на экран только перетаскиванием (drag & drop). Обычный тап по нему в палитре ничего не делает.

  1. Открой вкладку «Дизайнер».
  2. Убедись, что на макете уже есть контейнер — Linear(V), Linear(H) или RelativeLayout.
  3. Раскрой категорию Widgets в палитре слева.
  4. Зажми MultiAutoCompleteTextView и, не отпуская, перетащи его поверх контейнера — он подсветится, и виджет встанет внутрь.
  5. Отпусти в нужном месте — поле появится в разметке.
  6. Тапни по нему и задай Подсказку и Порог.
  7. Присвой осмысленный ID — он понадобится для логики.
  8. Открой вкладку «События» и в блоке onCreate добавь для этого виджета:
    • блок setSimpleItems — список подсказок;
    • блок setTokenizer — символ-разделитель (обычно запятая).
⚠️ Важно: обычный тап по MultiAutoCompleteTextView в палитре ничего не делает. Виджет попадает на макет только перетаскиванием.
⚠️ Важно: без настройки Tokenizer в логике поле будет вести себя как обычное AutoCompleteTextView — без учёта разделителей. Вводить несколько значений не получится.
⚠️ Важно: список подсказок задаётся в логике, а не в свойствах виджета. В Дизайнере ты настраиваешь только внешний вид.
💡 Совет: в качестве разделителя используй запятую с пробелом — это самый привычный формат для пользователей. Тогда ввод будет выглядеть аккуратно: Москва, Казань, Сочи.
💡 Совет: не ставь слишком много подсказок — поле ввода тегов с автодополнением удобно, только если вариантов не десятки тысяч. Для больших списков используй другой подход.
💡 Совет: показывай пользователю уже введённые значения — они видны в поле через запятую. Это позволяет легко удалить лишнее.
❌ Частая ошибка: путать AutoCompleteTextView и MultiAutoCompleteTextView. Первый — для одного значения, второй — для нескольких через разделитель.
❌ Частая ошибка: забыть указать Tokenizer. Без него подсказки появляются только для первого слова, а после запятой — нет.

Резюме

  • MultiAutoCompleteTextView — поле ввода нескольких значений с автодополнением, разделённых символом (обычно запятой).
  • Перетаскивается на макет как любой другой виджет — перетаскиванием, а не тапом.
  • В свойствах задаётся только внешний вид: Подсказка, Цвет подсказки, размер текста.
  • Список подсказок задаётся в логике через setSimpleItems.
  • Обязательно настраивается Tokenizer в логике — разделитель между значениями. Без него много значений не ввести.
  • Идеальный сценарий: ввод тегов, ключевых слов, email-адресов через запятую.

Частые ошибки новичков

  • Тапают по виджету в палитре и ждут, что он появится на экране. Нужно именно перетащить.
  • Забывают указать Tokenizer. После запятой подсказки не появляются — виджет работает как обычный AutoCompleteTextView.
  • Не задают список подсказок в логике. Поле молчит, потому что не знает вариантов.
  • Путают с AutoCompleteTextView. Это разные виджеты: один — для одного значения, другой — для нескольких.
  • Не задают ID. В логике невозможно привязать подсказки и разделитель к полю.
  • Используют для больших списков. На тысячи вариантов виджет не рассчитан — нужен другой подход.
  • Ставят в качестве разделителя случайные символы. Пользователь не догадается, что вводить «;» или «|». Лучше запятая.
