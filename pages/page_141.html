LocationManager — GPS-геолокация

LocationManager — компонент для определения местоположения. Получает координаты устройства: широту и долготу. Позволяет отслеживать перемещение, показывать позицию на карте, определять адрес.

Иконка в диалоге добавления — метка местоположения (капля).

Как работает

  • Определяет географические координаты устройства.
  • Использует GPS, Wi-Fi, мобильную сеть — в зависимости от доступности.
  • Обновляет позицию в реальном времени — по мере движения.
  • Событие onLocationChanged срабатывает при каждом изменении координат.
  • Может получать точное (GPS) или приблизительное (сеть) местоположение.

Когда использовать

  • Карты — показ местоположения пользователя.
  • Навигация — маршруты, подсказки.
  • Такси и доставка — трекинг курьера и клиента.
  • Фитнес — маршруты пробежек, велосипедных поездок.
  • Поиск рядом — ближайшие магазины, кафе.
  • Погода — определение города по координатам.
  • Отметки на карте — сохранение мест.

Настройки при добавлении

Настройка Что задаёт Пример
Имя компонента Идентификатор для вызова в логике. gps, location.

Основные блоки в логике

Блок Что делает
requestLocationUpdates Начать отслеживание.
removeUpdates Прекратить отслеживание.
getLastKnownLocation Получить последнее известное местоположение.
getLatitude Получить широту.
getLongitude Получить долготу.

Событие LocationManager

Событие Когда срабатывает
onLocationChanged Срабатывает при изменении координат.
onProviderDisabled Когда провайдер (GPS, сеть) отключён.
onProviderEnabled Когда провайдер включён.

Как использовать

  1. Подключи компонент LocationManager на вкладке «Компонент».
  2. Задай имя — например, gps.
  3. Добавь разрешения: ACCESS_FINE_LOCATION (точное) и ACCESS_COARSE_LOCATION (приблизительное).
  4. В onCreate вызови блок requestLocationUpdates — начни отслеживание.
  5. В категории «Компонент» добавь событие onLocationChanged — обработка координат.
  6. Внутри события получай широту и долготу через getLatitude и getLongitude.
  7. Используй координаты: покажи на карте, отправь на сервер, сохрани в память.
  8. При уходе с экрана (onPause или onStop) вызови removeUpdates — прекрати отслеживание.

Пример: показ координат

  • В onLocationChanged получи getLatitude и getLongitude.
  • Отформатируй их в строку.
  • Установи в TextView: «Широта: 55.7558, Долгота: 37.6173».
  • Пользователь видит свои координаты.

Пример: погода по местоположению

  • В onLocationChanged получи координаты.
  • Отправь запрос через RequestNetwork к API погоды с этими координатами.
  • В onResponse — покажи погоду в твоём городе.
⚠️ Важно: разрешение ACCESS_FINE_LOCATION обязательно. Без него приложение не получит координаты.
⚠️ Важно: пользователь может отказать в разрешении. Приложение должно корректно обработать отказ — показать сообщение, предложить ввести город вручную.
⚠️ Важно: GPS расходует батарею. Постоянное отслеживание быстро её разряжает. Прекращай отслеживание, когда оно не нужно.
⚠️ Важно: getLastKnownLocation может вернуть пустое значение, если приложение давно не получало данные. В этом случае жди onLocationChanged.
⚠️ Важно: на Android 12+ появились дополнительные требования к разрешениям местоположения. Если приложение не получает координаты — проверь настройки.
💡 Совет: для экономии батареи используй приблизительное местоположение (ACCESS_COARSE_LOCATION), если точность не критична. Например, для определения города.
💡 Совет: для поиска адреса по координатам используй обратное геокодирование через RequestNetwork к API Google или OpenStreetMap.
💡 Совет: для карт используй компонент MapView и передавай в него координаты из onLocationChanged. Карта центрируется на позиции.
💡 Совет: для трекинга пробежки собирай все координаты в список и потом рисуй маршрут на карте.
💡 Совет: не запрашивай точное местоположение без объяснения. Покажи пользователю, зачем оно нужно — тогда он охотнее даст разрешение.
💡 Совет: для тестирования используй эмулятор Android — там можно задать любые координаты. Это удобнее, чем реальные поездки.
❌ Частая ошибка: не запрашивать разрешение. Координаты не приходят, ошибка не видна.
❌ Частая ошибка: держать GPS постоянно включённым. Батарея садится за пару часов.
❌ Частая ошибка: не обрабатывать отказ в разрешении. Пользователь не понимает, почему функция не работает.
❌ Частая ошибка: ожидать мгновенных координат. Первое определение может занять 10–30 секунд.
❌ Частая ошибка: использовать точное местоположение там, где хватает приблизительного. Лишний расход батареи.

Резюме

  • LocationManager — компонент для определения местоположения.
  • Даёт координаты: широту и долготу.
  • Основные блоки: requestLocationUpdates, removeUpdates, getLastKnownLocation, getLatitude, getLongitude.
  • Основное событие: onLocationChanged — при изменении координат.
  • Требует разрешений ACCESS_FINE_LOCATION и ACCESS_COARSE_LOCATION.
  • Постоянное отслеживание расходует батарею — отключай, когда не нужно.
  • Пользователь может отказать — обрабатывай этот случай.
  • Для тестирования используй эмулятор — можно задать любые координаты.

Частые ошибки новичков

  • Не запрашивают разрешение. Координаты не приходят.
  • Держат GPS постоянно включённым. Батарея садится.
  • Не обрабатывают отказ. Функция не работает без объяснения.
  • Ждут мгновенных координат. Первое определение занимает время.
  • Используют точное там, где хватит приблизительного. Лишний расход.
  • Забывают removeUpdates. Отслеживание продолжается в фоне.
  • Не центрируют карту по координатам. Пользователь не видит свою позицию.
