Логика EditorActivity

EditorActivity — экран редактирования проекта. Здесь логика сложнее, чем в MainActivity, потому что нужно работать с тремя панелями и с содержимым проекта.

В этом разделе — одиннадцать событий:

  1. При создании / (onCreate) — загрузка проекта, показ панели «Разделы», загрузка дерева разделов.
  2. Нажатие btnTabSections / (onClick) — показать панель разделов.
  3. Нажатие btnTabEditor / (onClick) — показать панель HTML.
  4. Нажатие btnTabInfo / (onClick) — показать панель информации.
  5. Нажатие btnAddSection / (onClick) — добавить раздел.
  6. Нажатие btnRenameSection / (onClick) — переименовать раздел.
  7. Нажатие btnDeleteSection / (onClick) — удалить раздел.
  8. Нажатие listSections / (onItemClick) — выбрать раздел, загрузить его HTML в редактор.
  9. Нажатие btnSave / (onClick) — сохранить текущий HTML в раздел.
  10. Нажатие btnPreview / (onClick) — открыть PreviewActivity с HTML.
  11. Нажатие btnFind / (onClick) — найти текст в HTML.

Это самый большой раздел. Но каждое событие — небольшое. Идём по порядку.

Как работает EditorActivity в целом

Прежде чем разбирать события по отдельности, поймём логику экрана:

  1. Экран получает project_id из Intent (переданного с главного экрана).
  2. Читает из хранилища имя проекта, автора и структуру разделов.
  3. Заполняет панель информации: имя и автора.
  4. Заполняет список разделов (ListView).
  5. Показывает панель «Разделы» и скрывает две другие.
  6. Пользователь тапает по разделу → загружается его HTML в editorText.
  7. Пользователь редактирует HTML → нажимает «Сохранить» → HTML записывается в хранилище.
  8. Пользователь нажимает «Предпросмотр» → HTML передаётся в PreviewActivity.

Событие 1. При создании / (onCreate)

Когда срабатывает: при открытии EditorActivity — то есть когда пользователь тапнул по проекту на главном экране.

Что делает: получает ID проекта из Intent, читает данные проекта, показывает панель «Разделы», скрывает две другие, заполняет информацию и список разделов.

Порядок блоков:

  1. Получить данные project_id из Intent — Получить данные / (Get Extra) для компонента goToScreen. Результат в projectId.
  2. Прочитать из хранилища имя проекта — Прочитать строку / (Get String), ключ project_id_name, значение по умолчанию "". Результат в projectName.
  3. Прочитать автора — ключ project_id_author. Результат в projectAuthor.
  4. Прочитать структуру разделов — ключ project_id_structure. Результат в structure.
  5. Установить текст в заголовок шапки — Установить текст / (Set Text) для titleEdit = projectName.
  6. Установить текст в infoName — Установить текст / (Set Text) = "Название: " + projectName.
  7. Установить текст в infoAuthor — Установить текст / (Set Text) = "Автор: " + projectAuthor.
  8. Установить текст в infoStats — Установить текст / (Set Text) = "Разделов: 0 · Символов: 0".
  9. Скрыть панели — Установить видимость / (Set Visibility):
    • panelEditor → Скрытый / (Gone).
    • panelInfo → Скрытый / (Gone).
  10. Показать панель разделов — Установить видимость / (Set Visibility) для panelSections → Видимый / (Visible).
  11. Установить цвет кнопки «Разделы» в синий — Установить цвет фона / (Set Background Color) для btnTabSections = #3F51B5.
  12. Установить цвет кнопок «HTML» и «Инфо» в серый — Установить цвет фона / (Set Background Color) = #9E9E9E.
  13. Если structure == "" — заполнить listSections заглушкой «Нет разделов» через Установить список / (Set List Data).
  14. Иначе — разбить структуру по ;;; через Разделить / (Split). Результат в sections. Заполнить listSections через Установить список / (Set List Data).

Псевдокод onCreate:

// ──── ШАГ 1. Получаем ID проекта из Intent ────
// MainActivity передала этот ID при переходе.
projectId = goToScreen.getExtra("project_id")

// ──── ШАГ 2. Читаем метаданные проекта ────
projectName = getString("project_" + projectId + "_name", "")
projectAuthor = getString("project_" + projectId + "_author", "")
structure = getString("project_" + projectId + "_structure", "")

// ──── ШАГ 3. Заполняем информацию о проекте ────
// Устанавливаем имя проекта в шапке экрана.
titleEdit.setText(projectName)

infoName.setText("Название: " + projectName)
infoAuthor.setText("Автор: " + projectAuthor)
infoStats.setText("Разделов: 0 · Символов: 0")

// ──── ШАГ 4. Настраиваем видимость панелей ────
// Скрываем панели редактора и информации.
panelEditor.setVisibility(GONE)
panelInfo.setVisibility(GONE)

// Показываем панель разделов.
panelSections.setVisibility(VISIBLE)

// ──── ШАГ 5. Настраиваем цвета кнопок-вкладок ────
btnTabSections.setBackgroundColor("#3F51B5")
btnTabEditor.setBackgroundColor("#9E9E9E")
btnTabInfo.setBackgroundColor("#9E9E9E")

// ──── ШАГ 6. Заполняем список разделов ────
if (structure == "") {
    listSections.setListData(["Нет разделов"])
} else {
    sections = structure.split(";;;")
    listSections.setListData(sections)
}

Что важно понять про переключение панелей:

  • Алгоритм один и тот же для всех трёх кнопок: показать одну, скрыть две, перекрасить кнопки.

Событие 5. Нажатие btnAddSection / (onClick)

Когда срабатывает: при тапе по кнопке «+» в панели разделов.

Что делает: открывает диалог ввода имени нового раздела, добавляет раздел в структуру, обновляет список.

Порядок блоков в onClick:

  1. Показать диалог ввода — Диалог / (Dialog) → Показать / (Show).

В onDialogPositiveClick:

  1. Прочитать введённое имя — Получить текст / (Get Text) для inputSectionName. Результат в newSection.
  2. Если newSection == "" — показать Всплывающее сообщение / (Toast) «Введите имя» и завершить.
  3. Прочитать текущую структуру — Прочитать строку / (Get String) для project_id_structure.
  4. Если структура пуста — записать только newSection.
  5. Иначе — записать structure + ";;;" + newSection.
  6. Создать пустую страницу для нового раздела — Записать строку / (Put String) в ключ project_id_pages_newSection со значением <h1>newSection</h1>.
  7. Обновить список разделов.
  8. Показать Всплывающее сообщение / (Toast) «Раздел добавлен».

Псевдокод onClick btnAddSection:

myDialog.setTitle("Новый раздел")
myDialog.setPositiveButton("Добавить")
myDialog.setNegativeButton("Отмена")
myDialog.show()

// ──── В onDialogPositiveClick: ────
newSection = inputSectionName.getText()

if (newSection == "") {
    Toast("Введите имя")
    return
}

structure = getString("project_" + projectId + "_structure", "")

if (structure == "") {
    putString("project_" + projectId + "_structure", newSection)
} else {
    putString("project_" + projectId + "_structure", structure + ";;;" + newSection)
}

putString(
    "project_" + projectId + "_pages_" + newSection,
    "<h1>" + newSection + "</h1>"
)

structure = getString("project_" + projectId + "_structure", "")
sections = structure.split(";;;")
listSections.setListData(sections)

Toast("Раздел добавлен")

Событие 6. Нажатие btnRenameSection / (onClick)

Когда срабатывает: при тапе по кнопке «✎» в панели разделов.

Что делает: переименовывает выбранный раздел, сохраняет его HTML под новым ключом.

Порядок блоков в onClick:

  1. Получить выбранный элемент из списка — Получить выбранный элемент / (Get Selected Item) для listSections. Результат в oldName.
  2. Если oldName == null — показать Toast «Выберите раздел» и завершить.
  3. Показать диалог ввода нового имени.

В onDialogPositiveClick:

  1. Получить новое имя из поля — Получить текст / (Get Text). Результат в newName.
  2. Прочитать структуру разделов.
  3. Заменить oldName на newName в структуре — Заменить / (Replace).
  4. Записать обновлённую структуру обратно.
  5. Прочитать HTML старого раздела.
  6. Записать HTML под новым ключом.
  7. Удалить старый ключ.
  8. Обновить список разделов.

Псевдокод onClick btnRenameSection:

oldName = listSections.getSelectedItem()

if (oldName == null) {
    Toast("Выберите раздел")
    return
}

myDialog.setTitle("Переименовать раздел")
myDialog.setPositiveButton("Переименовать")
myDialog.setNegativeButton("Отмена")
myDialog.show()

// ──── В onDialogPositiveClick: ────
newName = inputSectionName.getText()

if (newName == "") {
    Toast("Введите имя")
    return
}

structure = getString("project_" + projectId + "_structure", "")
newStructure = structure.replace(oldName, newName)
putString("project_" + projectId + "_structure", newStructure)

html = getString("project_" + projectId + "_pages_" + oldName, "")
putString("project_" + projectId + "_pages_" + newName, html)
remove("project_" + projectId + "_pages_" + oldName)

structure = getString("project_" + projectId + "_structure", "")
sections = structure.split(";;;")
listSections.setListData(sections)

Событие 7. Нажатие btnDeleteSection / (onClick)

Когда срабатывает: при тапе по кнопке «🗑» в панели разделов.

Что делает: удаляет выбранный раздел и его страницу после подтверждения.

Порядок блоков в onClick:

  1. Получить выбранный раздел.
  2. Если null — Toast «Выберите раздел» и завершить.
  3. Показать диалог подтверждения.

В onDialogPositiveClick:

  1. Прочитать структуру.
  2. Заменить name на пустую строку — Заменить / (Replace).
  3. Схлопнуть двойные ;;;;;; → ;;;.
  4. Убрать лишние ; в начале и конце — Обрезать / (Trim).
  5. Записать структуру обратно.
  6. Удалить страницу раздела — Удалить / (Remove).
  7. Обновить список.
  8. Toast «Раздел удалён».

Псевдокод onClick btnDeleteSection:

name = listSections.getSelectedItem()

if (name == null) {
    Toast("Выберите раздел")
    return
}

myDialog.setTitle("Удаление раздела")
myDialog.setMessage("Удалить раздел " + name + "?")
myDialog.setPositiveButton("Удалить")
myDialog.setNegativeButton("Отмена")
myDialog.show()

// ──── В onDialogPositiveClick: ────
structure = getString("project_" + projectId + "_structure", "")
s1 = structure.replace(name, "")
s2 = s1.replace(";;;;;;", ";;;")
s3 = s2.trim(";")
putString("project_" + projectId + "_structure", s3)

remove("project_" + projectId + "_pages_" + name)

structure = getString("project_" + projectId + "_structure", "")
if (structure == "") {
    listSections.setListData(["Нет разделов"])
} else {
    sections = structure.split(";;;")
    listSections.setListData(sections)
}

Toast("Раздел удалён")

Событие 11. Нажатие btnFind / (onClick)

Когда срабатывает: при тапе по кнопке «Найти» внизу экрана.

Что делает: открывает диалог с полем ввода, ищет текст в HTML и выделяет его в редакторе.

Порядок блоков в onClick:

  1. Показать диалог ввода запроса.

В onDialogPositiveClick:

  1. Получить текст запроса — Получить текст / (Get Text). Результат в query.
  2. Прочитать HTML из editorText.
  3. Найти позицию запроса — Найти позицию / (IndexOf) для html и query. Результат в pos.
  4. Если pos < 0 — Toast «Не найдено».
  5. Иначе — выделить найденный текст — Установить выделение / (Set Selection) для editorText от pos до pos + query.length.
  6. Показать панель HTML.

Псевдокод onClick btnFind:

myDialog.setTitle("Найти в HTML")
myDialog.setPositiveButton("Найти")
myDialog.setNegativeButton("Отмена")
myDialog.show()

// ──── В onDialogPositiveClick: ────
query = inputSearch.getText()
html = editorText.getText()

pos = html.indexOf(query)

if (pos < 0) {
    Toast("Не найдено")
} else {
    editorText.setSelection(pos, pos + query.length())
    panelEditor.setVisibility(VISIBLE)
    panelSections.setVisibility(GONE)
    panelInfo.setVisibility(GONE)
}

Что важно понять про логику EditorActivity

Первое — три панели. Все три события переключения панелей похожи. Разница только в том, какая панель становится видимой. Это удобно: одна и та же логика повторяется три раза с минимальными изменениями.

Второе — состояние текущего раздела. Информация о том, какой раздел сейчас открыт, хранится в last_page_file. Это значение читается при сохранении, предпросмотре и поиске.

Третье — структура данных. Структура разделов хранится как строка с разделителем ;;;. Разбивается через Разделить / (Split) и собирается через конкатенацию. HTML каждой страницы хранится под отдельным ключом: project_id_pages_имя_раздела.

Четвёртое — при переименовании переносим HTML. Так как имя раздела — это ключ, при переименовании содержимое нужно скопировать под новый ключ и удалить старый. Иначе HTML потеряется.

Пятое — при сохранении обновляем статистику. infoStats показывает количество символов. Обновляем его после каждого сохранения.

Совет. После того как опишешь логику EditorActivity, проверь сценарии: создай проект, добавь раздел, отредактируй HTML, сохрани, посмотри предпросмотр. Переименуй раздел, проверь, что HTML сохранился. Удали раздел.
Частая ошибка. Забыть сохранить HTML при нажатии «Предпросмотр». Если пользователь редактировал, но не нажал «Сохранить», и сразу нажал «Предпросмотр» — HTML потеряется. В логике мы сохраняем его перед переходом.
