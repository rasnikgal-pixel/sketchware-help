RequestNetwork — HTTP-запросы

RequestNetwork — компонент для сетевых запросов. Отправляет HTTP-запросы к серверам и API, получает ответы в форматах JSON, XML, HTML, plain text. Основной инструмент для работы с интернетом.

Иконка в диалоге добавления — значок Wi-Fi или стрелка в облако.

Как работает

  • Отправляет HTTP-запрос по указанному URL.
  • Поддерживает методы: GET, POST, PUT, DELETE.
  • Может передавать параметры, заголовки, тело запроса.
  • Получает ответ от сервера: текст, JSON, HTML.
  • При успехе срабатывает onResponse, при ошибке — onErrorResponse.
  • Запрос выполняется асинхронно — приложение не зависает.

Когда использовать

  • Погода — запрос к API погоды.
  • Курсы валют — данные с биржи.
  • Новости — лента с сервера.
  • Авторизация — отправка логина и пароля.
  • Загрузка файлов — на сервер.
  • API соцсетей — посты, комментарии, лайки.
  • Firebase REST — работа с базой через HTTP.
  • Практически любая работа с внешними данными.

Основные настройки при добавлении

  • Имя компонента — идентификатор для вызова. Например, weatherRequest.

Основные блоки в логике

  • setUrl — задать URL запроса.
  • setRequestMethod — метод: GET, POST, PUT, DELETE.
  • setParams — параметры запроса (словарь «ключ — значение»).
  • setHeaders — заголовки (например, Content-Type: application/json).
  • startRequestNetwork — отправить запрос.

События RequestNetwork

  • onResponse — успешный ответ. Внутри — переменная response, содержащая текст ответа.
  • onErrorResponse — ошибка: нет сети, таймаут, ошибка сервера.

Как использовать

  • Подключи компонент RequestNetwork на вкладке «Компонент».
  • Задай имя — например, apiRequest.
  • Добавь разрешение INTERNET в Менеджере разрешений.
  • В логике:
    • задай URL через setUrl;
    • задай метод через setRequestMethod;
    • если есть параметры — через setParams;
    • вызови startRequestNetwork.
  • В категории «Компонент» добавь события:
    • onResponse — обработка данных;
    • onErrorResponse — обработка ошибки.
  • В onResponse парсишь ответ и используешь данные.

Пример: запрос погоды

  • URL: https://api.openweathermap.org/data/2.5/weather?q=Moscow&appid=КЛЮЧ.
  • Метод: GET.
  • В onResponse — полученный JSON парсишь и выводишь температуру в TextView.
  • В onErrorResponse — показываешь «Не удалось загрузить погоду».

Форматы ответа

  • JSON — самый частый формат современных API. Парсинг через блоки JSON.
  • XML — старый формат, иногда ещё используется.
  • HTML — веб-страницы.
  • Plain text — просто текст.

⚠️ Важно: разрешение INTERNET обязательно. Без него запрос не уйдёт, а ошибка не всегда видна.

⚠️ Важно: запрос асинхронный — нельзя сразу после startRequestNetwork использовать ответ. Только в onResponse.

⚠️ Важно: не отправляй запросы в главном потоке — Sketchware делает это автоматически. Но тяжёлая логика в onResponse может «подвесить» интерфейс. Разбивай на части.

⚠️ Важно: всегда обрабатывай onErrorResponse. Без сети или при ошибке сервера — приложение должно показать понятное сообщение, а не «молчать».

⚠️ Важно: не храни API-ключи в коде приложения. Их можно извлечь из APK. Для серьёзных проектов — используй прокси-сервер.

💡 Совет: для отладки запросов используй сервисы вроде Postman или Insomnia. Сначала убедись, что запрос работает в браузере, потом переноси в приложение.

💡 Совет: для проверки ответа добавь временный Toast в onResponse — покажи первые 200 символов ответа. Так увидишь, что пришло с сервера.

💡 Совет: для JSON используй специальные блоки парсинга. Например, getString(response, "key") или getJSONArray(response, "list").

💡 Совет: для прогресса загрузки показывай ProgressBar перед запросом и скрывай его в onResponse и onErrorResponse.

💡 Совет: для POST-запросов не забудь задать Content-Type в заголовках: application/json или application/x-www-form-urlencoded.

💡 Совет: не отправляй запросы слишком часто. Например, при вводе каждого символа в поле поиска. Используй задержку (Timer) или отправляй только при нажатии кнопки.

❌ Частая ошибка: забыть про разрешение INTERNET. Запрос не уходит, ошибка не видна.

❌ Частая ошибка: ожидать ответ сразу после startRequestNetwork. Ответ приходит только в onResponse.

❌ Частая ошибка: не обрабатывать onErrorResponse. При ошибке — тишина, пользователь не понимает, что происходит.

❌ Частая ошибка: хранить API-ключи в коде. Их можно извлечь из APK и использовать в своих целях.

❌ Частая ошибка: отправлять запросы в цикле без задержки. Это спамит сервер и может привести к блокировке IP.

❌ Частая ошибка: не проверять ответ на ошибки. Сервер может вернуть код 404 или 500 — приложение должно уметь это распознать.
